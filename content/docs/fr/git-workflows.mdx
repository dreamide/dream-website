Ouvrir **Git** dans la barre d'outils de droite pour les onglets **Modifications**, **Historique** et **Pull request**. Le menu **Actions Git** situé sous le chat propose les prochaines étapes pour la branche actuelle.

## Avant de commencer

Pour les commits, votre référentiel a besoin d'une identité Git author configurée. Pour les pushes, il faut un remote et des identifiants permettant d'y accéder. La création de pull request utilise GitHub CLI, qui doit être installé et authentifié pour le référentiel de destination.

Vous pouvez taper vous-mêmes les messages de commit et le texte de demande de modification. Pour les générer, activez un modèle fourni et choisissez **Paramètres → Général → Modèles → Modèle de génération de texte**.

## Revoir les modifications

1. Ouvrir **Git → Modifications** pour inspecter les fichiers modifiés, ajoutés et supprimés.
2. Développer un fichier pour examiner sa différence.
3. Choisissez **Diff unifié** ou **Diff côte à côte** dans l'en-tête, et activez le wrap de mot dans **Actions Modifications** si nécessaire.
4. Utilisez **Actions Modifications → Actualiser** si les modifications effectuées en dehors de Dream n'ont pas encore été reflétées.

Pour des différences très grandes, Dream peut afficher **Diff trop grand pour être rendu**. Utilisez **Rendre quand même** uniquement lorsque vous souhaitez charger cette vue plus large, ou inspecter le fichier dans votre éditeur ou terminal.

Utilisez l'action **Annuler les modifications du fichier** pour abandonner des modifications de travail inutiles. L'action **Annuler toutes les modifications** s'applique plus largement ; vérifiez son portée avant de confirmer. Annuler du code est indépendant de l'archivage du chat qui l'a produit. Pour annuler uniquement ce que a modifié une réponse particulière, utilisez le [point d'arrêt](/docs/fr/checkpoints) de cette réponse.

Pour demander à un agent de commenter des lignes spécifiques, glissez sur les numéros de ligne dans une diff ou cliquez sur le contrôle **+** d'une ligne, puis saisissez un commentaire. Dream l'envoie avec le chemin du fichier et les lignes sélectionnées. Voir [Envoyer des retours à une conversation](/docs/fr/feedback).

1. Ouvrir **Git → Modifications**, ou choisir **Valider** dans le menu des **Actions Git** du pied de page.
2. Revoir les différences de fichier ci-dessous le commit composer.
3. Vérifiez **Inclure les fichiers non préparés**. Elle est activée par défaut et inclut les modifications non indexées dans le commit.
4. Vérifier **Générer automatiquement un message**, qui est activé par défaut. Pour écrire votre propre message, désactivez-le et saisissez le texte ; désactiver cela efface le message généré.
5. Choisissez **Valider**, ou **Valider et pousser** si vous êtes prêt à publier le commit sur le distant.

Pour commiter uniquement un sous-ensemble sélectionné, stagez ces fichiers en utilisant Git dans un terminal ou un éditeur externe et désactivez **Inclure les fichiers non préparés**. Le panneau des modifications ne fournit pas de contrôles individuels de staging.

Dream refuse les commits lorsque des modifications stagées se trouvent en dehors du dossier projet actif. Commitez ces modifications séparément avant de continuer avec cette action.

<Warning>
  Vérifiez les fichiers inclus ainsi que le message. Avec Include unstaged activé, un commit peut contenir du travail provenant de plusieurs conversations partageant ce checkout.
</Warning>

Utilisez **Publier la branche** pour une branche sans branche de suivi, ou **Pousser** pour envoyer les commits en attente. Ces actions en bas de la fenêtre effectuent l’envoi immédiatement. Vérifiez d’abord la branche, le dépôt distant et les commits dans **Historique** ; les nombres de commits en avance et en retard apparaissent lorsqu’une branche de suivi existe.

Si l'envoi échoue, vérifiez l'erreur et confirmez votre accès au serveur distant. Un commit local réussi reste enregistré même si une mise à jour suivante échoue ; vérifiez l'état du branche avant de répéter une action combinée.

## Créer un pull request

1. Travailler sur une branche de fonctionnalité dont le nom diffère de la branche de base de la demande de modification.
2. Choisissez **Créer un PR** dans le pied de page, ou **Actions Git → Créer une demande d'extraction**.
3. Examine les branches source et de base ainsi que les modifications proposées.
4. Saisissez un titre et une description, ou utilisez **Générer automatiquement les détails du PR** et vérifiez le texte généré.
5. Sous **Étapes suivantes**, sélectionnez l'action qui correspond à l'état du branche.
6. Activez **Brouillon** si la demande de modification n'est pas prête pour la révision, puis soumettez-la.

| Étape suivante | Qu'est-ce qui se passe |
| --- | --- |
| Créer une demande de fusion | Crée une demande de pull pour du travail déjà poussé |
| Pousser et créer une demande de modification | Pousse des commits avant de créer la demande de modification |
| Commit, pousser et créer une demande de modification | Commite les modifications en cours, effectue les pushes et crée la demande de modification |

L'interface commence avec **Brouillon** désactivé. Activez-le pour créer une demande de fusion en brouillon. La création d'une demande de fusion nécessite une branche au lieu d'une pointe détachée, et source et base ne peuvent pas être la même branche.

Si une action combinée échoue, certaines étapes peuvent déjà avoir été exécutées. Vérifiez la commit, la branche distante ou la demande de modification avant de réessayer.

## Revoir et fusionner une demande de pull

Ouvrir **Git → Pull request** pour consulter la demande de fusion de la branche actuelle. Utilisez **Résumé** pour voir sa description, ses vérifications et son débat, ou **Code** pour inspecter les différences et ajouter des commentaires en ligne. Vous pouvez modifier le titre et la description lorsque cela est autorisé et utiliser **Fusionner** pour choisir une méthode de fusion. Consultez [Examiner les pull requests](/docs/fr/pull-requests) pour le workflow complet.

## Passer ou créer des branches

Ouvrir le commutateur de branche sous le chat, rechercher les branches locales et sélectionner une d'entre elles pour la sortir. Utiliser **Créer et basculer vers une nouvelle branche…** pour nommer et créer une branche. Actualiser la liste si une branche créée en dehors de Dream est manquante.

Changer de branche modifie les fichiers utilisés par chaque conversation dans ce projet. Vérifiez les travaux non terminés avant de les changer. Pour des tâches parallèles avec des checkouts indépendants, utilisez [Worktrees Git](/docs/fr/worktrees). Lorsqu'un arbre de travail est terminé, utilisez son pied de page pour le fusionner dans la branche principale, créer une demande de fusion, ou supprimer le checkout. Voir [Terminer un arbre de travail](/docs/fr/worktrees#compléter-un-arbre-de-travail).

## Parcourir l'historique des commits

<Frame caption="Parcourir l'historique des commits">
  <img
    src="/images/docs/git-history-panel.png"

    width={933}

Ouvrir **Git → Historique**, ou **Actions Git → Voir l'historique**, pour suivre les commits et les fusions dans le graphique coloré. Utilisez **Rechercher des commits** pour filtrer les commits chargés par message, auteur, préfixe de hachage ou référence. **Charger plus** inclut des commits plus anciens ; effacez la recherche pour afficher à nouveau le graphique.

Cliquez sur un commit ou le focalisez avec le clavier pour utiliser **Copier le hash du commit**.
