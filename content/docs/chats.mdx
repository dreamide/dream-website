---
title: Working with chats
description: Start conversations, find previous work, rename chats, and manage your chat history.
---

A chat holds one conversation with a coding agent. A chat usually belongs to a project, and has its
own model, permissions, and conversation history. Use separate chats for tasks you want to return to
independently, such as fixing a bug and reviewing a feature.

To ask something without opening a folder, start a
[chat without a project](/docs/standalone-chats).

## Start a conversation

1. Select the project tab you want to work in.
2. Click **New chat** in the left toolbar.
3. Check the model and permissions below the message box.
4. Describe the task and submit your message.

New chats use your [default model settings](/docs/models). An empty draft may be reused when you
click **New chat** again before sending a message. Once you send a message, the conversation appears
in the project's history.

For a useful first message, give the agent an outcome and a way to check it. For example:

> Find why the settings form loses its values after a refresh. Fix the cause and explain how you
> verified the fix.

Use [file references and attachments](/docs/providing-context) to point to relevant code or an image.

## Return to a conversation

1. Click **Chat history** in the left toolbar.
2. Browse the current project's chats, with recently updated conversations first.
3. Enter part of a chat's title in **Search history** to narrow the list.
4. Select the conversation to open it.

History search filters this project's titles. To search titles and message text across projects,
click **Search chats** in the top bar (default **Command+Shift+F** on macOS or **Ctrl+Shift+F** on
Windows/Linux). Results include local projects, connected remote hosts, and
[chats without a project](/docs/standalone-chats). Selecting an archived result restores it;
selecting a closed project's chat reopens that project.

If a host cannot be searched, reconnect it and try again. Narrow the query when results are truncated.
You can also manage older conversations in [Archived chats](/docs/archived-chats).

When [multi-chat](/docs/multiple-chats) is enabled, selecting a conversation can bring it into the
side-by-side layout. With multi-chat disabled, you view one conversation at a time.

## Rename a chat

Dream can generate a title after a conversation starts. To give it a more specific name, open the
chat's **…** menu and choose **Edit**, or double-click the title. In **Edit chat**, enter the name
and click **Save**. Use **Cancel** to keep the existing name.

Names such as “Fix settings persistence” and “Review settings tests” are easier to distinguish than
several chats named after the same project.

## Follow work in progress

Enable **Desktop notifications** under **Settings → General → Chat messages** to get an alert when a chat
finishes, fails, or needs input while Dream is in the background. Click a notification to open its
chat. **Notification sound** is a separate option and can play even while Dream is focused.

Notifications also cover turns that keep running on the host while this window is not following
them. A turn that you stop yourself does not send one.

A loading spinner identifies chats that are streaming a response. When you send a message,
Dream scrolls it into view.

While an agent responds, the chat shows its progress and tool activity. Open tool details to inspect
commands, file reads, or changes. When the agent supplies a task list, the task control beside the
message box shows its progress.

Chat history and project tabs show a status for each chat: a spinner while it is responding, an
amber dot when the agent is waiting for you, and a green dot when it has finished and you have not
opened it yet. Select the project and open the conversation to read its latest message. Use the
stop control in the composer to interrupt a response. Stopping a response does not undo file changes
already made.

A turn runs on the project's host rather than in the window. If the window loses its connection to
the host, the turn keeps running and Dream reconnects to it automatically. Quitting Dream stops the
host that the app started, along with its turns; to keep agents working after you close the app,
[run the host yourself](/docs/dream-host).

After a reply finishes, use **View file changes from this reply** in its footer to see the files it
changed and [restore any of them](/docs/checkpoints).

## Queue messages

You do not have to wait for a response to finish before sending the next instruction. Type a
message while the agent is working and send it. Dream adds it to the chat's queue and runs it when
the current turn ends. While a turn is running, the composer's button stops the turn when the
message box is empty and sends the message once you have typed something.

The **Queue** list appears above the message box when a message is waiting or a run needs your
attention. Each row shows the message, its model, and a status.

| Status | Meaning |
| --- | --- |
| Queued | Waiting for the turns ahead of it |
| Running | The turn the agent is working on now |
| Waiting | The running turn is waiting for your answer or approval |
| Interrupted | Stopped before it finished, for example by the stop control or a host restart |
| Failed | Ended with an error |

Use **Cancel** on a queued message to take it out of the queue. A failed or interrupted run offers
**Retry** and **Remove**. Read the reply that an interrupted run left behind before you retry it,
because part of its work may already be done.

**Pause queue** holds the queued messages and lets the current turn finish. **Resume queue** starts
them again. The stop control is different: it ends the running turn, along with any tasks it
[delegated](/docs/delegation), and pauses the queue.

A failed or interrupted run also pauses the queue, and its header reads **Queue paused**. Sending a
new message resumes the queue and dismisses those runs.

Queues are saved on the project's host and survive restarting Dream. After the host restarts, a
turn that was running is marked as interrupted and the queue stays paused until you resume it. If a
queued message cannot be sent, its text returns to the message box.

## Close, archive, or delete?

| Action | Result | How to return |
| --- | --- | --- |
| Close a chat column | Removes it from the multi-chat layout | Open it from Chat history |
| Archive a chat | Removes it from active chat history | Restore it in Settings → Archived chats |
| Delete an archived chat | Permanently removes the chat and its messages from Dream | It cannot be restored through Dream |

Closing a column is useful when you need more space. Archiving is useful when a task is finished.
Neither action reverts the agent's changes to project files.

To try a different approach while keeping the conversation so far, [branch from a message](/docs/branching-chats).
To prepare a task for later, [save a prompt in Stash](/docs/stash). For instructions you want to
reuse across projects, create a [reusable prompt](/docs/saved-prompts) and run it from the composer's
**+ → Run prompt** menu. Type **$** to invoke an [agent skill](/docs/skills).
