title: Git workflows
description: Review changes, work with branches, and use Git worktrees in Dream.
---

Dream's Git tools are available when the project folder is a Git repository. Use **Changes** in the
right toolbar to inspect files and **Open Git actions** to commit, push, or create a pull request.

## Before you start

For commits, your repository needs a Git author identity configured. For pushing, it needs a remote
and credentials that can access it. Pull-request creation uses GitHub CLI, which must be installed
and authenticated for the destination repository.

You can type commit messages and PR text yourself. To generate them, enable a provider model and
choose **Settings → General → Models → Default model for commits and PRs**.

## Review changes

1. Open **Changes** to inspect modified, added, and deleted files.
2. Expand a file to review its diff.
3. Choose **Unified diff** or **Split diff** in the panel's actions, and enable word wrap if useful.
4. Use **Refresh changes** if work done outside Dream is not yet reflected.

For very large diffs, Dream may show **Diff too large to render**. Use **Render anyway** only when
you want to load that larger view, or inspect the file in your editor or terminal.

Use a file's **Revert file changes** action to discard unwanted working changes. **Revert all
changes** applies more broadly; review its scope before confirming. Reverting code is separate from
archiving the chat that produced it. To undo only what a particular reply changed, use that
reply's [checkpoint](/docs/checkpoints).

To ask an agent about specific lines, drag across the line numbers in a diff or click a line's
**+** control, then type a comment. Dream sends it with the file path and selected lines. See
[Sending feedback to a chat](/docs/feedback).

## Commit your work

1. Open **Git actions → Commit**.
2. Review the changes included in the dialog.
3. Check **Include unstaged**. It is enabled by default and includes unstaged changes in the commit.
4. Enter a commit message or use **Auto generate message**, then edit the result as needed.
5. Choose **Commit**, or **Commit & push** if you are ready to publish the commit to the remote.

To commit only a selected subset, stage those files using Git in a terminal or external editor and
turn **Include unstaged** off. The Changes panel does not provide individual staging controls.

Dream rejects commits when there are staged changes outside the active project folder. Commit
those separately before continuing with this action.

<Warning>
  Review the included files as well as the message. With Include unstaged enabled, a commit can
  contain work from several chats sharing this checkout.
</Warning>

## Push a branch

Open **Git actions → Push**, review the outgoing commits and destination, and choose **Push**.
The destination depends on the branch's upstream and repository remote configuration.

If pushing fails, inspect the error and confirm your remote access. A successful local commit
remains committed even if a following push fails; check the branch state before repeating a
combined action.

## Create a pull request

1. Work on a feature branch whose name differs from the PR's base branch.
2. Open **Git actions → Create PR**.
3. Review the source and base branches and the proposed changes.
4. Enter a title and description, or use **Auto generate PR details** and review the generated text.
5. Under **Next steps**, select the action that matches the branch's state.
6. Review **Draft** and **Open PR page**, then submit.

| Next step | What happens |
| --- | --- |
| Create PR | Creates a PR for work already pushed |
| Push & create PR | Pushes commits before creating the PR |
| Commit, push & create PR | Commits working changes, pushes, and creates the PR |

The dialog starts with **Draft** selected. Clear it when the PR is ready for review. PR creation
requires a branch rather than a detached HEAD, and source and base cannot be the same branch.

If a combined action fails, earlier steps may already have completed. Check for the commit, remote
branch, or PR before retrying.

## Switch or create branches

Open the branch switcher beneath the chat, search local branches, and select one to check it out.
Use **Create and checkout new branch…** to name and create a branch. Refresh the list if a branch
created outside Dream is missing.

Changing branches changes the files used by every chat in that project. Review unfinished work
before switching. For parallel tasks with independent checkouts, use [Git worktrees](/docs/worktrees).
When a worktree is finished, its **Complete worktree** dialog can merge the branch into its base or
open a pull request and then remove the checkout.
