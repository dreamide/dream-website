Open **Git** in the right toolbar for the **Changes**, **History**, and **Pull request** tabs.
The **Git actions** menu beneath the chat offers the next steps for the current branch.

The **Git actions** button sits at the right of the footer and is highlighted when there are changes
to commit or commits to push. **Git** appears only for projects inside a Git repository.

## Before you start

For commits, your repository needs a Git author identity configured. For pushing, it needs a remote
and credentials that can access it. Pull-request creation uses GitHub CLI, which must be installed
and authenticated for the destination repository.

You can type commit messages and PR text yourself. To generate them, enable a provider model and
choose **Settings → General → Models → Text generation model**.

## Review changes

1. Open **Git → Changes** to inspect modified, added, and deleted files.
2. Expand a file to review its diff.
3. Choose **Unified diff** or **Split diff** in the header. **Word wrap** is on by default and has its own toggle there, beside **Expand all** and **Collapse all**.
4. Click a file's path in its diff header to open that file in **Files**.

The list updates as files change, after terminal commands finish, and when you return to the Dream
window.

For very large diffs, Dream may show **Diff too large to render**. Use **Render anyway** only when
you want to load that larger view, or inspect the file in your editor or terminal.

Use a file's **Revert file changes** action to discard unwanted working changes. **Revert all
changes** applies more broadly; review its scope before confirming. Reverting code is separate from
archiving the chat that produced it. To undo only what a particular reply changed, use that
reply's [checkpoint](/docs/checkpoints).

To ask an agent about specific lines, drag across the line numbers in a diff or click a line's
**+** control, then type a comment. Dream sends it with the file path and selected lines. See
[Sending feedback to a chat](/docs/feedback).

## Commit your work

1. Open **Git → Changes**, or choose **Commit** from the footer's **Git actions** menu.
2. Review the file diffs below the commit composer.
3. Check **Include unstaged**. It is enabled by default and includes unstaged changes in the commit.
4. Review **Auto generate message**, which is on by default. To write your own message, turn it off and enter the text; turning it off clears the generated message.
5. Choose **Commit**, or **Commit & push** if you are ready to publish the commit to the remote.

With **Auto generate message** on, Dream drafts the message in the background when the project's
last running agent turn ends, so it is usually ready when you open the panel. Press
**Command+Enter** on macOS or **Ctrl+Enter** on Windows/Linux to commit, and add **Shift** to commit
and push.

To commit only a selected subset, stage those files using Git in a terminal or external editor and
turn **Include unstaged** off. The Changes panel does not provide individual staging controls.

Dream rejects commits when there are staged changes outside the active project folder. Commit
those separately before continuing with this action.

<Warning>
  Review the included files as well as the message. With Include unstaged enabled, a commit can
  contain work from several chats sharing this checkout.
</Warning>

In **Git actions**, use **Publish branch** for a branch without an upstream, or **Push** for outgoing
commits. Either one opens a **Push changes** preview that shows the branch, its destination, and the
commits that will be sent. Review them, then click **Push**. When an upstream exists, the **Push**
and **Pull** menu items show how many commits the branch is ahead and behind.

If pushing fails, inspect the error and confirm your remote access. When the remote has commits you
do not have yet, Dream tells you to pull and then push again. A successful local commit remains
committed even if a following push fails; check the branch state before repeating a combined action.

## Fetch and pull

**Git actions → Fetch** downloads new commits from the remote without changing your files. **Pull**
also brings the upstream branch's commits into your branch.

After a pull, a notification reports how many commits arrived. Choose **View changes** in it to open
**Pulled changes**, which lists those commits and the files they changed.

If your branch and its upstream have both gained commits, Dream merges the upstream commits into
your branch; it does not rebase. When that merge would conflict, Dream aborts it, leaves your files
as they were, and lists the conflicting files. Resolve the difference with Git in a terminal, then
pull again.

**Open repository** in the same menu opens the remote repository in your browser.

## Create a pull request

1. Work on a feature branch whose name differs from the PR's base branch.
2. Choose **Git actions → Create pull request**.
3. Review the source and base branches and the proposed changes.
4. Enter a title and description, or use **Auto generate PR details** and review the generated text.
5. Under **Next steps**, select the action that matches the branch's state.
6. Turn on **Draft** if the PR is not ready for review, then submit.

| Next step | What happens |
| --- | --- |
| Create PR | Creates a PR for work already pushed |
| Push & create PR | Pushes commits before creating the PR |
| Commit, push & create PR | Commits working changes, pushes, and creates the PR |

The dialog starts with **Draft** off. Enable it to create a draft PR. PR creation
requires a branch rather than a detached HEAD, and source and base cannot be the same branch.

If a combined action fails, earlier steps may already have completed. Check for the commit, remote
branch, or PR before retrying.

## Review and merge a pull request

Open **Git → Pull request** to view the current branch's PR. Use **Summary** for
its description, checks, and discussion, or **Code** to inspect diffs and post inline comments.
You can edit the title and description when permitted and use **Merge** to choose a merge method.
See [Reviewing pull requests](/docs/pull-requests) for the full workflow.

## Switch or create branches

Open the branch switcher beneath the chat, search local branches, and select one to check it out.
Use **Create and checkout new branch…** to name and create a branch. The list reloads each time you
open it, so it includes branches created outside Dream.

Changing branches changes the files used by every chat in that project. Review unfinished work
before switching. For parallel tasks with independent checkouts, use [Git worktrees](/docs/worktrees).
When a worktree is finished, use its footer to merge into the base branch, create a pull request,
or remove the checkout. See [Complete a worktree](/docs/worktrees#complete-a-worktree).

### Delete a local branch

1. Open the branch switcher and hover over the branch, or move to it with the keyboard.
2. Click **Delete branch**, the trash icon on its row.
3. Read the summary. Dream reports whether the branch's commits are in the base branch, the state of
   its pull request, and whether any commits exist only on this branch.
4. Click **Delete branch**. When commits would be lost, the button reads **Delete anyway**.

Deleting removes the local branch only; its remote branch is not changed. You cannot delete the
current branch, the base branch, or a branch that is open in the main checkout.

If the branch is checked out in a [worktree](/docs/worktrees), the dialog offers
**Remove worktree and branch** instead. That also deletes the worktree's folder and its chats.

## Browse commit history

Open **Git → History**, or **Git actions → View history**, to follow commits and merges in the
colored graph. Use **Search commits** to filter loaded commits by message, author, hash prefix,
or ref. **Load more** includes older commits; clear the search to show the graph again.

Hover over a commit or focus it with the keyboard to use **Copy commit hash**.
