Abrir **Git** en la barra de herramientas derecha para las pestañas **Cambios**, **Historial** y **Solicitud de extracción**. El menú de **Acciones de Git** bajo el chat ofrece los siguientes pasos para la rama actual.

## Antes de comenzar

Para hacer commits, el repositorio necesita una identidad de autor de Git configurada. Para hacer push, necesita un remoto y credenciales con acceso a él. La creación de pull requests utiliza GitHub CLI, que debe estar instalado y autenticado para el repositorio de destino.

Puedes escribir tus mensajes de commit y el texto de la solicitud de cambios tú mismo. Para generarlos, activa un modelo de proveedor y elige **Configuración → General → Modelos → Modelo de generación de texto**.

## Revisar cambios

1. Abrir **Git → Cambios** para inspeccionar los archivos modificados, añadidos y eliminados.
2. Expandir un archivo para revisar su diff.
3. Elige **Diff unificado** o **Diff dividido** en el encabezado, y habilita el desplazamiento de palabras en **Acciones de Cambios** si es útil.
4. Use **Acciones de Cambios → Actualizar** si los cambios realizados fuera de Dream aún no se reflejan.

Para diffs muy grandes, Dream puede mostrar **Diferencia demasiado grande para renderizar**. Utiliza **Renderizar de todos modos** solo cuando quieras cargar esa vista más grande, o inspeccionar el archivo en tu editor o terminal.

Use la acción **Revertir cambios de archivo** para descartar cambios de trabajo no deseados. **Revertir todos los cambios** se aplica de forma más amplia; revísalo antes de confirmarlo. Revertir código es distinto de archivar el chat que lo generó. Para anular solo lo que cambió una respuesta específica, utiliza el [punto de control](/docs/es/checkpoints) de esa respuesta.

Para pedir a un agente sobre líneas específicas, arrastre sobre los números de línea en un diff o haga clic en el control **+** de una línea, luego escriba un comentario. Dream lo envía junto con la ruta del archivo y las líneas seleccionadas. Vea [Enviar retroalimentación a un chat](/docs/es/feedback).

1. Abre **Git → Cambios**, o elige **Confirmar** en el menú **Acciones de Git** situado debajo del chat.
2. Revisa las diferencias de los archivos debajo del campo del mensaje de commit.
3. Revise **Incluir no preparado**. Está habilitado por defecto y incluye los cambios no etiquetados en el commit.
4. Revisar **Generar mensaje automáticamente**, que está activado por defecto. Para escribir su propio mensaje, desactívalo y escribe el texto; desactivarlo borra el mensaje generado.
5. Elige **Confirmar**, o **Confirmar y enviar** si estás listo para publicar el commit en el remoto.

Para commiter solo un subconjunto seleccionado, stage esos archivos usando Git en un terminal o en un editor externo y desactiva **Incluir no preparado**. El panel de cambios no proporciona controles individuales de estaging.

Dream rechaza los commits cuando hay cambios estagados fuera del directorio activo del proyecto. Comitea esos cambios por separado antes de continuar con esta acción.

<Warning>
  Revisar los archivos incluidos así como el mensaje. Con Include unstaged habilitado, un commit puede contener trabajo de varios chats que comparten este checkout.
</Warning>

## Empujar una rama

    loading="lazy"

Usa **Publicar rama** para una rama sin upstream, o **Enviar** para enviar commits pendientes. Estas acciones del pie de página envían los cambios inmediatamente. Comprueba primero la rama, el remoto y los commits en **Historial**; el pie muestra cuántos commits hay por delante y por detrás cuando existe un upstream.

Si el empuje falla, revisa el error y confirma tu acceso remoto. Un commit local exitoso permanece commitado incluso si un empuje posterior falla; verifica el estado de la rama antes de repetir una acción combinada.

## Crea un pull request

1. Trabaja en una rama de características cuyo nombre difiera de la rama base del pedido.
2. Elige **Crear PR** en el pie de página, o **Acciones de Git → Crear solicitud de extracción**.
3. Revisa los branches de origen y base y los cambios propuestos.
4. Ingrese un título y una descripción, o use **Generar detalles de PR automáticamente** y revise el texto generado.
5. Bajo **Próximos pasos**, seleccione la acción que corresponda al estado de la rama.
6. Activa **Borrador** si el pedido de cambios no está listo para la revisión, luego envíalo.

| Paso siguiente | ¿Qué sucede? |
| --- | --- |
| Crear PR | Crea una solicitud de incorporación para trabajo ya empujado |
| Empujar y crear solicitud de cambios | Empuja los commits antes de crear el pedido de cambios |
| Comitear, empujar y crear una solicitud de cambios | Comitea los cambios en curso, los envía y crea la solicitud de incorporación. |

El diálogo comienza con **Borrador** desactivado. Actívalo para crear una PR de borrador. La creación de una PR requiere un ramo en lugar de un HEAD desacoplado, y origen y base no pueden ser el mismo ramo.

Si una acción combinada falla, pasos anteriores pueden haberse completado ya. Verifica el commit, el ramo remoto o la solicitud de cambios antes de reintentarlo.

## Revisar y fusionar una solicitud de incorporación

Abrir **Git → Solicitud de extracción** para ver la solicitud de incorporación de la rama actual. Utilice **Resumen** para su descripción, comprobaciones y discusión, o **Código** para inspeccionar los diffs y dejar comentarios en línea. Puede editar el título y la descripción cuando sea permitido y use **Fusionar** para elegir un método de fusión. Consulte [Revisar solicitudes de incorporación](/docs/es/pull-requests) para el flujo completo.

## Cambiar o crear ramas

Abre el interruptor de ramas debajo del chat, busca ramas locales y elige una para verificarla. Utiliza **Crear y cambiar a una nueva rama…** para nombrar y crear una rama. Actualiza la lista si una rama creada fuera de Dream está faltando.

Cambiar de rama cambia los archivos utilizados por cada chat en ese proyecto. Revisa el trabajo no completado antes de cambiar de rama. Para tareas paralelas con checkouts independientes, utiliza [Worktrees de Git](/docs/es/worktrees). Cuando un worktree ha terminado, utiliza su pie de página para fusionarlo en la rama base, crear una solicitud de fusión o eliminar el checkout. Consulta [Completar un worktree](/docs/es/worktrees#completear-un-árbol-de-trabajo).

## Explorar el historial de commits

<Frame caption="Explorar el historial de commits">
  <img
    src="/images/docs/git-history-panel.png"
    alt="Pestaña Historial de Git con búsqueda de commits, etiquetas de ramas y un gráfico de colores de commits y fusiones."
    width={933}

    loading="lazy"

Abrir **Git → Historial**, o **Acciones de Git → Ver historial**, para seguir los commits y los fusiones en el gráfico coloreado. Utiliza **Buscar commits** para filtrar los commits cargados por mensaje, autor, prefijo de hash o referencia. **Cargar más** incluye commits antiguos; borra la búsqueda para volver a mostrar el gráfico.

Pase el cursor sobre un commit o enfoque con el teclado para usar **Copiar hash del commit**.
