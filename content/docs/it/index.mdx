Dream unisce i tuoi progetti, gli agenti di coding basati su intelligenza artificiale, i file, i terminali, le anteprime del browser e il workflow Git in un'unica area di lavoro desktop. Connetti un'CLI di agente supportato, apri una cartella e lavora con una o più conversazioni senza cambiare strumenti.

## Cosa include Dream

- Un workspace multi-progetto con schede di progetto persistenti
- [Spazi di lavoro remoti SSH](/docs/it/remote-hosts) con agenti, file, Git e terminali remoti
- Molti chat parallele e ramificazione delle chat
- Prompt riutilizzabili tra progetti e competenze agentistiche consapevoli del provider
- Punti di controllo per risposta per la revisione e il ripristino dei file modificati da un agente
- Supporto per Codex CLI, Claude Code CLI, OpenCode CLI, Cursor Agent CLI e Grok Build CLI
- Un esploratore di file, una ricerca e modifica di file, terminali integrati e anteprime di browser
- Stato, ramo, differenza, commit, push, richiesta di pull e workflow del worktree, inclusa l'operazione di unificare un worktree completato nel suo ramo base
- Feedback sul differenziale a livello di riga e selezione degli elementi del browser che inviano messaggi mirati a un chat
- Un pannello di pull-request di GitHub per la revisione del codice, la pubblicazione di commenti, l'editing dei dettagli e il merge
- Serveri MCP configurabili e strumenti integrati per l'interazione con il browser

<Note>
  Dream esegue agenti di programmazione attraverso i loro CLIs installati. È necessario almeno un CLI supportato prima di poter iniziare una conversazione.
</Note>

## Capisci lo spazio di lavoro

Un **progetto** è una cartella sul computer o su un host SSH con chat e strumenti propri. Una **chat** è una conversazione con un proprio modello e impostazioni. Più chat nello stesso progetto condividono i file; un **albero di lavoro** offre a un'attività una copia di lavoro Git separata.

Usa [Autorizzazioni degli agenti](/docs/it/agent-modes) per scegliere come funziona un agente, e [Contesto e utilizzo](/docs/it/context-and-usage) per comprendere le informazioni sotto il composer. La [guida alle impostazioni](/docs/it/settings) elenca le preferenze applicative. Se qualcosa manca o non funziona, inizia con [Risoluzione dei problemi](/docs/it/troubleshooting).
