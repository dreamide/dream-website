Apri **Git** nella barra degli strumenti a destra per le schede **Modifiche**, **Cronologia** e **Pull request**. Il menu **Azioni Git** sotto la chat propone i passaggi successivi per il branch corrente. Il suo pulsante è evidenziato quando ci sono modifiche di cui eseguire il commit o commit di cui eseguire il push.

## Prima di iniziare

Per i commit, il tuo repository ha bisogno di un'identità autore configurata con Git. Per il push, ha bisogno di un remoto e di credenziali che possano accedervi. La creazione di un pull request utilizza il GitHub CLI, che deve essere installato e autenticato per il repository di destinazione.

Puoi scrivere tu stesso i messaggi di commit e il testo delle PR. Per generarli, abilita un modello di un provider e scegli **Impostazioni → Generale → Modelli → Modello di generazione del testo**. Con **Genera automaticamente il messaggio** attivo, Dream prepara un nuovo messaggio di commit quando termina l’ultima risposta dell’agente in esecuzione nel progetto.

## Revisione dei cambiamenti

1. Apri **Git → Modifiche** per esaminare i file modificati, aggiunti e eliminati.
2. Espandi un file per esaminare la sua differenza.
3. Scegli **Diff unificato** o **Diff diviso** nell’intestazione. **A capo automatico** è attivo per impostazione predefinita; usa il relativo interruttore nell’intestazione per mostrare le righe lunghe senza andare a capo.

Le modifiche e l’albero dei file si aggiornano al termine dei comandi del terminale e quando torni alla finestra di Dream, quindi il lavoro svolto fuori da Dream compare senza aggiornamento manuale.

Per diff estremamente grandi, Dream potrebbe mostrare **Diff troppo grande per essere renderizzato**. Utilizza **Renderizza comunque** solo quando desideri caricare quella vista più ampia, o esaminare il file nel tuo editor o terminale.

Usa l’azione **Annulla le modifiche apportate al file** di un file per scartare le modifiche di lavoro indesiderate. **Azioni modifiche → Annulla tutte le modifiche** ha un effetto più ampio; verificane la portata prima di confermare. Annullare il codice è separato dall’archiviare la chat che lo ha prodotto. Per annullare solo ciò che ha modificato una determinata risposta, usa il [checkpoint](/docs/it/checkpoints) di quella risposta.

Per chiedere a un agente di informazioni su righe specifiche, trascina sulle righe di un diff o fai clic sul controllo **+** di una riga, poi scrivi un commento. Dream lo invia insieme al percorso del file e alle righe selezionate. Vedere [Inviare feedback a una chat](/docs/it/feedback).

1. Apri **Git → Modifiche**, o scegli **Esegui commit** dal menu **Azioni Git** nel footer.
2. Esamina i diff dei file sotto il compositore del commit. Il compositore mostra quanti file include il commit.
3. Verifica **Includi le modifiche non aggiunte all’indice**. È abilitato per impostazione predefinita e include le modifiche non stage nel commit.
4. Controlla **Genera automaticamente il messaggio**, attivo per impostazione predefinita. Per scrivere un messaggio tuo, disattivalo e inseriscilo in **Messaggio di commit**; disattivarlo cancella il messaggio generato.
5. Scegli **Esegui commit**, o **Effettua il commit e il push** se sei pronto a pubblicare il commit sul remoto.

Per committare solo un sottoinsieme selezionato, stage quei file utilizzando Git in un terminale o un editor esterno e disattiva **Includi le modifiche non aggiunte all’indice**. Il pannello delle modifiche non fornisce controlli individuali di staging.

Dream rifiuta i commit in caso ci siano modifiche staged al di fuori della cartella progetto attiva. Committale separatamente prima di procedere con questa operazione.

<Warning>
  Revisti i file inclusi nonché il messaggio. Con Include unstaged abilitato, un commit può contenere lavori da diversi chat che condividono questo checkout.
</Warning>

## Spingi un ramo

1. Apri **Azioni Git** sotto la chat. **Esegui push** mostra quanti commit sono avanti rispetto all’upstream. Un branch senza upstream offre invece **Pubblica branch**.
2. In **Invia le modifiche**, controlla il **Ramo**, la **Destinazione** e i commit che verranno inviati, compreso il numero di commit in avanti e indietro del branch.
3. Scegli **Esegui push**.

Se il push non riesce, esamina l’errore e verifica il tuo accesso al remote Git. Un commit locale riuscito resta valido anche se il push successivo non riesce; controlla lo stato del branch prima di ripetere un’azione combinata.

## Fetch e pull

Usa **Azioni Git → Fetch** per scaricare nuovi commit e branch dal remote senza modificare i tuoi file. Usa **Azioni Git → Pull** per portare i commit del branch upstream nel branch corrente; il menu mostra di quanti commit sei indietro. Dream indica quanti commit ha scaricato o che il branch è già aggiornato.

Il pull modifica i file usati da tutte le chat del progetto. Prima lascia terminare le risposte in corso ed esegui il commit del tuo lavoro o mettilo da parte. **Azioni Git → Apri repository** apre il repository remoto nel browser.

## Crea una pull request

1. Lavora su un ramo caratterizzato da un nome diverso dal ramo base della richiesta di merge.
2. Scegli **Crea PR** nel piede della pagina, o **Azioni Git → Crea richiesta pull**.
3. Controlla i rami source e base e le modifiche proposte.
4. Inserisci un titolo e una descrizione, oppure usa **Genera automaticamente i dettagli PR** e verifica il testo generato.
5. Sotto **Passaggi successivi**, seleziona l'azione che corrisponde allo stato della ramificazione.
6. Accendi **Bozza** se la richiesta di merge non è pronta per il review, poi invia.

| Passo successivo | Cosa succede |
| --- | --- |
| Crea PR | Crea una PR per lavoro già spostato |
| Spingi e crea una richiesta di pull | Spinge i commit prima di creare la richiesta di merge |
| Commit, push e crea PR | Committati i cambiamenti in corso, effettuano il push e creano la richiesta di merge |

Il dialogo inizia con **Bozza** disattivato. Abilitalo per creare un PR in bozza. La creazione di un PR richiede un ramo piuttosto che un HEAD separato, e source e base non possono essere lo stesso ramo.

Se un'azione combinata fallisce, passaggi precedenti potrebbero già essere stati completati. Verifica il commit, il ramo remoto o la richiesta di merge prima di riprovarci.

## Revisione e fusione di una richiesta di pull

Apri **Git → Pull request** per visualizzare la richiesta di fusione della ramifica corrente. Usa **Riepilogo** per la sua descrizione, i controlli e il discorso, oppure **Codice** per esaminare i diff e pubblicare commenti inline. Puoi modificare il titolo e la descrizione quando è consentito e utilizza **Unisci** per scegliere il metodo di fusione. Vedi [Esaminare le pull request](/docs/it/pull-requests) per il flusso completo.

## Passare o creare ramificazioni

Apri il selettore di ramificazioni sotto il chat, cerca le ramificazioni locali e seleziona una per verificarne l'uscita. Usa **Crea e verifica nuova ramificazione…** per nominare e creare una ramificazione. Aggiorna l'elenco se una ramificazione creata al di fuori di Dream manca.

Cambiare ramificazioni modifica i file utilizzati da ogni chat in quel progetto. Verifica il lavoro incompiuto prima di effettuare il cambio. Per compiti paralleli con check-out indipendenti, usa [Git worktrees](/docs/it/worktrees). Quando un worktree è completato, utilizza il suo footer per unirsi al ramo principale, creare una richiesta di pull, o rimuovere il check-out. Vedi [Completare un worktree](/docs/it/worktrees#completa-un-worktree).

Apri **Git → Cronologia**, o **Azioni Git → Visualizza cronologia**, per seguire i commit e i merge nel grafico a colori. Usa **Cerca commit** per filtrare i commit caricati per messaggio, autore, prefisso hash o riferimento. **Carica di più** include commit più vecchi; cancella la ricerca per riprendere il grafico.

Spostare il cursore su un commit o concentrarsi su di esso con il tastierino per utilizzare **Copia hash del commit**.
