當啟用 **變更檢查點** 時，Dream會在每個代理回覆之前以及回覆完成後對專案檔案進行快照。你可以使用這些檢查點來檢視回復具體修改了哪些檔案，並在希望採取不同方法時恢復選定的檔案。

## 檢查點是如何工作的

- 一個檢查點會將專案的工作樹（包括未跟蹤的檔案）記錄在 Dream 應用程式資料中的私有儲存中。它不會在你的倉庫中建立提交、暫存或分支，且可以在非 Git 倉庫的資料夾中使用。
- 專案中的 `.gitignore` 忽略的路徑以及常見的構建資料夾（如 `node_modules`、`dist`、`build` 和 `coverage`）永遠不會被捕獲。
- 你每傳送一則訊息，Dream 都會記錄一次**修改前**的快照，並在回應完成或你停止回應時記錄**修改後**的快照。
- 檢查點需要 Dream 可用 `git` 可執行檔案。如果捕獲失敗或耗時過長，回覆將不會進行檢查點，其審查控制也不會顯示。

檢查點預設已開啟。要關閉它們，請開啟 **設定 → 一般**，找到 **聊天訊息**，並關閉 **變更檢查點**。

## 審查回覆的更改

1. 等待響應完成。
2. 將滑鼠懸停在助手訊息上，點選訊息頁尾中的時鐘圖示**檢視此回覆的檔案變更**。
3. 在 **此回覆中的變更** 中，檢視檔案列表。每一行顯示路徑、狀態（**已新增**、**已刪除**、**已修改** 或 **已重新命名**）及其行數。
4. 展開一行以檢視差異。

該對話僅比較該回復的前後快照；其他回覆或你自己的編輯產生的變化均不包含在內。如果響應被中斷，對話會註明後狀態是在你開啟它時捕獲的。

在回覆之後檔案再次發生更改，無論是來自後續回覆、終端命令還是你的編輯器，都會顯示一個“稍後編輯”徽章。二進位制檔案在沒有差異的情況下列出。

## 恢復檔案

1. 選擇您想要恢復的檔案。沒有後續編輯的檔案預設被選中；使用 **全選** 來包含所有檔案。
2. 點選 **復原**。該按鈕顯示已選擇的檔案數量。
3. 檢查標記為 **已還原** 的行，然後點選 **關閉**。

恢復會撤銷回復對選定檔案的修改，同時保留該檔案之後所作的無關編輯。回覆建立的檔案會被刪除，回覆刪除的檔案會被重新建立，被重新命名的檔案會恢復到其之前的路徑。

如果後續的編輯與回覆的更改有重疊，Dream 會保持該檔案不變併發出警告。選擇 **仍然覆寫** 可以用其回覆前的完整內容替換該檔案，從而丟棄那些後續的編輯。

<Warning>
  從對話方塊中無法撤銷恢復操作。在恢復檔案之前，請複製你需要的後續工作內容。恢復檔案不會從對話中移除訊息；在要求代理繼續之前，請告知它恢復了哪些內容。
</Warning>

還原屬於檔案操作，而非 Git 操作。還原後請開啟[變更](/docs/zh-Hant/git-workflows)檢查工作樹，並在還原同一檔案之前[儲存編輯器中的草稿](/docs/zh-Hant/files)。

## 檢查點儲存

只要其聊天仍然存在，檢查點就會持續可用。從 **設定 → 已封存聊天** 中永久刪除一個聊天會移除其檢查點，完成或刪除一個 [工作樹專案](/docs/zh-Hant/worktrees) 會移除該專案的檢查點。歸檔一個聊天會保留這些檢查點。

為了嘗試一種不同的方法同時保持之前的對話內容，可以結合使用恢復功能和[從早期訊息分支](/docs/zh-Hant/branching-chats)。僅分支操作會複製訊息，而不會改變檔案。
