右側面板的“拉取請求”按鈕會開啟當前分支的 GitHub 拉取請求。首先安裝並認證倉庫的 GitHub CLI。要建立新的拉取請求，請參考 [Git 工作流程](/docs/zh-Hant/git-workflows#建立提取要求)。

## 開啟當前分支的 PR

1. 選擇專案並檢查其當前分支。
2. 在右側面板中單擊 **拉取請求**。
3. 審查 PR 的標題、狀態、源分支和基礎分支，以及檢查結果。
4. 使用 **摘要** 進行描述和討論，或使用 **程式碼** 表示更改的檔案。

如果分支沒有合併請求，面板將提供 **建立拉取請求**。在 GitHub 上進行更改後，使用 **拉取請求操作 → 重新整理**，或選擇 **在 GitHub 上開啟** 以在瀏覽器中檢視該拉取請求。一旦分支包含該拉取請求頭之後的新提交，合併的拉取請求將不再顯示。

## 審查程式碼併發布評論

在 **摘要** 中閱讀討論內容，並使用 **寫入** 和 **預覽** 功能撰寫一篇 Markdown 評論。選擇 **發表留言** 將其釋出到 GitHub。

在 **Code** 中，展開檔案並選擇其差異中的行以發表行內評論。你可以閱讀現有的審查執行緒，並使用 **回覆** 繼續討論。當文字補丁不可用時，開啟 GitHub 上的拉取請求以檢查該檔案。

這些評論會發布到 GitHub。要詢問你的編碼代理關於本地更改的情況，請使用 [在更改中進行差異回饋](/docs/zh-Hant/feedback#在差異中註釋行)。

## 編輯標題和描述

當您的賬戶有許可權時，使用 **編輯標題** 或 **編輯描述**。編輯標題後儲存標題；對於描述，使用 **寫入** 和 **預覽**，然後 **儲存**。您還可以在編輯控制元件可用的情況下編輯自己的評論。

## 合併一個拉取請求

1. 審查程式碼、討論和檢查。
2. 點選面板標題欄的“合併”按鈕。
3. 在 **合併 PR** 中確認源分支和基礎分支。
4. 選擇一種可用的方法：**建立合併提交**，**壓縮提交並合併**，或**變基並合併**。
5. 提交合並。

只有開放的、非草稿的拉取請求才能被合併。請先在 GitHub 上將草稿標記為“已準備就緒”。你的賬戶需要合併許可權，且倉庫會決定哪些合併方式可用。當倉庫要求未滿足時，GitHub 可以拒絕合併。

Dream 檢查 PR 是否仍顯示載入合併詳情時的頭提交。如果該提交在 GitHub 上已更改，請重新整理並審查新的變更後再重試。
