title: "使用聊天"

一個聊天包含與程式設計代理的一段對話。聊天通常屬於某個專案，並擁有自己的模型、權限和對話記錄。對於想要各自獨立回頭處理的任務（例如修正錯誤和審查功能），請使用不同的聊天。

若想在不開啟資料夾的情況下提問，請開始一個[無專案的聊天](/docs/zh-Hant/standalone-chats)。

## 開始對話

1. 選擇你想要工作的專案分頁。
2. 在左側工具欄點選 **新聊天**。
3. 檢查訊息框下方的模型和許可權。
4. 描述任務並提交您的訊息。

新聊天會使用您的[預設模型設定](/docs/zh-Hant/models)。當您再次點選**新聊天**時，空草稿可以被重新使用。一旦您傳送訊息，該對話將出現在專案的聊天記錄中。

為了一個有用的第一條訊息，給代理一個結果和一種檢查它的方法。例如：

> 找出重新整理頁面後設定表單遺失數值的原因。修正問題，並說明你如何驗證修正結果。

使用 [檔案引用和附件](/docs/zh-Hant/providing-context) 指向相關的程式碼或影象。

## 返回到對話中

1. 在左側工具欄點選 **聊天記錄**。
2. 瀏覽當前專案的聊天記錄，最近更新的對話排在前面。
3. 在 **搜尋歷史** 中輸入聊天標題的一部分以縮小列表。
4. 選擇對話以開啟它。

記錄搜尋會篩選此專案的聊天標題。若要跨專案搜尋標題和訊息文字，請按一下頂端列的**搜尋聊天**（預設快速鍵在 macOS 上為 **Command+Shift+F**，在 Windows/Linux 上為 **Ctrl+Shift+F**）。結果涵蓋本機專案、已連線的遠端主機，以及[無專案的聊天](/docs/zh-Hant/standalone-chats)。選取已封存的結果會將其還原；選取已關閉專案中的聊天則會重新開啟該專案。

如果無法搜尋主機，請重新連接它並再試一次。當結果被截斷時，可縮小查詢範圍。您也可以在 [已封存聊天](/docs/zh-Hant/archived-chats) 中管理較舊的對話。

當啟用 [多聊天](/docs/zh-Hant/multiple-chats) 時，選擇一個對話可以將其置於並排佈局中。當禁用多聊天時，每次只檢視一個對話。

## 重新命名一個聊天記錄

Dream 在對話開始後可以生成一個標題。為了賦予其更具體的名稱，請開啟聊天的 **…** 選單，選擇 **編輯**，或雙擊標題。在 **編輯聊天** 中輸入名稱並點選 **儲存**。使用 **取消** 以保留現有名稱。

“修復設定持久化”和“審查設定測試”這類名稱比多個同專案命名的聊天更容易區分。

## 跟蹤正在進行的工作

啟用 **桌面通知**（位於 **設定 → 一般 → 聊天訊息**），即可在 Dream 於背景執行時，收到聊天完成、失敗或需要你輸入的提醒。點選通知可開啟對應聊天。**通知提示音** 是獨立選項，即使 Dream 取得焦點也可以播放。

通知也涵蓋此視窗未跟隨、但仍在主機上繼續執行的回合。由你自行停止的回合不會傳送通知。

正在串流接收回覆的聊天會顯示載入指示器。傳送訊息後，Dream 會捲動到該訊息，使其出現在可見區域。

當代理響應時，聊天介面會顯示其進度和工具活動。點選開放工具詳情以檢查命令、檔案讀取或更改。當代理提供任務列表時，訊息框旁邊的任務控制會顯示其進度。

聊天記錄和專案分頁會顯示每個聊天的狀態：正在回應時顯示轉圈圖示，代理正在等待你時顯示琥珀色圓點，已完成但你尚未開啟時顯示綠色圓點。選取專案並開啟對話，即可閱讀最新訊息。使用輸入區中的停止控制項可中斷回應。停止回應不會復原已經做出的檔案變更。

回合是在專案的主機上執行，而不是在視窗中執行。如果視窗與主機的連線中斷，回合會繼續執行，Dream 也會自動重新連線。結束 Dream 會停止由應用程式啟動的主機及其回合；若要在關閉應用程式後讓代理繼續工作，請[自行執行主機](/docs/zh-Hant/dream-host)。

回覆完成後，使用其底部的“檢視此回覆的檔案變更”來檢視它修改了哪些檔案，並[恢復其中任意一個](/docs/zh-Hant/checkpoints)。

## 將訊息排入佇列

你不必等回應完成才傳送下一個指示。在代理工作時輸入訊息並送出，Dream 會將它加入該聊天的佇列，並在目前回合結束時執行。回合執行期間，輸入區的按鈕在訊息框為空時會停止回合，在你輸入內容後則會傳送訊息。

有訊息在等待，或有某次執行需要你處理時，**佇列**清單會顯示在訊息框上方。每一列會顯示訊息、其模型和狀態。

| 狀態 | 含義 |
| --- | --- |
| 排隊中 | 等待排在前面的回合 |
| 執行中 | 代理目前正在處理的回合 |
| 等待中 | 執行中的回合正在等待你的回答或核准 |
| 已中斷 | 在完成前就已停止，例如因為停止控制項或主機重新啟動 |
| 失敗 | 因錯誤而結束 |

對排隊中的訊息使用**取消**，可將它移出佇列。失敗或已中斷的執行會提供**重試**和**移除**。重試之前，請先閱讀已中斷的執行留下的回覆，因為部分工作可能已經完成。

**暫停佇列**會保留排隊中的訊息，並讓目前回合執行完畢。**繼續佇列**會再次開始執行這些訊息。停止控制項則不同：它會結束執行中的回合及其[委派](/docs/zh-Hant/delegation)的所有任務，並暫停佇列。

失敗或已中斷的執行也會暫停佇列，此時佇列的標題會顯示**佇列已暫停**。傳送新訊息會繼續佇列，並清除這些執行項目。

佇列儲存在專案的主機上，重新啟動 Dream 後仍會保留。主機重新啟動後，原本執行中的回合會標記為已中斷，佇列則維持暫停，直到你繼續為止。如果排隊中的訊息無法傳送，其文字會回到訊息框。

## 關閉、歸檔還是刪除？

| 操作 | 結果 | 如何返回 |
| --- | --- | --- |
| 關閉一個聊天列 | 從多聊天佈局中移除它 | 從聊天記錄中開啟它 |
| 歸檔聊天記錄 | 從當前聊天記錄中移除它 | 在設定 → 已歸檔聊天中恢復它 |
| 刪除一個歸檔的聊天記錄 | 永久從 Dream 中刪除聊天及其訊息 | 它無法透過 Dream 恢復 |

關閉一列在你需要更多空間時很有用。歸檔在任務完成時很有用。這兩種操作都不會撤銷代理對專案檔案的更改。

要嘗試不同的方法同時保留之前的對話內容，[從訊息分支](/docs/zh-Hant/branching-chats)。為了為後續任務做準備，[將提示儲存到暫存](/docs/zh-Hant/stash)。對於需要在多個專案中重複使用的指令，建立一個[可複用的提示](/docs/zh-Hant/saved-prompts)，然後從編排器的 **+ → 執行提示** 選單中執行。輸入 **$** 來呼叫一個[代理技能](/docs/zh-Hant/skills)。
