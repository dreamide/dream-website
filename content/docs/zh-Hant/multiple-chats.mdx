多聊天介面在同一專案中並排顯示多個對話。每個對話都保留自己的訊息和模型選擇，因此你可以比較不同的方法，或在開發實現的同時保持審查內容可見。

## 同時開啟聊天記錄

1. 開啟一個專案以及你想要保持可見的對話。
2. 在左側工具欄點選 **啟用多聊天**。將滑鼠懸停在工具欄圖示上以檢視其名稱。
3. 點選 **新聊天** 可在已開啟的聊天旁邊新增一個新對話。
4. 在新聊天的編輯器中選擇一個模型併傳送訊息。

要恢復之前的對話，請開啟 **聊天記錄** 並選擇它。已選擇佈局中的某個聊天記錄將聚焦該對話，而不是建立重複項。

多聊天是專案設定。你可以在一個專案中同時保留多個對話，並在另一個專案中使用單個對話。

## 整理工作區

- **調整大小**：拖動聊天欄之間的分隔線以調整其寬度。
- **重新排序**：拖動聊天記錄標題區域將其移動到另一場對話旁邊。
- **關閉一列：** 點選其表頭中的 **×**。對話仍保留在聊天記錄中。
- **返回單次對話：** 選擇你想要保持檢視的對話，然後在左側工具欄點選“停用多聊天”。

當存在其他開啟的聊天視窗時，可以使用關閉控制功能以保持這些聊天視窗可見。關閉多聊天功能不會歸檔其他對話；當需要時，仍可從歷史記錄中重新開啟它們。

## 示例：實現，然後審查

1. 開始一個名為“實現設定持久化”的聊天，並要求它修復設定表單。
2. 啟用多聊天並建立一個名為“審查設定持久化”的第二個聊天。
3. 如果你想要獲得另一個啟用模型的評估，請在審查聊天中選擇其他模型。
4. 一旦實現準備就緒，請求審查聊天框檢查當前更改並報告問題，而無需編輯檔案。
5. 在詢問實現聊天機器人解決其發現的問題時，保持審查內容可見。
6. 當需要更多空間時，關閉審查列。從歷史記錄中重新開啟它以重新檢視發現內容。

第二個聊天不會自動接收第一個聊天的訊息。請為其提供任務上下文，並[引用相關檔案](/docs/zh-Hant/providing-context)，或者在需要複製早期訊息時使用[聊天分支](/docs/zh-Hant/branching-chats)。

## 瞭解什麼是共享

同一個專案中的所有聊天都針對同一個專案資料夾工作。檔案編輯和 Git 分支更改對其他聊天可見，即使它們的對話歷史是分開的。

<Warning>
  兩個代理同時編輯同一檔案可能會相互干擾。當任務需要獨立檢出時，請使用單獨的 [Git 工作樹](/docs/zh-Hant/worktrees)。僅啟用多聊天功能並不能隔離檔案變更。
</Warning>

對於已完成的對話，使用 [歸檔](/docs/zh-Hant/archived-chats) 來保持對話歷史的簡潔。
