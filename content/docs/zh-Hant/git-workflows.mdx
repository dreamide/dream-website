在右側工具列中開啟 **Git**，以查看 **變更**、**歷史** 和 **拉取請求** 紙。聊天對話下方的 **Git 動作** 菜單提供當前分支的下一步操作。

**Git 動作**按鈕位於底部列右側，有變更可提交或有提交可推送時會醒目顯示。**Git** 只會在位於 Git 儲存庫內的專案中顯示。

## 開始之前

對於提交操作，您的倉庫需要配置 Git 作者身份。對於推送操作，它需要一個遠端倉庫以及可以訪問該遠端倉庫的憑據。拉取請求的建立使用 GitHub CLI，該工具必須安裝併為目標倉庫進行認證。

你可以手動輸入提交資訊和拉取請求文字。要生成這些內容，請啟用一個供應商模型，並選擇 **設定 → 一般 → 模型 → 文字生成模型**。

## 審查更改

1. 開啟 **Git → 變更** 以檢視已修改、新增和刪除的檔案。
2. 展開檔案以審查其差異。
3. 在標題列中選擇**統一差異**或**並排差異**。**自動換行**預設為開啟，其切換開關也在該處，位於**全部展開**和**全部折疊**旁邊。
4. 在檔案的差異標題中按一下其路徑，即可在**檔案**中開啟該檔案。

清單會在檔案變更時、終端機指令執行完畢後，以及你回到 Dream 視窗時更新。

對於非常大的差異，Dream 可能會顯示 **差異太大而無法渲染**。僅在您希望載入該更大的檢視，或在編輯器或終端中檢查檔案時，才使用 **無論如何渲染**。

使用檔案的 **還原檔案變更** 動作捨棄不需要的工作變更。**變更操作 → 還原所有變更** 的作用範圍更廣；確認前請檢查其範圍。還原程式碼與封存產生該程式碼的聊天是兩件獨立的事。若只想復原某個回覆所做的變更，請使用該回覆的[檢查點](/docs/zh-Hant/checkpoints)。

要向代理詢問特定行的內容，請在差異中拖動行號或點選行的 **+** 控制按鈕，然後輸入評論。Dream 會將該評論連同檔案路徑和選中的行一起傳送。詳見 [向聊天傳送回饋](/docs/zh-Hant/feedback)。

1. 開啟 **Git → 變更**，或從底部的 **提交** 菜單中選擇 **Git 動作**。
2. 檢視提交組合下方的檔案差異。
3. 檢查 **包括未暫存的**。它預設已啟用，並會將未暫存的更改包含在提交中。
4. 檢查預設開啟的 **自動產生訊息**。若要自行撰寫訊息，請將其關閉，並在 **提交訊息** 中輸入；關閉時會清除已產生的訊息。
5. 選擇 **提交**，或選擇 **提交並推送** 如果你準備將提交發布到遠端。

開啟**自動產生訊息**後，Dream 會在專案中最後一個執行中的代理回合結束時，於背景草擬提交訊息，因此你開啟面板時通常已經準備好。在 macOS 上按 **Command+Enter**，或在 Windows/Linux 上按 **Ctrl+Enter** 即可提交；加按 **Shift** 則會提交並推送。

僅提交選定的子集時，請在終端或外部編輯器中使用 Git 對這些檔案進行暫存，並將 **包括未暫存的** 關閉。更改面板不提供單個檔案的暫存控制。

Dream 在檢測到活動專案資料夾外存在已暫存的更改時會拒絕提交。請單獨提交這些更改，然後再繼續此操作。

<Warning>
  在啟用“包含未提交內容”時，一次提交可以包含多個共享此檢出的聊天的工作。
</Warning>

在 **Git 動作**中，對沒有上游的分支使用**發佈分支**，對待推送的提交使用**推送**。兩者都會開啟**推送更改**預覽，顯示分支、目的地以及即將送出的提交。檢查這些內容後，按一下**推送**。有上游時，**推送**和**拉取**選單項目會顯示分支領先和落後的提交數量。

如果推送失敗，請檢查錯誤訊息，並確認你對遠端的存取權限。當遠端有你尚未取得的提交時，Dream 會提示你先拉取再重新推送。即使後續的推送失敗，已成功的本機提交仍會保留；重複執行組合動作前，請先檢查分支狀態。

## 擷取與拉取

**Git 動作 → 擷取**會從遠端下載新的提交，但不會變更你的檔案。**拉取**還會將上游分支的提交併入你的分支。

拉取之後，會有通知回報收到了多少個提交。在通知中選擇**檢視變更**可開啟**已拉取的變更**，其中列出這些提交及其變更的檔案。

如果你的分支和其上游都有新的提交，Dream 會將上游的提交合併到你的分支，而不會進行變基。若該合併會產生衝突，Dream 會中止合併，讓你的檔案維持原狀，並列出發生衝突的檔案。請在終端機中使用 Git 解決差異，然後再次拉取。

拉取會變更專案中每個聊天所使用的檔案。請先讓執行中的回覆完成，並提交或暫時擱置你的工作。**Git 動作 → 開啟儲存庫** 會在瀏覽器中開啟遠端儲存庫。

## 建立提取要求

1. 在名稱與 PR 的基礎分支不同的特徵分支上工作。
2. 選擇 **Git 動作 → 建立拉取請求**。
3. 審查源分支和基礎分支以及提出的變更。
4. 輸入標題和描述，或使用 **自動產生 PR 詳細信息** 並審查生成的文字。
5. 在“下一步”中，選擇與分支狀態匹配的操作。
6. 如果該拉取請求尚未準備好審查，請開啟 **草稿** 然後提交。

對話方塊初始時 **草稿** 為關閉狀態。啟用它以建立草稿型 Pull Request。建立 Pull Request 需要一個分支，而不是一個脫離 HEAD 的狀態，且源分支和基礎分支不能相同。

如果一個組合操作失敗，早期步驟可能已經完成。在重試之前，請檢查提交、遠端分支或拉取請求。

## 審查併合並一個拉取請求

開啟 **Git → 拉取請求** 以查看當前分支的提取要求。使用 **摘要** 來查看其描述、檢查項目與討論內容，或使用 **程式碼** 來檢視差異並張貼行內評論。當允許時，您可以編輯標題與描述，並使用 **合併** 來選擇合併方式。請參閱 [檢視提取要求](/docs/zh-Hant/pull-requests) 以獲取完整流程。

## 切換或建立分支

開啟聊天下方的分支切換器，搜尋本機分支，並選取其中一個以將其檢出。使用**建立並檢出新分支…** 可命名並建立分支。清單會在每次開啟時重新載入，因此會包含在 Dream 之外建立的分支。

切換分支會改變該專案中每個對話所使用的檔案。在切換前請審查未完成的工作。對於具有獨立檢查出的平行任務，請使用 [Git 工作樹](/docs/zh-Hant/worktrees)。當一個工作樹完成時，可使用其頁腳將其合併至基礎分支、建立拉取請求，或移除該檢查出。請參閱 [完成一個工作樹](/docs/zh-Hant/worktrees#完成一個工作樹)。

### 刪除本機分支

1. 開啟分支切換器，將滑鼠游標停留在該分支上，或用鍵盤移到該分支。
2. 按一下該列上的垃圾桶圖示**刪除分支**。
3. 閱讀摘要。Dream 會回報該分支的提交是否已在基礎分支中、其拉取請求的狀態，以及是否有提交只存在於此分支上。
4. 按一下**刪除分支**。如果會遺失提交，按鈕會顯示為**仍要刪除**。

刪除只會移除本機分支，其遠端分支不受影響。你無法刪除目前分支、基礎分支，或在主檢出中開啟的分支。

如果該分支已在某個[工作樹](/docs/zh-Hant/worktrees)中檢出，對話方塊會改為提供**刪除工作樹和分支**。這也會刪除該工作樹的資料夾及其聊天。

開啟 **Git → 歷史**，或 **Git 動作 → 檢視歷史**，以追蹤提交與合併的彩色圖表。使用 **搜尋提交** 來依照訊息、作者、哈希前綴或參考標記過濾已載入的提交。**Load more** 會包含較舊的提交；清除搜尋條件以重新顯示圖表。

將游標移至某筆提交紀錄或使用鍵盤聚焦該筆提交紀錄，以使用 **複製提交雜湊**。
