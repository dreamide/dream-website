在右側工具列中開啟 **Git**，以查看 **變更**、**歷史** 和 **拉取請求** 紙。聊天對話下方的 **Git 動作** 菜單提供當前分支的下一步操作。

## 開始之前

對於提交操作，您的倉庫需要配置 Git 作者身份。對於推送操作，它需要一個遠端倉庫以及可以訪問該遠端倉庫的憑據。拉取請求的建立使用 GitHub CLI，該工具必須安裝併為目標倉庫進行認證。

你可以手動輸入提交資訊和拉取請求文字。要生成這些內容，請啟用一個供應商模型，並選擇 **設定 → 一般 → 模型 → 文字生成模型**。

## 審查更改

1. 開啟 **Git → 變更** 以檢視已修改、新增和刪除的檔案。
2. 展開檔案以審查其差異。
3. 在標題中選擇 **統一差異** 或 **並排差異**，若必要，於 **變更動作** 中啟用文字捲動。
4. 若在 Dream 之外完成的變更尚未反映，請使用 **變更動作 → 重新整理**。

對於非常大的差異，Dream 可能會顯示 **差異太大而無法渲染**。僅在您希望載入該更大的檢視，或在編輯器或終端中檢查檔案時，才使用 **無論如何渲染**。

使用檔案的 **還原檔案變更** 功能來放棄不需要的暫存更改。**還原所有變更** 的範圍更廣；在確認之前請務必審查其作用範圍。還原始碼與歸檔生成該程式碼的聊天記錄是兩個獨立的操作。若只想撤銷某個回覆所導致的更改，請使用該回復的 [檢查點](/docs/zh-Hant/checkpoints)。

要向代理詢問特定行的內容，請在差異中拖動行號或點選行的 **+** 控制按鈕，然後輸入評論。Dream 會將該評論連同檔案路徑和選中的行一起傳送。詳見 [向聊天傳送回饋](/docs/zh-Hant/feedback)。

1. 開啟 **Git → 變更**，或從底部的 **提交** 菜單中選擇 **Git 動作**。
2. 檢視提交組合下方的檔案差異。
3. 檢查 **包括未暫存的**。它預設已啟用，並會將未暫存的更改包含在提交中。
4. 檢查預設開啟的 **自動產生訊息**。若要自行撰寫訊息，請關閉此選項並輸入文字；關閉時會清除產生的訊息。
5. 選擇 **提交**，或選擇 **提交並推送** 如果你準備將提交發布到遠端。

僅提交選定的子集時，請在終端或外部編輯器中使用 Git 對這些檔案進行暫存，並將 **包括未暫存的** 關閉。更改面板不提供單個檔案的暫存控制。

Dream 在檢測到活動專案資料夾外存在已暫存的更改時會拒絕提交。請單獨提交這些更改，然後再繼續此操作。

<Warning>
  在啟用“包含未提交內容”時，一次提交可以包含多個共享此檢出的聊天的工作。
</Warning>

對於沒有上游的分支，使用 **發佈分支**；要傳送待推送的提交，使用 **推送**。這些底部操作會立即執行推送。請先檢查分支、遠端儲存庫及 **歷史** 中的提交；若有上游，底部會顯示領先和落後的提交數。

如果推送失敗，請檢查錯誤並確認遠端訪問許可權。即使後續的推送失敗，成功的本地提交仍會保持已提交狀態；在重複組合操作前，請檢查分支狀態。

## 建立提取要求

1. 在名稱與 PR 的基礎分支不同的特徵分支上工作。
2. 選取底部的 **建立 PR**，或 **Git 動作 → 建立拉取請求**。
3. 審查源分支和基礎分支以及提出的變更。
4. 輸入標題和描述，或使用 **自動產生 PR 詳細信息** 並審查生成的文字。
5. 在“下一步”中，選擇與分支狀態匹配的操作。
6. 如果該拉取請求尚未準備好審查，請開啟 **草稿** 然後提交。

| 下一步 | 發生了什麼 |
| --- | --- |
| 建立 PR | 為已推送的工作建立 PR |
| 推送並建立 PR | 在建立拉取請求之前推送提交 |
| 提交、推送並建立 PR | 提交工作更改，推送，並建立 PR |

對話方塊初始時 **草稿** 為關閉狀態。啟用它以建立草稿型 Pull Request。建立 Pull Request 需要一個分支，而不是一個脫離 HEAD 的狀態，且源分支和基礎分支不能相同。

如果一個組合操作失敗，早期步驟可能已經完成。在重試之前，請檢查提交、遠端分支或拉取請求。

## 審查併合並一個拉取請求

開啟 **Git → 拉取請求** 以查看當前分支的提取要求。使用 **摘要** 來查看其描述、檢查項目與討論內容，或使用 **程式碼** 來檢視差異並張貼行內評論。當允許時，您可以編輯標題與描述，並使用 **合併** 來選擇合併方式。請參閱 [檢視提取要求](/docs/zh-Hant/pull-requests) 以獲取完整流程。

## 切換或建立分支

在聊天區域下方開啟分支切換器，搜尋本地分支並選擇一個以檢出它。使用 **建立並檢出新分支…** 來命名和建立分支。如果在 Dream 之外建立的分支缺失，重新整理列表。

切換分支會改變該專案中每個對話所使用的檔案。在切換前請審查未完成的工作。對於具有獨立檢查出的平行任務，請使用 [Git 工作樹](/docs/zh-Hant/worktrees)。當一個工作樹完成時，可使用其頁腳將其合併至基礎分支、建立拉取請求，或移除該檢查出。請參閱 [完成一個工作樹](/docs/zh-Hant/worktrees#完成一個工作樹)。

## 瀏覽提交歷史紀錄

開啟 **Git → 歷史**，或 **Git 動作 → 檢視歷史**，以追蹤提交與合併的彩色圖表。使用 **搜尋提交** 來依照訊息、作者、哈希前綴或參考標記過濾已載入的提交。**Load more** 會包含較舊的提交；清除搜尋條件以重新顯示圖表。

將游標移至某筆提交紀錄或使用鍵盤聚焦該筆提交紀錄，以使用 **複製提交雜湊**。
