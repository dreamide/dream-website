title: "疑難排解"
description: "解決缺失模型和聊天、終端和預覽問題，以及常見的 Git 錯誤。"
---

從受影響的聊天或工具中檢視錯誤。在更改設定之前，請確認所選的專案和供應商，特別是當多個聊天同時開啟時。

## 未檢測到供應商 CLI

1. 開啟你的系統終端並驗證供應商 CLI 是否啟動。
2. 完成其登入或首次執行設定。
3. 在 Dream 中開啟 **設定 → 提供者** 並重新整理該供應商。
4. 如果你在 Dream 執行時安裝了它，且檢測仍然失敗，請重啟 Dream 以使其能夠識別更改後的環境。

Dream 需要可執行檔案能夠被應用程式訪問，而不僅限於互動式 shell 中的快捷方式或別名。請參見 [連線服務商](/docs/zh-Hant/providers)。

## 模型缺失或我無法開始聊天

檢查 **設定 → 提供者**，並啟用至少一個檢測到的模型。僅有一個未啟用模型的檢測到的 CLI 並不足以開始聊天。在更改供應商的認證或模型配置後，請重新整理。對於 OpenCode，必須在重新整理前完成其認證或配置。

然後檢查 **設定 → 一般 → 模型**。如果之前選擇的預設模型不可用，請再次選擇一個啟用的模型。現有的聊天會話有自己的選擇器；更改全域性預設模型不會替換這些選擇。

## 推理強度或速度控制缺失

這些控制元件取決於所選模型的功能。請選擇一個提供你需要的選項的模型。切換聊天的模型會重置其努力程度和速度選擇，因此切換後請檢查兩者。參見 [模型與預設設定](/docs/zh-Hant/models)。

## 我找不到聊天功能

1. 選擇對話發生專案的專案。
2. 開啟 **聊天記錄** 並清空其搜尋框。
3. 按聊天標題搜尋，而不是搜尋其訊息中的詞語。
4. 檢查 **設定 → 已封存聊天**，如果聊天記錄在那裡，請恢復該聊天。
5. 如果專案已關閉，可透過啟動螢幕上的“最近關閉”重新開啟它。

關閉多聊天列不會歸檔對話。沒有訊息的空聊天不會出現在歷史記錄中。透過 Dream 無法恢復永久刪除的聊天。

## 一個已恢復的聊天記錄又被歸檔了

恢復聊天會保留其最後活動日期。如果再次執行 **立即封存**，且該日期早於截止時間，則可再次符合歸檔條件。在執行該操作前，請檢查截止時間以及您希望保留的聊天記錄。

## 分支功能不可用

在當前響應完成之前不要分支。**新工作樹**也要求一個 Git 倉庫。缺失或無效的基引用可能會阻止工作樹的建立；請確認倉庫中存在您想要使用的已提交分支或引用。

如果新工作樹中缺少預期的編輯，請檢查這些更改是否在原始專案中未提交。工作樹不會複製這些更改。參見 [Git 工作樹](/docs/zh-Hant/worktrees)。

## 一個回覆沒有“檢視檔案更改”控制功能

該控制元件在助手訊息響應完成後出現，且僅當為該回復捕獲了檢查點時才會出現。請檢查 **變更檢查點** 中是否啟用了 **設定 → 一般 → 聊天訊息**，並確保 `git` 可執行檔案對 Dream 可用。非常大的專案可能超出捕獲時間限制，此時回覆將不會捕獲檢查點。參見 [審查與恢復更改](/docs/zh-Hant/checkpoints)。

## 我無法傳送差異或元素回饋

在目標聊天正在響應時，傳送控制元件會被禁用，並顯示 **聊天忙碌中**。等待其完成，或在彈出選單中啟用 **新聊天**。如果彈出選單提示選擇不再匹配差異，請重新整理更改並重新選擇行。參見 [向聊天傳送回饋](/docs/zh-Hant/feedback)。

## 在終端中繼續缺失

該功能僅適用於具有有效可恢復提供程式會話的 Claude 聊天，並在響應處理過程中被禁用。新聊天、其他提供程式，或在更改模型或速度後重置會話可能無法使用該功能。請參見 [終端](/docs/zh-Hant/terminals#在終端中繼續一個-claude-聊天記錄)。

## 終端無法開啟

檢查專案目錄是否仍然存在。在 **設定 → 一般 → 終端機** 中選擇一個可用的 shell，然後開啟一個新的會話。對於 Claude 繼續功能，原始會話目錄也必須存在。嘗試在系統終端中使用相同的 shell 以識別環境問題。

## 瀏覽器預覽為空或過時

確認應用程式正在執行，並使用其終端中顯示的完整 URL 和埠。檢查終端錯誤，然後嘗試 **重新整理瀏覽器** 或 **強制重新載入**。對比你係統瀏覽器中的 URL。使用 DevTools 檢查頁面錯誤；僅在相關身份驗證或快取問題時清除 Cookie 或快取。參見 [瀏覽器預覽](/docs/zh-Hant/browser)。

## 無法儲存檔案

檢查檔案是否可寫，並檢視編輯器的錯誤。如果檔案在你編輯期間已更改，請在 **從磁碟重新載入** 之前儲存你的草稿，然後重新應用預期的更改。參見 [檔案與搜尋](/docs/zh-Hant/files#處理編輯器外部更改的檔案)。

## Git 操作失敗

對於 PR 評論、編輯或合併的問題，請參見 [審查拉取請求](/docs/zh-Hant/pull-requests)。請檢查 GitHub CLI 是否已認證，以及您的賬戶是否具有所需的倉庫許可權。一個草稿拉取請求在合併前必須標記為“已準備就緒”。

| 症狀 | 要檢查什麼 |
| --- | --- |
| 一個資料夾沒有 Git 工具 | 在 Git 倉庫中開啟一個資料夾 |
| 沒有暫存的更改要提交 | 審查時包含未暫存的檔案，或透過 Git 暫存目標檔案 |
| 專案外的暫存更改 | 在使用 Dream 的提交操作之前，分別提交它們 |
| 推送沒有目標地址 | 配置 Git 遠端倉庫並驗證訪問許可權 |
| 建立 PR 會報告一個 CLI 錯誤 | 驗證 GitHub CLI 是否已安裝、已認證，並能訪問倉庫 |
| PR 源和基礎分支相同 | 在建立 PR 之前切換到一個功能分支 |
| 建立 PR 時報告斷開的 HEAD | 在建立 PR 之前檢出一個分支 |
| 工作區移除失敗 | 審查並保留該檢出版本中的未提交更改 |
| 合併與移除功能不可用 | 工作樹與其基線沒有提交記錄領先，或者主檢出存在未提交的更改或正在進行的合併 |
| 完整工作樹會報告衝突 | 合併被中止，沒有任何更改；將基礎分支合併到工作樹中，解決衝突，提交，然後重新嘗試 |
| 在完整工作樹中建立拉取請求不可用 | 配置 Git 遠端倉庫並安裝 GitHub CLI |

在組合操作失敗後，重試前檢查分支狀態：一個提交或推送可能在後續步驟失敗前已經成功。參見 [Git 工作流程](/docs/zh-Hant/git-workflows)。
