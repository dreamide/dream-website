Dream 與你計算機上已安裝的程式設計代理命令列工具協同工作。

## 支援的供應商

| 供應商 | 必需的 CLI |
| --- | --- |
| OpenAI | Codex CLI |
| Anthropic | Claude Code CLI |
| OpenCode | OpenCode CLI |
| Cursor | Cursor Agent CLI |
| Grok 構建 | Grok 構建 CLI |

從其供應商處安裝 CLI，然後在 Dream 之外完成該 CLI 的正常登入或身份驗證流程。

## 啟用模型

1. 在 Dream 中開啟設定。
2. 選擇 **提供者**。
3. 安裝或認證其 CLI 後，重新整理提供者。
4. 開啟供應商的啟用開關，然後啟用其檢測到的一個或多個模型。
5. 開啟 **一般 → 模型**，為新的聊天和提交及拉取請求草稿設定預設值。

在開啟第一個專案之前，必須啟用至少一個模型。聊天在啟動後可以使用不同於預設模型的啟用模型。

## 使用多個供應商

啟用您希望使用的每個供應商的模型。聊天編排器會列出已啟用的模型，因此您可以為另一場對話選擇不同的供應商，或在現有聊天中更改模型。

例如，你可以將你的實現聊天保留在一個供應商上，而使用另一個供應商建立審查聊天。你無需每次更改全域性預設設定。請參考 [模型與預設設定](/docs/zh-Hant/models) 來配置新聊天的預設設定、推理強度、速度以及獨立的 Git 撰寫模型。

## 瞭解不同供應商之間的差異

已安裝的 CLI 負責身份驗證和執行代理工作。不同供應商之間的模型列表、支援的努力程度和速度選項、附件處理、使用資訊以及許可權行為可能有所不同。

Dream 為每個聊天提供了 **詢問**、**接受編輯** 和 **完整存取** 三種許可權。在選擇之前，請閱讀 [智慧體許可權](/docs/zh-Hant/agent-modes)。Claude 透過可恢復會話進行聊天時，也支援 [在終端中繼續聊天](/docs/zh-Hant/terminals#在終端中繼續一個-claude-聊天記錄)。

[技能](/docs/zh-Hant/skills)適用於 Claude Code、Codex、OpenCode 和 Cursor。[MCP 伺服器](/docs/zh-Hant/mcp-servers)和 Dream 的內建瀏覽器工具適用於 Claude Code、Codex、OpenCode 和 Grok Build；Cursor 不支援這些由 Dream 管理的工具連線。

## 檢查 CLI 更新

供應商卡片在可用時會顯示已安裝的 CLI 版本。Dream 還會檢查是否有新版本，並在發現新版本時顯示 **更新可用：…** 標籤。該標籤僅報告更新的可用性，並不會執行安裝操作。請使用該 CLI 的常規安裝方法進行更新，然後在 Dream 中重新整理其供應商卡片。

使用供應商的啟用開關將其模型從可用選擇中隱藏，而無需解除安裝 CLI。在更改啟用的供應商或模型後，請重新檢查預設設定。

## 故障排查檢測

如果一個供應商顯示 **未檢測到 CLI**：

1. 開啟你的系統終端並驗證 CLI 命令能否成功啟動。
2. 完成 CLI 所請求的任何登入或首次執行設定。
3. 返回 **設定 → 提供者** 並重新整理它。
4. 對於 OpenCode，如果未顯示模型，請執行其身份驗證流程或配置 `opencode.json` 檔案。

如果在 Dream 啟動時已安裝了 CLI，如果重新整理仍無法檢測到它，請重新啟動 Dream。該命令必須在 Dream 的環境中可用；僅一個 shell 別名並不等同於已安裝的 CLI。

如果檢測到 CLI 但所需的模型缺失，請檢查供應商的賬戶/配置並重新整理列表。如果模型已列出但在聊天中不可用，請透過其切換按鈕啟用模型，並確認供應商本身已啟用。有關更多檢查，請參見 [故障排查](/docs/zh-Hant/troubleshooting)。
