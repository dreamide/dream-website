多聊天界面在同一项目中并排显示多个对话。每个对话都保留自己的消息和模型选择，因此你可以比较不同的方法，或在开发实现的同时保持审查内容可见。

## 同时打开聊天记录

1. 打开一个项目以及你想要保持可见的对话。
2. 在左侧工具栏点击 **启用多聊天**。将鼠标悬停在工具栏图标上以查看其名称。
3. 点击 **新聊天** 可在已打开的聊天旁边添加一个新对话。
4. 在新聊天的编辑器中选择一个模型并发送消息。

要恢复之前的对话，请打开 **聊天记录** 并选择它。已选择布局中的某个聊天记录将聚焦该对话，而不是创建重复项。

多聊天是项目设置。你可以在一个项目中同时保留多个对话，并在另一个项目中使用单个对话。

## 整理工作区

- **调整大小**：拖动聊天栏之间的分隔线以调整其宽度。
- **重新排序**：拖动聊天记录标题区域将其移动到另一场对话旁边。
- **关闭一列：** 点击其表头中的 **×**。对话仍保留在聊天记录中。
- **返回单次对话：** 选择你想要保持视图的对话，然后在左侧工具栏点击“停用多聊天”。

当存在其他打开的聊天窗口时，可以使用关闭控制功能以保持这些聊天窗口可见。关闭多聊天功能不会归档其他对话；当需要时，仍可从历史记录中重新打开它们。

## 示例：实现，然后审查

1. 开始一个名为“实现设置持久化”的聊天，并要求它修复设置表单。
2. 启用多聊天并创建一个名为“审查设置持久化”的第二个聊天。
3. 如果你想要获得另一个启用模型的评估，请在审查聊天中选择其他模型。
4. 一旦实现准备就绪，请求审查聊天框检查当前更改并报告问题，而无需编辑文件。
5. 在询问实现聊天机器人解决其发现的问题时，保持审查内容可见。
6. 当需要更多空间时，关闭审查列。从历史记录中重新打开它以重新查看发现内容。

第二个聊天不会自动接收第一个聊天的消息。请为其提供任务上下文，并[引用相关文件](/docs/zh-Hans/providing-context)，或者在需要复制早期消息时使用[聊天分支](/docs/zh-Hans/branching-chats)。

## 了解什么是共享

同一个项目中的所有聊天都针对同一个项目文件夹工作。文件编辑和 Git 分支更改对其他聊天可见，即使它们的对话历史是分开的。

<Warning>
  两个代理同时编辑同一文件可能会相互干扰。当任务需要独立检出时，请使用单独的 [Git 工作树](/docs/zh-Hans/worktrees)。仅启用多聊天功能并不能隔离文件变更。
</Warning>

对于已完成的对话，使用 [归档](/docs/zh-Hans/archived-chats) 来保持对话历史的简洁。
