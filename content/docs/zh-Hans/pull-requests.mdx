右侧面板的“拉取请求”按钮会打开当前分支的 GitHub 拉取请求。首先安装并认证仓库的 GitHub CLI。要创建新的拉取请求，请参考 [Git 工作流程](/docs/zh-Hans/git-workflows#创建拉取请求)。

## 打开当前分支的 PR

1. 选择项目并检查其当前分支。
2. 在右侧面板中单击 **拉取请求**。
3. 审查 PR 的标题、状态、源分支和基础分支，以及检查结果。
4. 使用 **摘要** 进行描述和讨论，或使用 **代码** 表示更改的文件。

如果分支没有合并请求，面板将提供 **创建拉取请求**。在 GitHub 上进行更改后，使用 **拉取请求操作 → 刷新**，或选择 **在 GitHub 上打开** 以在浏览器中查看该拉取请求。一旦分支包含该拉取请求头之后的新提交，合并的拉取请求将不再显示。

## 审查代码并发布评论

在 **摘要** 中阅读讨论内容，并使用 **写入** 和 **预览** 功能撰写一篇 Markdown 评论。选择 **发表评论** 将其发布到 GitHub。

在 **Code** 中，展开文件并选择其差异中的行以发表行内评论。你可以阅读现有的审查线程，并使用 **回复** 继续讨论。当文本补丁不可用时，打开 GitHub 上的拉取请求以检查该文件。

这些评论会发布到 GitHub。要询问你的编码代理关于本地更改的情况，请使用 [在更改中进行差异反馈](/docs/zh-Hans/feedback#在差异中注释行)。

## 编辑标题和描述

当您的账户有权限时，使用 **编辑标题** 或 **编辑描述**。编辑标题后保存标题；对于描述，使用 **写入** 和 **预览**，然后 **保存**。您还可以在编辑控件可用的情况下编辑自己的评论。

## 合并一个拉取请求

1. 审查代码、讨论和检查。
2. 点击面板标题栏的“合并”按钮。
3. 在 **合并 PR** 中确认源分支和基础分支。
4. 选择一种可用的方法：**创建合并提交**，**压缩提交并合并**，或**变基并合并**。
5. 提交合并。

只有开放的、非草稿的拉取请求才能被合并。请先在 GitHub 上将草稿标记为“已准备就绪”。你的账户需要合并权限，且仓库会决定哪些合并方式可用。当仓库要求未满足时，GitHub 可以拒绝合并。

Dream 检查 PR 是否仍显示加载合并详情时的头提交。如果该提交在 GitHub 上已更改，请刷新并审查新的变更后再重试。
