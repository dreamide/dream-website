title: "使用聊天"

一个聊天承载与编码代理的一次对话。聊天通常属于某个项目，并拥有自己的模型、权限和对话历史。对于想要分别回头处理的任务（例如修复一个错误和审查一个功能），请使用不同的聊天。

如果想在不打开文件夹的情况下提问，可以开始一个 [无项目的聊天](/docs/zh-Hans/standalone-chats)。

## 开始对话

1. 选择你想要工作的项目选项卡。
2. 在左侧工具栏点击 **新聊天**。
3. 检查消息框下方的模型和权限。
4. 描述任务并提交您的消息。

新聊天会使用您的[默认模型设置](/docs/zh-Hans/models)。当您再次点击**新聊天**时，空草稿可以被重新使用。一旦您发送消息，该对话将出现在项目的聊天记录中。

为了一个有用的第一条消息，给代理一个结果和一种检查它的方法。例如：

> 找出刷新页面后设置表单丢失数值的原因。修复问题，并说明你如何验证修复结果。

使用 [文件引用和附件](/docs/zh-Hans/providing-context) 指向相关的代码或图像。

## 返回到对话中

1. 在左侧工具栏点击 **聊天记录**。
2. 浏览当前项目的聊天记录，最近更新的对话排在前面。
3. 在 **搜索历史** 中输入聊天标题的一部分以缩小列表。
4. 选择对话以打开它。

历史搜索会筛选当前项目的标题。要跨项目搜索标题和消息文本，请点击顶部栏的 **搜索聊天**（默认快捷键在 macOS 上为 **Command+Shift+F**，在 Windows/Linux 上为 **Ctrl+Shift+F**）。搜索结果包含本地项目、已连接的远程主机以及 [无项目的聊天](/docs/zh-Hans/standalone-chats)。选择已归档的结果会将其恢复；选择已关闭项目的聊天会重新打开该项目。

如果无法搜索主机，请重新连接它并再次尝试。当搜索结果被截断时，可以缩小查询范围。您还可以在 [已归档聊天](/docs/zh-Hans/archived-chats) 中管理旧的对话。

当启用 [多聊天](/docs/zh-Hans/multiple-chats) 时，选择一个对话可以将其置于并排布局中。当禁用多聊天时，每次只查看一个对话。

## 重命名一个聊天记录

Dream 在对话开始后可以生成一个标题。为了赋予其更具体的名称，请打开聊天的 **…** 菜单，选择 **编辑**，或双击标题。在 **编辑聊天** 中输入名称并点击 **保存**。使用 **取消** 以保留现有名称。

“修复设置持久化”和“审查设置测试”这类名称比多个同项目命名的聊天更容易区分。

## 跟踪正在进行的工作

启用 **桌面通知**（位于 **设置 → 通用 → 聊天消息**），即可在 Dream 位于后台时，收到聊天完成、失败或需要你输入的提醒。点击通知可打开对应聊天。**通知提示音** 是单独的选项，即使 Dream 处于焦点状态也可以播放。

对于此窗口未在跟踪、但仍在主机上运行的轮次，同样会发送通知。你自己停止的轮次不会发送通知。

正在流式接收回复的聊天会显示加载指示器。发送消息后，Dream 会滚动到该消息，使其出现在可见区域。

当代理响应时，聊天界面会显示其进度和工具活动。点击开放工具详情以检查命令、文件读取或更改。当代理提供任务列表时，消息框旁边的任务控制会显示其进度。

聊天记录和项目标签页会显示每个聊天的状态：正在回复时显示加载指示器，代理在等待你时显示琥珀色圆点，已完成而你尚未打开时显示绿色圆点。选择项目并打开对话即可阅读最新消息。使用聊天输入框中的停止控件可中断回复。停止回复不会撤销已经做出的文件更改。

轮次在项目所属的主机上运行，而不是在窗口中运行。如果窗口与主机的连接断开，轮次会继续运行，Dream 会自动重新连接。退出 Dream 会停止由应用启动的主机及其上的轮次；如果希望关闭应用后代理继续工作，请 [自行运行主机](/docs/zh-Hans/dream-host)。

回复完成后，使用其底部的“查看此回复的文件变更”来查看它修改了哪些文件，并[恢复其中任意一个](/docs/zh-Hans/checkpoints)。

## 将消息加入队列

不必等回复完成再发送下一条指令。代理工作时，直接输入消息并发送即可。Dream 会将其加入该聊天的队列，并在当前轮次结束后运行。轮次运行期间，消息框为空时，聊天输入框的按钮用于停止该轮次；输入内容后，该按钮用于发送消息。

当有消息在等待，或某次运行需要你处理时，消息框上方会出现 **队列** 列表。每一行显示消息、所用模型和状态。

| 状态 | 含义 |
| --- | --- |
| 排队中 | 等待排在前面的轮次完成 |
| 运行中 | 代理当前正在处理的轮次 |
| 等待中 | 运行中的轮次正在等待你的回答或批准 |
| 已中断 | 在完成前被停止，例如因使用了停止控件或主机重启 |
| 失败 | 因错误而结束 |

对排队中的消息使用 **取消**，可将其移出队列。失败或中断的运行会提供 **重试** 和 **移除**。重试之前，请先阅读被中断的运行留下的回复，因为其中部分工作可能已经完成。

**暂停队列** 会保留排队中的消息，并让当前轮次运行完成。**继续队列** 会重新开始运行这些消息。停止控件则不同：它会结束正在运行的轮次及其 [委派](/docs/zh-Hans/delegation) 的所有任务，并暂停队列。

失败或中断的运行也会暂停队列，此时队列标题显示 **队列已暂停**。发送新消息会继续队列，并清除这些运行。

队列保存在项目所属的主机上，重启 Dream 后依然保留。主机重启后，之前正在运行的轮次会被标记为已中断，队列保持暂停，直到你将其继续。如果排队中的消息无法发送，其文本会回到消息框中。

## 关闭、归档还是删除？

| 操作 | 结果 | 如何返回 |
| --- | --- | --- |
| 关闭一个聊天列 | 从多聊天布局中移除它 | 从聊天记录中打开它 |
| 归档聊天记录 | 从当前聊天记录中移除它 | 在设置 → 已归档聊天中恢复它 |
| 删除一个归档的聊天记录 | 永久从 Dream 中删除聊天及其消息 | 它无法通过 Dream 恢复 |

关闭一列在你需要更多空间时很有用。归档在任务完成时很有用。这两种操作都不会撤销代理对项目文件的更改。

要尝试不同的方法同时保留之前的对话内容，[从消息分支](/docs/zh-Hans/branching-chats)。为了为后续任务做准备，[将提示保存到暂存](/docs/zh-Hans/stash)。对于需要在多个项目中重复使用的指令，创建一个[可复用的提示](/docs/zh-Hans/saved-prompts)，然后从编排器的 **+ → 运行提示** 菜单中执行。输入 **$** 来调用一个[代理技能](/docs/zh-Hans/skills)。
