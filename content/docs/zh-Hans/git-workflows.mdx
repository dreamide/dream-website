在右侧工具栏中打开 **Git**，以查看 **更改**、**历史** 和 **拉取请求** 选项卡。聊天界面下方的 **Git 操作** 菜单提供了当前分支的下一步操作。

**Git 操作**按钮位于底部列右侧，有变更可提交或有提交可推送时会醒目显示。**Git** 只会在位于 Git 仓库内的项目中显示。

## 开始之前

对于提交操作，您的仓库需要配置 Git 作者身份。对于推送操作，它需要一个远程仓库以及可以访问该远程仓库的凭据。拉取请求的创建使用 GitHub CLI，该工具必须安装并为目标仓库进行认证。

你可以手动输入提交信息和拉取请求文本。要生成这些内容，请启用一个提供商模型，并选择 **设置 → 通用 → 模型 → 文本生成模型**。

## 审查更改

1. 打开 **Git → 更改** 以检查已修改、已添加和已删除的文件。
2. 展开文件以审查其差异。
3. 在标题列中选择**统一差异**或**分栏差异**。**自动换行**默认为开启，其切换开关也在该处，位于**全部展开**和**全部折叠**旁边。
4. 在文件的差异标题中按一下其路径，即可在**文件**中开启该文件。

清单会在文件变更时、终端指令执行完毕后，以及你回到 Dream 视窗时更新。

对于非常大的差异，Dream 可能会显示 **差异太大而无法渲染**。仅在您希望加载该更大的视图，或在编辑器或终端中检查文件时，才使用 **无论如何渲染**。

使用文件的 **还原文件更改** 操作放弃不需要的工作区更改。**更改操作 → 还原所有更改** 的作用范围更广；确认前请检查其范围。还原代码与归档生成该代码的聊天是两件独立的事。若只想撤销某个回复所做的更改，请使用该回复的[检查点](/docs/zh-Hans/checkpoints)。

要向代理询问特定行的内容，请在差异中拖动行号或点击行的 **+** 控制按钮，然后输入评论。Dream 会将该评论连同文件路径和选中的行一起发送。详见 [向聊天发送反馈](/docs/zh-Hans/feedback)。

1. 打开 **Git → 更改**，或从底部 **提交** 菜单中选择 **Git 操作**。
2. 在提交 composer 之下审查文件差异。
3. 检查 **包括未暂存的**。它默认已启用，并会将未暂存的更改包含在提交中。
4. 检查默认开启的 **自动生成消息**。如需自己编写消息，请将其关闭，并在 **提交消息** 中输入；关闭时会清除已生成的消息。
5. 选择 **提交**，或选择 **提交并推送** 如果你准备将提交发布到远程。

开启**自动生成消息**后，Dream 会在项目中最后一个执行中的代理回合结束时，于背景草拟提交消息，因此你开启面板时通常已经准备好。在 macOS 上按 **Command+Enter**，或在 Windows/Linux 上按 **Ctrl+Enter** 即可提交；加按 **Shift** 则会提交并推送。

仅提交选定的子集时，请在终端或外部编辑器中使用 Git 对这些文件进行暂存，并将 **包括未暂存的** 关闭。更改面板不提供单个文件的暂存控制。

Dream 在检测到活动项目文件夹外存在已暂存的更改时会拒绝提交。请单独提交这些更改，然后再继续此操作。

<Warning>
  在启用“包含未提交内容”时，一次提交可以包含多个共享此检出的聊天的工作。
</Warning>

在 **Git 操作**中，对没有上游的分支使用**发布分支**，对待推送的提交使用**推送**。两者都会开启**推送更改**预览，显示分支、目的地以及即将送出的提交。检查这些内容后，按一下**推送**。有上游时，**推送**和**拉取**选单项目会显示分支领先和落后的提交数量。

如果推送失败，请检查错误消息，并确认你对远端的存取权限。当远端有你尚未取得的提交时，Dream 会提示你先拉取再重新推送。即使后续的推送失败，已成功的本机提交仍会保留；重复执行组合动作前，请先检查分支状态。

## 撷取与拉取

**Git 操作 → 获取**会从远端下载新的提交，但不会变更你的文件。**拉取**还会将上游分支的提交并入你的分支。

拉取之后，会有通知回报收到了多少个提交。在通知中选择**查看更改**可开启**已拉取的更改**，其中列出这些提交及其变更的文件。

如果你的分支和其上游都有新的提交，Dream 会将上游的提交合并到你的分支，而不会进行变基。若该合并会产生冲突，Dream 会中止合并，让你的文件维持原状，并列出发生冲突的文件。请在终端中使用 Git 解决差异，然后再次拉取。

拉取会更改项目中每个聊天所使用的文件。请先让正在运行的回复完成，并提交或暂时搁置你的工作。**Git 操作 → 打开仓库** 会在浏览器中打开远程仓库。

## 创建拉取请求

1. 在名称与 PR 的基础分支不同的特征分支上工作。
2. 选择 **Git 操作 → 创建拉取请求**。
3. 审查源分支和基础分支以及提出的变更。
4. 输入标题和描述，或使用 **自动生成 PR 详细信息** 并审查生成的文本。
5. 在“下一步”中，选择与分支状态匹配的操作。
6. 如果该拉取请求尚未准备好审查，请开启 **草稿** 然后提交。

| 下一步 | 发生了什么 |
| --- | --- |
| 创建 PR | 为已推送的工作创建 PR |
| 推送并创建 PR | 在创建拉取请求之前推送提交 |
| 提交、推送并创建 PR | 提交工作更改，推送，并创建 PR |

对话框初始时 **草稿** 为关闭状态。启用它以创建草稿型 Pull Request。创建 Pull Request 需要一个分支，而不是一个脱离 HEAD 的状态，且源分支和基础分支不能相同。

如果一个组合操作失败，早期步骤可能已经完成。在重试之前，请检查提交、远程分支或拉取请求。

## 审查并合并一个拉取请求

打开 **Git → 拉取请求** 查看当前分支的拉取请求。使用 **摘要** 查看其描述、检查项和讨论内容，或使用 **代码** 检查差异并添加行内评论。在允许的情况下，可以编辑标题和描述，并使用 **合并** 选择合并方式。有关完整的工作流程，请参见 [审查拉取请求](/docs/zh-Hans/pull-requests)。

## 切换或创建分支

开启聊天下方的分支切换器，搜寻本机分支，并选取其中一个以将其检出。使用**建立并检出新分支…** 可命名并建立分支。清单会在每次开启时重新载入，因此会包含在 Dream 之外建立的分支。

切换分支会改变该项目中每个聊天使用的文件。在切换之前，请检查未完成的工作。对于具有独立检出的并行任务，请使用 [Git 工作树](/docs/zh-Hans/worktrees)。当一个工作树完成时，可以使用其页脚将其合并到主分支、创建拉取请求或移除该检出。参见 [完成一个工作树](/docs/zh-Hans/worktrees#完成一个工作树)。

### 删除本机分支

1. 开启分支切换器，将鼠标游标停留在该分支上，或用键盘移到该分支。
2. 按一下该列上的垃圾桶图示**删除分支**。
3. 阅读摘要。Dream 会回报该分支的提交是否已在基础分支中、其拉取请求的状态，以及是否有提交只存在于此分支上。
4. 按一下**删除分支**。如果会遗失提交，按钮会显示为**仍然删除**。

删除只会移除本机分支，其远端分支不受影响。你无法删除目前分支、基础分支，或在主检出中开启的分支。

如果该分支已在某个[工作树](/docs/zh-Hans/worktrees)中检出，对话框会改为提供**删除工作树和分支**。这也会删除该工作树的文件夹及其聊天。

打开 **Git → 历史**，或 **Git 操作 → 查看历史**，以跟随彩色图表中的提交和合并。使用 **搜索提交** 来按消息、作者、哈希前缀或引用过滤已加载的提交。**加载更多** 包含更早的提交；清除搜索将重新显示图表。

将鼠标悬停在某个提交上或使用键盘聚焦它以使用 **复制提交哈希**。
