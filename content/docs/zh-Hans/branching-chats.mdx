---
title: "分支对话"
description: "从同一工作区的早期消息或独立的 Git 工作树中继续。"
---

当您希望探索另一种方法时，可以分支一个聊天。Dream会将选定消息中的对话内容复制到一个新的聊天中，并保留原始对话。在该点之后的消息不会包含在新聊天中。

## 在同一个工作区继续

1. 打开源对话并等待其响应完成。
2. 查找您想要从中分支的消息。
3. 使用其 **从此消息继续…** 动作。
4. 在“分支聊天”下选择“此工作区”。
5. 在新对话中发送一条跟进消息，描述你想要尝试的替代方案。

新的聊天会继承源聊天的模型和权限设置。在多聊天模式下，它会位于源聊天旁边；在单聊天布局中，它会成为可见的对话。

例如，当代理解释了某个错误后，可以要求新的聊天记录对比一个较小的修复方案。两个对话都可以使用当前项目文件。

<Note>
  分支会复制对话历史。它不会将文件系统恢复到选定消息发送时的状态。工作区中的两个聊天仍然共享相同的文件。
</Note>

## 在新的工作树中继续

对于独立检出，使用 **从此消息继续… → 新工作树**。此选项需要 Git 仓库。Dream 创建一个工作树项目，并生成一个包含复制历史的新聊天。

此快捷方式以当前分支为基线，并从聊天标题生成分支名称。它不会提示您选择自定义的基引用。要自己选择基引用和分支名称，请[从分支切换器创建一个工作树](/docs/zh-Hans/worktrees#创建一个工作树)。

<Warning>
  一个新的工作树从已提交的 Git 历史记录开始。它不包含未提交的更改，也不会重现所选消息的确切文件状态。在进入工作树分支之前，请保存并提交新检出中需要的任何更改。
</Warning>

## 选择正确的分支类型

| 你想要…… | 使用 |
| --- | --- |
| 问一个关于当前代码的不同问题 | 此工作区 |
| 比较推理过程，同时保持之前的讨论 | 此工作区 |
| 让另一个代理编辑一个独立检出 | 新工作树 |
| 在不复制任何消息的情况下开始一个任务 | 新聊天 |

在处理响应时无法进行分支操作。如果工作树选项不可用，请检查项目是否位于 Git 仓库中。有关打开和移除生成项目的工作树，请参见[工作树](/docs/zh-Hans/worktrees)。
