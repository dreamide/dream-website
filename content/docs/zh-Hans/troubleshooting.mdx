title: "故障排查"
description: "解决缺失模型和聊天、终端和预览问题，以及常见的 Git 错误。"
---

从受影响的聊天或工具中查看错误。在更改设置之前，请确认所选的项目和提供商，特别是当多个聊天同时打开时。

## 未检测到提供商 CLI

1. 打开你的系统终端并验证提供商 CLI 是否启动。
2. 完成其登录或首次运行设置。
3. 在 Dream 中打开 **设置 → 提供商** 并刷新该提供商。
4. 如果你在 Dream 运行时安装了它，且检测仍然失败，请重启 Dream 以使其能够识别更改后的环境。

Dream 需要可执行文件能够被应用程序访问，而不仅限于交互式 shell 中的快捷方式或别名。请参见 [连接服务商](/docs/zh-Hans/providers)。

## 模型缺失或我无法开始聊天

检查 **设置 → 提供商**，并启用至少一个检测到的模型。仅有一个未启用模型的检测到的 CLI 并不足以开始聊天。在更改提供商的认证或模型配置后，请刷新。对于 OpenCode，必须在刷新前完成其认证或配置。

然后检查 **设置 → 通用 → 模型**。如果之前选择的默认模型不可用，请再次选择一个启用的模型。现有的聊天会话有自己的选择器；更改全局默认模型不会替换这些选择。

## 推理强度或速度控制缺失

这些控件取决于所选模型的功能。请选择一个提供你需要的选项的模型。切换聊天的模型会重置其努力程度和速度选择，因此切换后请检查两者。参见 [模型与默认设置](/docs/zh-Hans/models)。

## 我找不到聊天功能

1. 选择对话发生项目的项目。
2. 打开 **聊天记录** 并清空其搜索框。
3. 按聊天标题搜索，而不是搜索其消息中的词语。
4. 检查 **设置 → 已归档聊天**，如果聊天记录在那里，请恢复该聊天。
5. 如果项目已关闭，可通过启动屏幕上的“最近关闭”重新打开它。

关闭多聊天列不会归档对话。没有消息的空聊天不会出现在历史记录中。通过 Dream 无法恢复永久删除的聊天。

## 一个已恢复的聊天记录又被归档了

恢复聊天会保留其最后活动日期。如果再次运行 **立即归档**，且该日期早于截止时间，则可再次符合归档条件。在执行该操作前，请检查截止时间以及您希望保留的聊天记录。

## 分支功能不可用

在当前响应完成之前不要分支。**新工作树**也要求一个 Git 仓库。缺失或无效的基引用可能会阻止工作树的创建；请确认仓库中存在您想要使用的已提交分支或引用。

如果新工作树中缺少预期的编辑，请检查这些更改是否在原始项目中未提交。工作树不会复制这些更改。参见 [Git 工作树](/docs/zh-Hans/worktrees)。

## 一个回复没有“查看文件更改”控制功能

该控件在助手消息响应完成后出现，且仅当为该回复捕获了检查点时才会出现。请检查 **更改检查点** 中是否启用了 **设置 → 通用 → 聊天消息**，并确保 `git` 可执行文件对 Dream 可用。非常大的项目可能超出捕获时间限制，此时回复将不会捕获检查点。参见 [审查与恢复更改](/docs/zh-Hans/checkpoints)。

## 我无法发送差异或元素反馈

在目标聊天正在响应时，发送控件会被禁用，并显示 **聊天正忙**。等待其完成，或在弹出菜单中启用 **新聊天**。如果弹出菜单提示选择不再匹配差异，请刷新更改并重新选择行。参见 [向聊天发送反馈](/docs/zh-Hans/feedback)。

## 在终端中继续缺失

该功能仅适用于具有有效可恢复提供程序会话的 Claude 聊天，并在响应处理过程中被禁用。新聊天、其他提供程序，或在更改模型或速度后重置会话可能无法使用该功能。请参见 [终端](/docs/zh-Hans/terminals#在终端中继续一个-claude-聊天记录)。

## 终端无法打开

检查项目目录是否仍然存在。在 **设置 → 通用 → 终端** 中选择一个可用的 shell，然后打开一个新的会话。对于 Claude 继续功能，原始会话目录也必须存在。尝试在系统终端中使用相同的 shell 以识别环境问题。

## 浏览器预览为空或过时

确认应用程序正在运行，并使用其终端中显示的完整 URL 和端口。检查终端错误，然后尝试 **刷新浏览器** 或 **强制重新加载**。对比你系统浏览器中的 URL。使用 DevTools 检查页面错误；仅在相关身份验证或缓存问题时清除 Cookie 或缓存。参见 [浏览器预览](/docs/zh-Hans/browser)。

## 无法保存文件

检查文件是否可写，并查看编辑器的错误。如果文件在你编辑期间已更改，请在 **从磁盘重新加载** 之前保存你的草稿，然后重新应用预期的更改。参见 [文件与搜索](/docs/zh-Hans/files#处理编辑器外部更改的文件)。

## Git 操作失败

对于 PR 评论、编辑或合并的问题，请参见 [审查拉取请求](/docs/zh-Hans/pull-requests)。请检查 GitHub CLI 是否已认证，以及您的账户是否具有所需的仓库权限。一个草稿拉取请求在合并前必须标记为“已准备就绪”。

| 症状 | 要检查什么 |
| --- | --- |
| 一个文件夹没有 Git 工具 | 在 Git 仓库中打开一个文件夹 |
| 没有暂存的更改要提交 | 审查时包含未暂存的文件，或通过 Git 暂存目标文件 |
| 项目外的暂存更改 | 在使用 Dream 的提交操作之前，分别提交它们 |
| 推送没有目标地址 | 配置 Git 远程仓库并验证访问权限 |
| 创建 PR 会报告一个 CLI 错误 | 验证 GitHub CLI 是否已安装、已认证，并能访问仓库 |
| PR 源和基础分支相同 | 在创建 PR 之前切换到一个功能分支 |
| 创建 PR 时报告断开的 HEAD | 在创建 PR 之前检出一个分支 |
| 工作区移除失败 | 审查并保留该检出版本中的未提交更改 |
| 合并与移除功能不可用 | 工作树与其基线没有提交记录领先，或者主检出存在未提交的更改或正在进行的合并 |
| 完整工作树会报告冲突 | 合并被中止，没有任何更改；将基础分支合并到工作树中，解决冲突，提交，然后重新尝试 |
| 在完整工作树中创建拉取请求不可用 | 配置 Git 远程仓库并安装 GitHub CLI |

在组合操作失败后，重试前检查分支状态：一个提交或推送可能在后续步骤失败前已经成功。参见 [Git 工作流程](/docs/zh-Hans/git-workflows)。
