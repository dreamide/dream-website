Dream 与你计算机上已安装的编程代理命令行工具协同工作。

## 支持的提供商

| 提供商 | 必需的 CLI |
| --- | --- |
| OpenAI | Codex CLI |
| Anthropic | Claude Code CLI |
| OpenCode | OpenCode CLI |
| Cursor | Cursor Agent CLI |
| Grok 构建 | Grok 构建 CLI |
| Antigravity | Antigravity CLI |

从提供者处安装 CLI，然后在 Dream 之外完成该 CLI 的一般登入或验证流程。Antigravity 即 Google Antigravity；Dream 透过其 `agy` 指令执行它。

## 启用模型

1. 在 Dream 中打开设置。
2. 选择 **提供商**。
3. 安装或认证其 CLI 后，刷新提供者。
4. 开启提供者的启用开关，然后按一下每个你想使用的已侦测到模型。已选取的模型会以勾号标示。
5. 打开 **通用 → 模型**，为新的聊天和提交及拉取请求草稿设置默认值。

在打开第一个项目之前，必须启用至少一个模型。聊天在启动后可以使用不同于默认模型的启用模型。

## 使用多个提供商

启用您希望使用的每个提供商的模型。聊天编排器会列出已启用的模型，因此您可以为另一场对话选择不同的提供商，或在现有聊天中更改模型。

例如，你可以将你的实现聊天保留在一个提供商上，而使用另一个提供商创建审查聊天。你无需每次更改全局默认设置。请参考 [模型与默认设置](/docs/zh-Hans/models) 来配置新聊天的默认设置、推理强度、速度以及独立的 Git 撰写模型。

## 了解不同提供商之间的差异

已安装的 CLI 负责身份验证和执行代理工作。不同提供商之间的模型列表、支持的努力程度和速度选项、附件处理、使用信息以及权限行为可能有所不同。

Dream 为每个聊天提供了 **询问**、**接受编辑** 和 **完全访问** 三种权限。在选择之前，请阅读 [智能体权限](/docs/zh-Hans/agent-modes)。Claude 通过可恢复会话进行聊天时，也支持 [在终端中继续聊天](/docs/zh-Hans/terminals#在终端中继续一个-claude-聊天记录)。

[技能](/docs/zh-Hans/skills)适用于 Claude Code、Codex、OpenCode 和 Cursor。[MCP 服务器](/docs/zh-Hans/mcp-servers)和 Dream 的内建浏览器工具适用于 Claude Code、Codex、OpenCode 和 Grok Build；Cursor 和 Antigravity 不支援这些由 Dream 管理的工具连接。

同样这四个提供者的聊天，也可以[将任务委派](/docs/zh-Hans/delegation)给你已设置的任何其他提供者。

## 检查 CLI 更新

提供者卡片会在可取得时显示已安装的 CLI 版本。Dream 也会检查是否有较新的版本，并在找到时显示**有可用更新：…** 按钮。按一下该按钮即可执行该 CLI 自己的更新指令；完成后 Dream 会回报结果。如果更新失败，请使用该 CLI 的一般安装方式进行更新，然后在 Dream 中重新整理其提供者卡片。

使用提供商的启用开关将其模型从可用选择中隐藏，而无需卸载 CLI。在更改启用的提供商或模型后，请重新检查默认设置。

## 故障排查检测

如果一个提供商显示 **未检测到 CLI**：

1. 打开你的系统终端并验证 CLI 命令能否成功启动。
2. 完成 CLI 所请求的任何登录或首次运行设置。
3. 返回 **设置 → 提供商** 并刷新它。
4. 对于 OpenCode，如果未显示模型，请运行其身份验证流程或配置 `opencode.json` 文件。

如果在 Dream 启动时已安装了 CLI，如果刷新仍无法检测到它，请重新启动 Dream。该命令必须在 Dream 的环境中可用；仅一个 shell 别名并不等同于已安装的 CLI。

如果已侦测到 CLI，但缺少你想要的模型，请检查提供者的帐户与设置，并重新整理清单。如果模型已列出但无法在聊天中使用，请在提供者卡片中选取这些模型，并确认提供者本身已启用。其他检查项目请参阅[疑难排解](/docs/zh-Hans/troubleshooting)。
