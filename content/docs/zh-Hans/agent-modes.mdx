每个聊天在其消息框下方都有一个**权限**控制。新聊天继承**设置 → 通用 → 模型 → 默认权限**，默认值为**完全访问**。更改默认权限不会影响现有的聊天。

## 选择权限

1. 打开消息输入框下方的盾牌图标控件，其工具提示为**权限**。
2. 选择 **询问**、**接受编辑** 或 **完全访问**。
3. 检查任务内容并提交。

| 权限 | 预期行为 |
| --- | --- |
| 询问 | 请求批准在提供商配置中需要权限的操作 |
| 接受编辑 | 允许在保留其他操作审批处理的情况下自动进行文件编辑 |
| 完全访问 | 给予代理更广泛的行动权限，无需审批提示 |

具体的权限行为由所选提供商决定。**询问**并不表示每次读取或工具调用都会请求批准，**接受编辑**也不表示批准所有命令。

<Note>
  Dream 不再提供单独的 Build 和 Plan 控件。如果希望先制定计划，请让代理在进行更改前调查问题并提出方案。这条指令不会将文件系统访问限制为只读；还应为任务选择合适的权限。
</Note>

## 响应问题和审批

一个代理可能会要求你澄清需求、选择选项或批准某个操作。阅读对话中的请求，并使用提供的控件作出回应。一个项目标签可能表示代理正在等待你的回答。打开该项目，返回对话中阅读请求。

如果需要调整任务，请在该聊天中向代理提供修改后的指令。必要时使用停止控件中断响应。停止不会撤销已经完成的编辑或命令；之后请检查[更改](/docs/zh-Hans/git-workflows)，或使用该响应的[检查点](/docs/zh-Hans/checkpoints)恢复它修改的文件。

对于需要单独文件的并行任务，请使用 [worktrees](/docs/zh-Hans/worktrees)。权限设置不会为同一文件夹中的两个聊天提供独立的检出。

## 委派任务

代理可以将任务的一部分交给同一项目中的另一个代理提供商。例如，Claude Code 聊天可以请 Codex 审查某项更改，然后在之后的轮次中读取结果。只需在消息中提出要求，例如“让另一个代理为这个模块编写测试并汇报结果。”

| 规则 | 详情 |
| --- | --- |
| 可委派任务的提供商 | Codex、Claude Code、OpenCode 和 Grok Build。Cursor Agent 可以接收委派任务，但不能发起 |
| 可用的提供商 | 另一个提供商的 CLI 必须已在项目所在主机上安装并登录 |
| 权限 | 委派任务的权限不能超过发起它的聊天 |
| 文件 | 委派任务使用同一份项目文件；为每个任务分配不同部分的工作，以避免冲突 |
| 停止 | 停止聊天也会停止它委派的任务 |

委派任务在主机上运行并保留结果，因此代理可以在之后的轮次中或 Dream 重启后查看它们。打开回复中的工具详情，即可查看代理启动了哪些任务。
