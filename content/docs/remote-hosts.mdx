---
title: Remote hosts
description: Open projects on other machines over SSH or HTTPS, with agents, files, Git, and terminals running there.
---

Dream can open projects on other machines alongside your local projects. Files, Git commands, agent
processes, and terminals run on the project's host. The project tab and the footer beneath the chat
show which host you are working on.

Dream reaches a host in one of two ways:

| Route | Use it when | What you need |
| --- | --- | --- |
| SSH | You can already run `ssh` to the machine | An SSH target. Dream installs and runs its host there |
| HTTPS | The machine runs Dream or `dream-host` with [remote access](/docs/remote-access) turned on | The host's address and a pairing code |

A host can have routes of both kinds. See [Routes](/docs/remote-hosts#routes).

## Add an SSH host

1. Verify that `ssh devbox` works in your system terminal, replacing `devbox` with your SSH config
   alias or `user@host`. Dream uses your system SSH client, configuration, and keys.
2. Open **Settings → Connections**. Under **Remote hosts**, choose **Add host**, then **SSH host**.
3. Enter the **SSH target**. Dream suggests aliases from your SSH config. The name is optional and
   defaults to the target.
4. Click **Save**. Dream connects to the host right away.
5. Answer any host-key, password, passphrase, or two-factor prompts in Dream. Declining or canceling
   a prompt stops that connection attempt.

When it connects, Dream installs the host that matches your app version under
`~/.dream/host/versions/` on that machine and starts it. Nothing needs to be installed there first.
If the machine cannot download the host, Dream downloads it locally and uploads it over SSH. Install
and sign in to the agent CLIs on the remote machine too; they run in that machine's environment.

Over SSH, Dream supports Linux x64, Linux ARM64, and macOS Apple silicon (ARM64) machines. Linux
machines need glibc 2.31 or newer. The desktop app you connect from can run on Windows, macOS, or
Linux.

## Pair with a host over HTTPS

Use a pairing code when SSH is unavailable or inconvenient, for example to reach your office
computer from a laptop through Tailscale or a Cloudflare tunnel.

1. On the other computer, turn on [remote access](/docs/remote-access) and create a code with
   **Pair a device**, or run `dream-host pair`.
2. On this computer, open **Settings → Connections** and choose **Add host**, then **Pairing code**.
3. Enter the **Host address** and the **Pairing code**. The name is optional.
4. Click **Pair host**.

A code works once and expires ten minutes after it is created. This computer must trust the host's
HTTPS certificate. No Dream account is involved; this computer stays paired until it is revoked on
the host.

## Routes

Each host has one entry under **Remote hosts**, however many ways you can reach it. Click **Edit**
on a host to open its routes, then use **Add SSH route** or **Add HTTPS route** to add another way in.
You can rename the host in the same dialog.

Routes are tried from top to bottom until one connects. Use **Move up** and **Move down** to set the
order, and **Remove route** to delete one; a host always keeps at least one route. When the preferred
route is unavailable, Dream switches to the next one.

Previewing a site that runs on the host in Dream's [browser](/docs/browser), and opening the project
in an external editor with **Open in**, both need an SSH route. A host reached only over HTTPS still
provides its projects, chats, files, Git, and terminals.

## Open a remote project

1. Click the **+** beside the project tabs, then **Open Folder**.
2. In the **Open folder** dialog, choose the host under **Open on**. Dream connects to it if needed.
3. Enter the **Folder path**. Dream lists the matching folders on that host as you type; press
   **Tab** to complete the highlighted one.
4. Click **Open**. The remote folder opens as a project tab with its own chats and tools.

If you have not added a host yet, use **Add SSH host…** at the bottom of the dialog.

Closed remote projects appear in **Recently closed** with their host and path. Reopening one
connects to that host. Remote paths belong to the remote machine; use an editor connected there
when opening files outside Dream.

## Reconnect or remove a host

Each host shows its connection status in **Settings → Connections**. Dream retries interrupted
connections. Project tabs remain visible while a host is unavailable, and sending a message is
disabled until it reconnects. If reconnection stops, read the displayed error and use **Reconnect**
in the chat, or **Connect** in **Settings → Connections**.

Agent turns run on the host, so a turn that is already running continues while this computer is
disconnected. Dream picks the turn up again when it reconnects.

**Disconnect** leaves a host's project tabs in place. **Remove** asks for confirmation, then removes
the host and its projects from this Dream workspace and stops their terminals. Files and chats on
the host are not touched.

## Connection problems

Check the same SSH target in your system terminal first. Correct authentication or host-key
problems before reconnecting. If the host cannot start, read the error in
**Settings → Connections** and check that the machine's platform is supported.

When an HTTPS host refuses the connection, the error says whether the host runs an incompatible
version or this computer is not authorized. Update Dream on both computers to the same version, or
create a new pairing code on the host and pair again.

Development builds have no published host to download. From the Dream app repository, run
`pnpm host:install-dev devbox`, then connect again. The remote build requires Node.js 22 or newer,
pnpm or Corepack, make, Python 3, and a C++ toolchain (g++ 10 or newer). The installer stops the
existing development host daemon before replacing its runtime.
