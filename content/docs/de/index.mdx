Dream bringt Ihre Projekte, AI-Coding-Agenten, Dateien, Terminals, Browser-Vorabilder und Git-Arbeitsschritte in eine einzige Desktop-Arbeitsfläche. Verbinden Sie einen unterstützten Agent-CLI, öffnen Sie einen Ordner und arbeiten Sie mit einem oder mehreren Chats, ohne zwischen Tools wechseln zu müssen.

## Was Dream enthält

- Ein mehrprojekt-Workspace mit persistierenden Projekt-Optionen
- [Remote-Arbeitsbereiche über SSH](/docs/de/remote-hosts) mit entfernten Agenten, Dateien, Git und Terminals
- Mehrere Seitlich nebeneinander liegende Chats und chat-Verzweigungen
- Wiederverwendbare Prompts über Projekte hinweg und providerbewusste Agent-Fähigkeiten
- Per-Reply-Checkpoints zum Überprüfen und Wiederherstellen der Dateien, die ein Agent geändert hat
- Unterstützung für Codex CLI, Claude Code CLI, OpenCode CLI, Cursor Agent CLI und Grok Build CLI
- Ein Datei-Explorer, Dateisuche und -bearbeitung, integrierte Terminals und Browser-Vorschau
- Git-Status, Branch, Diff, Commit, Push, Pull Request und Worktree-Arbeiten, einschließlich des Fusions eines abgeschlossenen Worktree in seinen Basis-Branch
- Zeilenbezogene Differenz-Feedback und Auswahl von Browser-Elementen, die gezielte Nachrichten an ein Chat-System senden
- Ein GitHub-Pull-Request-Panel zum Überprüfen von Code, Kommentare posten, Details bearbeiten und Zusammenführen
- Konfigurierbare MCP-Server und integrierte Agent-Tools für die Interaktion mit dem Browser

<Note>
  Dream führt Coding-Agents über ihre installierten CLIs aus. Sie benötigen mindestens einen unterstützten CLI, bevor Sie ein Chat-Verfahren beginnen können.
</Note>

## Verstehe den Arbeitsbereich

Ein **Projekt** ist ein Ordner auf deinem Rechner oder einem SSH-Host mit eigenen Chats und Werkzeugen. Ein **Chat** ist eine Unterhaltung mit eigenem Modell und eigenen Einstellungen. Mehrere Chats eines Projekts teilen dessen Dateien; ein **Arbeitsbaum** bietet einer Aufgabe eine separate Git-Arbeitskopie.

Verwenden Sie [Agentenberechtigungen](/docs/de/agent-modes), um zu wählen, wie ein Agent funktioniert, und [Kontext und Nutzung](/docs/de/context-and-usage), um die Informationen unter dem Composer zu verstehen. Die [Einstellungsreferenz](/docs/de/settings) enthält die allgemeinen Einstellungen der Anwendung. Wenn etwas fehlt oder nicht funktioniert, beginnen Sie mit [Fehlerbehebung](/docs/de/troubleshooting).
