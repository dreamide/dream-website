Dream works with coding-agent command-line tools already installed on your computer.

## Supported providers

| Provider | Required CLI |
| --- | --- |
| OpenAI | Codex CLI |
| Anthropic | Claude Code CLI |
| OpenCode | OpenCode CLI |
| Cursor | Cursor Agent CLI |
| Grok Build | Grok Build CLI |

Install the CLI from its provider, then complete that CLI's normal sign-in or authentication flow
outside Dream.

## Enable models

1. Open **Settings** in Dream.
2. Select **Providers**.
3. Refresh the provider after installing or authenticating its CLI.
4. Turn on the provider's enable switch, then enable one or more of its detected models.
5. Open **General → Models** and choose defaults for new chats and for commit and
   pull-request drafting.

You must enable at least one model before opening your first project. A chat can use a different
enabled model from the default after it starts.

## Use more than one provider

Enable models from each provider you want to use. The chat composer lists enabled models, so you
can choose a different provider for another conversation or change the model in an existing chat.

For example, keep your implementation chat on one provider and create a review chat using another.
You do not need to change your global default each time. Follow [Models and defaults](/docs/models)
to configure new-chat defaults, reasoning effort, speed, and the separate Git drafting model.

## Understand provider differences

The installed CLI handles authentication and executes agent work. Model lists, supported effort
and speed options, attachment handling, usage information, and permission behavior can differ
between providers.

Dream exposes **Ask**, **Accept edits**, and **Full access** permissions per chat.
Read [Agent permissions](/docs/agent-modes) before choosing them. Claude chats with a
resumable session also offer [Continue in terminal](/docs/terminals#continue-a-claude-chat-in-a-terminal).

[Skills](/docs/skills) are available for Claude Code, Codex, OpenCode, and Cursor.
[MCP servers](/docs/mcp-servers) and Dream's built-in browser tools are available for Claude Code,
Codex, OpenCode, and Grok Build; Cursor does not support these Dream-managed tool connections.

## Check for CLI updates

Provider cards show the installed CLI version when available. Dream also checks for newer versions
and shows an **Update available: …** badge when one is found. The badge reports availability; it
does not install the update. Update using that CLI's normal installation method, then refresh its
provider card in Dream.

Use the provider's enable switch to hide its models from the available selections without
uninstalling the CLI. Recheck your defaults after changing enabled providers or models.

## Troubleshooting detection

If a provider says **CLI not detected**:

1. Open your system terminal and verify that the CLI command starts successfully.
2. Finish any sign-in or first-run setup requested by the CLI.
3. Return to **Settings → Providers** and refresh it.
4. For OpenCode, run its authentication flow or configure `opencode.json` if no models appear.

If the CLI was installed while Dream was open, restart Dream if refresh still cannot detect it.
The command must be available to Dream's environment; a shell alias alone is not an installed CLI.

If a CLI is detected but your desired model is missing, check the provider's account/configuration
and refresh the list. If models are listed but unavailable in chats, enable them with their
toggles and confirm the provider itself is enabled. See [Troubleshooting](/docs/troubleshooting)
for additional checks.
