右側のツールバーで **Git** を開くと、**変更**、**履歴**、**プルリクエスト**の各タブが表示されます。チャットの下にある **Git の操作** メニューには、現在のブランチで次に行う操作が表示されます。コミットする変更やプッシュするコミットがあるときは、このボタンが強調表示されます。

## 開始する前に

コミットの場合は、リポジトリに Git の作者識別情報が設定されている必要があります。プッシュの場合は、リモートとそのリモートにアクセスできる認証情報が必要です。プルリクエストの作成は GitHub CLI を使用しますが、そのリポジトリの宛先にインストールされ、認証されている必要があります。

コミットメッセージや PR のテキストは自分で入力できます。生成するには、プロバイダーのモデルを有効にして**設定 → 一般 → モデル → テキスト生成モデル**を選択します。**メッセージを自動生成**がオンの場合、プロジェクトで最後に実行中だったエージェントの応答が完了すると、Dream が新しいコミットメッセージの下書きを作成します。

## 変更を確認する

1. **Git → 変更**を開くことで、変更された、追加された、削除されたファイルを確認できます。
2. ファイルを展開してその差分を確認します。
3. ヘッダーで**統一 diff**または**分割 diff**を選択します。**折り返し**はデフォルトでオンです。長い行を折り返さずに表示するには、ヘッダーのトグルを使用します。

変更とファイルツリーは、ターミナルコマンドの終了後や Dream ウィンドウに戻ったときに更新されるため、Dream の外で行った作業も手動で更新せずに表示されます。

非常に大きな差分の場合、Dream は **差分が大きすぎてレンダリングできません** と表示します。**とにかくレンダリングする** を使用する場合のみ、その大きなビューをロードしたり、編集器またはターミナルでファイルを確認したい場合です。

不要な作業中の変更を破棄するには、ファイルの**ファイルの変更を元に戻す**アクションを使用します。**変更操作 → すべての変更を元に戻す**はより広い範囲に適用されるため、確定する前に範囲を確認してください。コードを元に戻すことは、そのコードを生成したチャットのアーカイブとは別の操作です。特定の応答による変更だけを元に戻すには、その応答の[チェックポイント](/docs/ja/checkpoints)を使用します。

特定の行についてアグェントに質問するには、diff内の行番号をドラッグするか、行の**+**コントロールをクリックしてコメントを入力します。Dreamはファイルパスと選択された行とともにそれを送信します。[チャットへのフィードバックの送信](/docs/ja/feedback)を参照してください。

## 作業をコミットしてください

    loading="lazy"

</Frame>

1. **Git → 変更**を開く、またはフッターの**コミット**メニューから**Git の操作**を選択する。
2. コミットコンポーザーの下にあるファイルの差分を確認します。コンポーザーには、コミットに含まれるファイル数が表示されます。
3. **ステージングされていないものを含む**を確認してください。これはデフォルトで有効になっており、コミットにステージングされていない変更を含みます。
4. デフォルトでオンになっている**メッセージを自動生成**を確認します。自分でメッセージを書くには、これをオフにして**コミットメッセージ**に入力します。オフにすると、生成されたメッセージは消去されます。
5. **コミット**を選択するか、リモートにコミットを公開する準備ができている場合は **コミットとプッシュ** を選択する。

選択されたサブセットだけをコミットするには、ターミナルまたは外部エディタでGitを使用してそのファイルをステージングし、**ステージングされていないものを含む**をオフにします。変更パネルは個々のステージングコントロールを提供しません。

Dreamは、アクティブなプロジェクトフォルダの外にステージド変更がある場合、コミットを拒否します。その変更を別途コミットしてください。その後、この操作を続けます。

<Warning>
  Include unstaged を有効にすると、複数のチャットがこのチェックアウトを共有している場合、1つのコミットには複数のチャットからの作業が含まれる。
</Warning>

## ブランチをプッシュする

<Frame caption="Gitのワークフロー">
  <img
    src="/images/docs/git-actions-menu.png"
    alt="チャット下部の現在のブランチの上に開いた Git 操作メニュー。"
    width={226}
    height={259}
    loading="lazy"
  />
</Frame>

1. チャットの下にある**Git の操作**を開きます。**プッシュ**には、アップストリームより先行しているコミット数が表示されます。アップストリームのないブランチでは、代わりに**ブランチを公開**が表示されます。
2. **変更をプッシュする**で、**ブランチ**、**送信先**、プッシュされるコミットを確認します。ブランチが何コミット先行し、何コミット遅れているかも確認してください。
3. **プッシュ**を選択します。

プッシュに失敗した場合は、エラーを確認し、Git リモートへのアクセス権があることを確認してください。後続のプッシュが失敗しても、成功したローカルコミットはコミットされたままです。組み合わせた操作を繰り返す前に、ブランチの状態を確認してください。

## フェッチとプル

ファイルを変更せずにリモートから新しいコミットとブランチをダウンロードするには、**Git の操作 → フェッチ**を使用します。アップストリームブランチのコミットを現在のブランチに取り込むには、**Git の操作 → プル**を使用します。メニューには遅れているコミット数が表示されます。Dream は、プルしたコミット数、またはブランチがすでに最新であることを報告します。

プルすると、プロジェクト内のすべてのチャットが使用するファイルが変更されます。先に実行中の応答を完了させ、作業をコミットするか退避してください。**Git の操作 → リポジトリを開く**を選ぶと、リモートリポジトリがブラウザで開きます。

## プルリクエストを作成

1. 機能ブランチを構築するが、その名前はPRのベースブランチと異なるものにする。
2. フッターの **PR の作成**、または **Git の操作 → プル リクエストを作成する** を選びます。
3. ソースブランチとベースブランチ、および提案された変更を確認する。
4. タイトルと説明を入力するか、**PR 詳細を自動生成**し、生成されたテキストを確認する。
5. **次のステップ**で、ブランチの状態に一致するアクションを選択します。
6. PRのレビューに準備が整っていない場合、**ドラフト**をオンにします。その後、提出します。

| 次へ | 何が起こるのか |
| --- | --- |
| PRを作成する | 既にプッシュされたワークをPRとして作成する |
| プッシュ＆PRを作成 | PRを作成する前にコミットをプッシュする |
| コミット、プッシュおよびPRを作成 | 作業変更をコミットし、プッシュし、PRを作成する |

ダイアログは初期に **ドラフト** がオフです。それを有効にすることでドロップPRを作成できます。PRの作成にはブランチが必要であり、デタッチされたHEADではなく、ソースとベースが同じブランチであることはできません。

組み合わせたアクションが失敗した場合、前のステップはすでに完了している可能性があります。コミット、リモートブランチ、またはPRを確認の上、再実行してください。

## プルリクエストのレビューとマージ

Git → プルリクエストを開いて現在のブランチのPRを確認します。その説明、チェック、ディスカッションは**概要**で確認し、差分を確認したりインラインコメントを投稿したりするには**コード**を使用します。タイトルや説明を編集できる場合、その内容を編集し、**マージ**を使用してマージ方法を選択できます。完全なワークフローについては[プルリクエストのレビュー](/docs/ja/pull-requests)を参照してください。

## ブランチを切り替えたり作成したり

チャットの下にあるブランチスイッチャーを開き、ローカルブランチを検索し、1つを選択してチェックアウトします。**新しいブランチを作成およびチェックアウト…** を使ってブランチを名前を付けて作成します。Dreamの外で作成されたブランチが欠落している場合は、リストを更新します。

<Frame caption="チェックマークは現在のブランチを識別しています。別のブランチを検索するか、同じメニューから新しいブランチを作成できます。">
  <img

ブランチを変更すると、そのプロジェクト内のすべてのチャットが使用するファイルが変更されます。未完了の作業を確認した上でブランチを切り替えます。独立したチェックアウトを持つ並列タスクでは、[Git worktrees](/docs/ja/worktrees)を使用します。ワークツリーが完了したら、そのフッターを使ってベースブランチにマージ、プルリクエストを作成、またはチェックアウトを削除します。[ワークツリーを完了させる](/docs/ja/worktrees#ワークツリーを完了する)を参照してください。

## コミット履歴を閲覧する

<Frame caption="コミット履歴を閲覧する">
  <img
    src="/images/docs/git-history-panel.png"
    alt="コミット検索、ブランチ名、コミットとマージの色付きグラフがある Git の履歴タブ。"
    width={933}
    height={1016}
    loading="lazy"
  />
</Frame>

**Git → 履歴**、または **Git の操作 → 履歴を表示** を開くと、色付きのグラフでコミットやマージを確認できます。**コミットを検索** では、読み込み済みのコミットをメッセージ、作成者、ハッシュの先頭部分、参照名で絞り込めます。**さらに読み込む** で古いコミットを追加できます。検索をクリアするとグラフが再び表示されます。

コミットにマウスを合わせたりキーボードでフォーカスを与えることで **コミットハッシュをコピー** できます。
