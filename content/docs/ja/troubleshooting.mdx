影響を受けたチャットまたはツールで表示されているエラーから始めましょう。設定を変更する前に、どのプロジェクトおよびプロバイダーが選択されているかを確認してください。特に複数のチャットが開いている場合。

リモートプロジェクトでは、**設定 → SSH ホスト**でホストの接続状態を確認します。認証、ランタイム、開発ビルドの設定については [SSH 接続の問題](/docs/ja/remote-hosts#接続の問題)を参照してください。

## Provider CLI が検出されませんでした

1. システムのターミナルを開き、プロバイダーCLIが開始されるか確認してください。
2. サインインまたは最初の実行設定を完了します。
3. Dream で設定 → プロバイダーを開き、そのプロバイダーをリフレッシュする。
4. Dreamが開いている状態でインストールした場合でも検出が失敗する場合は、環境の変更を反映するためにDreamを再起動してください。

Dreamは、アプリ内で実行可能ファイルが利用可能であることを必要とする。インタラクティブなシェルにおけるショートカットまたはエイリアスだけではなく、そのようにする必要がある。[プロバイダーの接続](/docs/ja/providers)を参照してください。

## モデルが存在しないか、チャットを開始できません

**設定 → プロバイダー**を確認し、検出されたモデルのうち少なくとも1つを有効にします。検出されたCLIに有効モデルが設定されていない場合、チャットを開始することはできません。プロバイダーの認証またはモデル設定を変更した後は、更新を行ってください。OpenCodeについては、更新を行う前に認証または設定を完了してください。

その後、**設定 → 一般 → モデル**を確認してください。以前に選択されたデフォルトモデルが利用できない場合は、再度有効なモデルを選択してください。既存のチャットにはそれぞれ独自の選択項目があります。グローバルデフォルトを変更しても、それらの選択は置き換えられません。

## 推論強度またはスピードコントロールがありません

これらの設定は選択されたモデルの機能に依存します。必要となるオプションを提供するモデルを選択してください。チャットのモデルを切り替えると、そのチャットの努力と速度の設定がリセットされますので、切り替え後には両方を確認してください。[モデルと既定の設定](/docs/ja/models)を参照してください。

## チャットを見つけることができません

1. 会話が行われたプロジェクトを選択してください。
2. **チャット履歴**を開き、その検索フィールドをクリアする。
3. チャットのタイトルに基づいて検索する。
4. **設定 → アーカイブ済みチャット** を確認し、そこに存在する場合、そのチャットを復元します。
5. プロジェクトが閉じられている場合、Getting-started画面の**最近閉じた項目**を介して再開してください。

複数チャットカラムを閉じても会話がアーカイブされません。メッセージがない空のチャットは履歴に表示されません。永久に削除されたチャットはDreamを通じて復元できません。

## 復元されたチャットが再びアーカイブされた

チャットを復元すると、その最後のアクティビティ日付が保持されます。**今すぐアーカイブ**を再度実行した場合、その日付がカットオフよりも古ければ、再度アーカイブ対象になります。アクションを実行する前に、カットオフ日付および保持したいチャットを確認してください。

## ブランチの作成は利用できません

現在の応答が終了するのを待ってからブランチを作成します。**新しいワークツリー** は Git リポジトリの存在を必要とします。ベースリファレンスが欠けているか無効である場合、ワークツリーの作成が妨げられる可能性があります；使用したいコミットされたブランチまたはリファレンスがリポジトリに存在することを確認してください。

新しいワークツリーに期待される編集が欠けている場合、元のプロジェクトで未コミットだったかどうかを確認してください。ワークツリーはそのような変更をコピーしません。[Gitワークツリー](/docs/ja/worktrees)を参照してください。

## 返信にはViewファイル変更の制御機能がありません

コントロールは、応答が終了した後にアシスタントメッセージに表示され、その応答に対してチェックポイントがキャプチャされた場合にのみ表示されます。**変更チェックポイント**が**設定 → 一般 → チャットメッセージ**で有効になっていること、およびDreamに`git`実行可能ファイルが存在することを確認してください。非常に大きなプロジェクトはキャプチャ時間制限を超過する場合があり、その場合、応答はチェックポイントなしで実行されます。[変更の確認と復元](/docs/ja/checkpoints)を参照してください。

## 差分や要素のフィードバックを送信できません

送信コントロールは、目的地のチャットが応答している間は無効になり、**チャットは処理中です**と表示されます。処理が終了するまで待つか、ポップオーバーで**新しいチャット**を有効にします。ポップオーバーが選択内容が差分と一致しなくなったことを報告した場合、変更を再読み込みし、行を再度選択します。[チャットへのフィードバックの送信](/docs/ja/feedback)を参照してください。

## Terminalでの継続は欠けている

この操作は、有効な継続可能なプロバイダーセッションを持つClaudeチャットに対してのみ利用可能であり、応答が処理中の間は無効になります。新しいチャット、別のプロバイダー、またはモデルまたはスピードを変更した後にセッションをリセットした場合、この機能は利用できません。[ターミナル](/docs/ja/terminals#dream-ide-で-claude-チャットをターミナルで継続する)を参照してください。

## ターミナルが開けない

プロジェクトディレクトリがまだ存在することを確認してください。**設定 → 一般 → ターミナル** で利用可能なシェルを選択し、新しいセッションを開きましょう。Claudeの継続機能を使用する場合、元のセッションディレクトリも存在しなければなりません。システムのターミナルで同じシェルを試みることで、環境の問題を特定できます。

## ブラウザプレビューは空か古くなっている

アプリケーションが実行されていることを確認し、そのターミナルに表示された正確なURLとポートを使用してください。ターミナルのエラーを確認した後、**ブラウザを更新**または**強制再読み込み**を試してください。システムブラウザ内のURLを確認してください。ページのエラーはDevToolsを使用して確認してください。クッキーまたはキャッシュの削除は、関連する認証またはキャッシュの問題に限定して行うことをお勧めします。[ブラウザープレビュー](/docs/ja/browser)を参照してください。

## ファイルを保存できません

ファイルが書き換え可能かどうかを確認し、エディタのエラーを読み取る。編集中にディスク上でファイルが変更された場合、**ディスクから再読み込み**前にドロップを保存した上で、意図した変更を再適用する。[ファイルと検索](/docs/ja/files#編集器の外でファイルが変更された場合に処理する)を参照。

## Gitアクションが失敗します

PRのコメント、編集、マージに関する問題がある場合、[プルリクエストのレビュー](/docs/ja/pull-requests)を参照してください。GitHub CLIが認証されており、アカウントが必要なリポジトリの権限を持っているかを確認してください。ドロップPRはマージする前に「準備済み」とマークされる必要があります。

| 症状 | 確認すべきこと |
| --- | --- |
| フォルダ用のGitツールはありません | Gitリポジトリ内のフォルダを開く |
| コミットにステージングされた変更はありません | レビューを含めるか、またはGitで意図したファイルをステージングする |
| アクティブなプロジェクト外でのステージド変更 | Dreamのコミットアクションを使用する前にそれぞれをコミットする |
| プッシュには目的地がない | Gitリモートを設定し、アクセスできるかを確認する |
| PRの作成でCLIエラーが報告された | GitHub CLIがインストールされていること、認証されていること、およびリポジトリにアクセスできるかを確認する |
| PRのソースとベースは同じである | PRを作成する前に機能ブランチに切り替える |
| PR作成レポート：HEADが分離されている | PRを作成する前にブランチをチェックアウトしてください |
| Worktreeの削除が失敗する | そのチェックアウトで未コミットの変更を確認および保持する |
| マージ＆削除は利用できません | ワークツリーはベースにコミットが先に存在しないか、メインチェックアウトに未コミットの変更やマージが進行中である |
| ワークツリーのレポートで競合が発生します | マージは中止され、何も変更されませんでした。ベースブランチをワークツリーにマージし、衝突を解決して、コミットした後、再試行してください。 |
| 完全なワークツリーではプルリクエストの作成が利用できません | Gitリモートを設定し、GitHub CLIをインストールする |

結合アクションが失敗した後は、再試行する前にブランチの状態を確認してください：コミットまたはプッシュは後に失敗するステップの前に成功している可能性があります。[Git workflows](/docs/ja/git-workflows)を参照してください。
