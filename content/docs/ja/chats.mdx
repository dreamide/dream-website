---
title: "チャットの使い方"
description: "会話を開始し、以前の作業を検索し、チャットを名前をつけて管理し、チャット履歴を管理できます。"
---

チャットは、コーディングエージェントとの 1 つの会話を保持します。チャットは通常プロジェクトに属し、独自のモデル、権限、会話履歴を持ちます。バグの修正と機能のレビューのように、別々に戻って作業したいタスクには、それぞれ別のチャットを使ってください。

フォルダを開かずに質問するには、[プロジェクトなしのチャット](/docs/ja/standalone-chats)を始めます。

## 会話を開始する

1. 作業したいプロジェクトタブを選択してください。
2. 左のツールバーで **新しいチャット** をクリックします。
3. メッセージボックスの下にモデルと権限を確認してください。
4. タスクを説明し、あなたのメッセージを提出してください。

新しいチャットは、[デフォルトのモデル設定](/docs/ja/models)を使用します。メッセージを送信する前に**新しいチャット**を再度クリックすると、空のドラフトが再利用できます。メッセージを送信した後、会話はプロジェクトの履歴に表示されます。

有用な最初のメッセージのために、エージェントに結果とその結果を確認する方法を提示してください。たとえば：

> ページを再読み込みすると設定フォームの値が失われる原因を調べてください。原因を修正し、修正をどのように検証したか説明してください。

[ファイルの参照と添付ファイル](/docs/ja/providing-context)を使用して関連するコードまたは画像へのリンクを示します。

## 会話に戻る

1. 左のツールバーで **チャット履歴** をクリックします。
2. 現在のプロジェクトのチャットを閲覧できる。最近更新された会話から順に表示する。
3. **検索履歴**にチャットのタイトルの一部を入力して、リストを絞り込む。
4. 対話を選択して開く。

履歴検索では、このプロジェクトのタイトルを絞り込みます。プロジェクトをまたいでタイトルとメッセージ本文を検索するには、トップバーの**チャットを検索**をクリックします（既定では macOS は **Command+Shift+F**、Windows/Linux は **Ctrl+Shift+F**）。検索結果には、ローカルプロジェクト、接続済みのリモートホスト、[プロジェクトなしのチャット](/docs/ja/standalone-chats)が含まれます。アーカイブ済みの結果を選択するとそのチャットが復元され、閉じたプロジェクトのチャットを選択するとそのプロジェクトが再び開きます。

ホストが検索できない場合は、再接続して再度試してください。結果がトリプルされた場合、クエリを絞ってください。過去の会話は [アーカイブ済みチャット](/docs/ja/archived-chats) で管理できます。

[multi-chat](/docs/ja/multiple-chats)が有効である場合、会話の選択によりサイドバイサイドレイアウトに表示されます。multi-chatが無効である場合、一度に1つの会話のみを表示します。

## チャットを再命名する

Dreamは会話が始まった後にタイトルを生成できます。より具体的な名前を付けるには、チャットの**…**メニューを開き、「編集」を選択するか、タイトルをダブルクリックします。**編集チャット**で名前を入力し、「保存」をクリックします。名前を変更しない場合は「キャンセル」を選びます。

「設定の永続化を修正」や「設定のテストをレビュー」といった名前は、同じプロジェクト名を持つ複数のチャットよりもはっきりと区別しやすい。

## 進行中の作業をフォローする

**デスクトップ通知** を **設定 → 一般 → チャットメッセージ** で有効にすると、Dream がバックグラウンドにあるときに、チャットの完了、失敗、入力待ちが通知されます。通知をクリックすると、そのチャットが開きます。**通知音** は別の設定で、Dream にフォーカスがあるときも再生できます。

通知は、このウィンドウが追跡していない間にホスト上で実行され続けているターンも対象になります。自分で停止したターンについては通知されません。

応答を受信中のチャットには読み込みスピナーが表示されます。メッセージを送信すると、Dream はそのメッセージが見える位置までスクロールします。

アグエントが応答している間、チャットではその進行状況やツールアクティビティが表示されます。オープンツール詳細を表示して、コマンド、ファイルの読み取り、または変更を確認できます。アグエントがタスクリストを提供する場合、メッセージボックスの側に表示されるタスクコントロールがその進行状況を示します。

チャット履歴とプロジェクトタブには、各チャットの状態が表示されます。応答中はスピナー、エージェントがあなたの対応を待っているときは琥珀色のドット、完了後まだ開いていないときは緑色のドットです。最新のメッセージを読むには、プロジェクトを選択して会話を開きます。応答を中断するには、入力欄の停止コントロールを使います。応答を停止しても、すでに行われたファイルの変更は元に戻りません。

ターンは、ウィンドウではなくプロジェクトのホスト上で実行されます。ウィンドウがホストとの接続を失ってもターンは実行され続け、Dream が自動的に再接続します。Dream を終了すると、アプリが起動したホストはターンとともに停止します。アプリを閉じた後もエージェントに作業を続けさせるには、[ホストを自分で実行](/docs/ja/dream-host)してください。

返信が終了した後は、そのフッターにある **この返答のファイル変更を表示** を使って、変更されたファイルを確認し、[それらのいずれかを元に戻す](/docs/ja/checkpoints)ことができます。

## メッセージをキューに入れる

次の指示を送るのに、応答の完了を待つ必要はありません。エージェントの作業中にメッセージを入力して送信してください。Dream はそれをチャットのキューに追加し、現在のターンが終わると実行します。ターンの実行中、入力欄のボタンは、メッセージ入力欄が空のときはターンを停止し、何か入力するとメッセージを送信します。

待機中のメッセージがあるとき、または対応が必要な実行があるときは、メッセージ入力欄の上に**キュー**の一覧が表示されます。各行には、メッセージ、そのモデル、状態が表示されます。

| 状態 | 意味 |
| --- | --- |
| 待機中 | 先行するターンの完了を待っている |
| 実行中 | エージェントが現在作業しているターン |
| 回答待ち | 実行中のターンがあなたの回答または承認を待っている |
| 中断 | 停止コントロールやホストの再起動などにより、完了前に停止した |
| 失敗 | エラーで終了した |

待機中のメッセージをキューから取り除くには、そのメッセージの**キャンセル**を使います。失敗または中断した実行には、**再試行**と**削除**が表示されます。中断した実行は作業の一部がすでに完了している場合があるため、再試行する前に、その実行が残した返信を読んでください。

**キューを一時停止**は、待機中のメッセージを保留し、現在のターンは最後まで実行させます。**キューを再開**で、保留したメッセージの実行が再び始まります。停止コントロールはこれとは異なり、実行中のターンとそのターンが[委任](/docs/ja/delegation)したタスクを終了し、キューを一時停止します。

実行が失敗または中断した場合もキューは一時停止し、キューのヘッダーには**キューを一時停止中**と表示されます。新しいメッセージを送信すると、キューが再開し、それらの実行は一覧から消えます。

キューはプロジェクトのホストに保存され、Dream を再起動しても残ります。ホストの再起動後、実行中だったターンは中断として扱われ、キューは再開するまで一時停止したままになります。待機中のメッセージを送信できない場合、そのテキストはメッセージ入力欄に戻ります。

## 閉じる、アーカイブ、または削除？

| アクション | 結果 | どうやって戻るか |
| --- | --- | --- |
| チャットカラムを閉じる | マルチチャットレイアウトから削除する | チャット履歴から開く |
| チャットをアーカイブする | アクティブなチャット履歴から削除する | 設定 → アーカイブ済みチャットで復元する |
| アーカイブされたチャットを削除する | Dream でチャットとそのメッセージを永続的に削除する | Dreamを通じて復元することはできません |

カラムを閉じることは、スペースを確保する必要がある場合に便利です。タスクが完了した場合にアーカイブは便利です。これらの操作のいずれも、エージェントがプロジェクトファイルに施した変更を元に戻すことはありません。

既に進行している会話のまま、別のアプローチを試したい場合は、[メッセージからブランチを作成](/docs/ja/branching-chats)してください。後の作業に準備するために、[スタッシュにプロンプトを保存](/docs/ja/stash)してください。複数のプロジェクトで再利用したい指示は、[再利用可能なプロンプト](/docs/ja/saved-prompts)を作成し、コンポーザーの**+ → プロンプトを実行**メニューから実行してください。**$** をタイプして[エージェントスキル](/docs/ja/skills)を呼び出してください。
