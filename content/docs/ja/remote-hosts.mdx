Dream では、ローカルプロジェクトと並べてリモートマシン上のプロジェクトを開けます。ファイル、Git コマンド、エージェントプロセス、ターミナルは、プロジェクトのホスト上で実行されます。プロジェクトのホストラベルで、どこで作業しているかを確認できます。

SSH でホストに接続するか、そのマシンで[リモートアクセス](/docs/ja/remote-access)がオンになっている場合は HTTPS で Dream ホストとペアリングします。1 つのホストに複数の経路を設定でき、Dream は最初に接続できた経路を使用します。

Dream は、Linux x64、Linux ARM64、macOS Apple シリコン (ARM64) 向けの管理対象ホストランタイムを SSH 経由でインストールします。これらはリモートホストのプラットフォームです。Dream デスクトップアプリ自体は Windows、macOS、Linux で実行できます。Linux のホストランタイムは glibc 2.31 以降のシステムをサポートします。

## SSH ホストを追加する

1. システムのターミナルで `ssh devbox` が動作することを確認します。`devbox` は SSH 設定のエイリアスまたは `user@host` に置き換えてください。Dream はシステムの SSH クライアント、設定、鍵を使用します。
2. **設定 → 接続**を開き、**ホストを追加 → SSH ホスト**を選択します。
3. **SSH の接続先**を入力するか、`~/.ssh/config` から提案されたエイリアスを選択し、必要に応じて**名前**を入力します。
4. ランタイムを自動インストールするには**ホストコマンド**を空欄のままにして、**保存**をクリックします。Dream が新しいホストに接続します。
5. ホスト鍵、パスワード、パスフレーズ、二要素認証の要求には Dream 内で回答します。要求を拒否またはキャンセルすると、その接続試行は停止します。

**SSH ホストを追加…**は、**フォルダーを開く**ダイアログからも選択できます。

管理対象のランタイムは、バージョンごとに `~/.dream/host/versions/` にインストールされます。ホストがランタイムをダウンロードできない場合は、Dream がローカルにダウンロードして SSH 経由で転送できます。エージェントの CLI もリモートマシンにインストールし、そこでサインインしてください。CLI はそのマシンの環境で動作します。

手動でインストールしたランタイムを使う場合は、リモートマシンで `dream-host` を実行するコマンドを**ホストコマンド**に設定します。

## HTTPS 経由でホストをペアリングする

ペアリングでは、SSH を使わずに、そのホストの[リモートアクセス](/docs/ja/remote-access)設定で使われるアドレスを通じて、このデスクトップを Dream ホストに接続します。

1. ホストマシンで**設定 → 接続**を開き、**デバイスをペアリング**を選択します。このボタンは**リモートアクセス**にあります。
2. このデスクトップで**設定 → 接続**を開き、**ホストを追加 → ペアリングリンク**を選択します。
3. **リンク**タブで**ペアリングリンク**を貼り付けます。または、**コード**タブで、ホストに表示された**ホストのアドレス**と**ペアリングコード**を入力します。
4. 必要に応じて名前を入力し、**ペアリング**を選択します。
5. コードを使用した場合は、ホストのリモートアクセス設定の**ペアリング待ち**で、このデスクトップを承認します。

ペアリングリンクは 1 回だけ使用でき、10 分後に期限切れになります。ホストの HTTPS 証明書は、このコンピューターで信頼されている必要があります。

## リモートプロジェクトを開く

1. スタート画面で**フォルダを開く**を選択します。その画面に戻るには、プロジェクトの**+**ボタンを使用します。
2. **開く場所**でホストを選択します。Dream から求められた場合は接続します。
3. **フォルダのパス**を入力します。入力中に Dream がフォルダを提案します。パスの下の一覧から参照したり、**1 つ上のフォルダ**を使ったりすることもできます。
4. **開く**をクリックします。リモートフォルダーが、専用のチャットとツールを持つプロジェクトタブとして開きます。

閉じたリモートプロジェクトは、ホストとパス付きで**最近閉じた項目**に表示されます。再び開くと、そのホストに接続します。リモートパスはリモートマシン上の場所です。Dream の外でファイルを開くときは、そのマシンに接続したエディターを使用してください。

## 経路を管理する

経路とは、ホストに到達する方法の 1 つで、SSH 接続またはペアリング済みの HTTPS アドレスのことです。同じホストに複数の経路を追加しておくと、1 つが使えなくても作業を続けられます。たとえば、オフィスのネットワークでは SSH、それ以外の場所では HTTPS を使えます。

1. **設定 → 接続**を開き、ホストの**編集**をクリックします。
2. 経路を確認します。経路は接続できるまで順番に試行され、**使用中の経路**が現在使われている経路を示します。
3. 順序を変更するには、**上へ移動**と**下へ移動**を使用します。
4. 同じホストへの別の接続方法を追加するには**SSH 経路を追加**または**HTTPS 経路を追加**を、経路を削除するには**経路を削除**を選択します。少なくとも 1 つの経路が必要です。

優先経路が使用できない場合、Dream は次の経路に切り替え、転送ポートを維持します。HTTPS 経路を変更するには、新しいペアリングリンクが必要です。

## ホストの再接続と削除

**設定 → 接続**の各ホストには、**接続済み**、**再接続中…**、**接続に失敗しました**などのステータスが表示されます。Dream は中断された接続を再試行します。ホストが利用できない間もプロジェクトタブは表示されたままですが、再接続するまでメッセージは送信できません。再接続が止まった場合は、表示されたエラーを読み、**接続**を使用します。

ホストの名前、接続先、コマンドを変更するには**編集**を使用します。接続先またはコマンドを変更すると、アクティブな接続が再接続されます。**切断**しても、そのプロジェクトタブはそのまま残ります。

**削除**を選ぶと確認を求められ、その後この Dream ワークスペースからホストとそのプロジェクトが削除され、ターミナルが停止します。ホスト上のファイルとチャットは削除されません。

## 接続の問題

まず、システムのターミナルで同じ SSH 接続先を確認します。再接続する前に、認証やホストキーの問題を修正してください。ホストランタイムを起動できない場合は、**設定 → 接続**のエラーを読み、設定済みの**ホストコマンド**、またはお使いのプラットフォーム用のランタイムが利用可能かどうかを確認します。

HTTPS 経路の場合は、ホストが実行中で、リモートアクセスが**準備完了**になっていることを確認します。経路に**確認が必要**と表示される場合 (ホストの**編集**ダイアログで確認できます)、デバイスのアクセスが取り消された可能性があります。ホストのリモートアクセス設定から新しいリンクを取得して、再度ペアリングしてください。[リモートアクセスの問題](/docs/ja/remote-access#リモートアクセスの問題)を参照してください。

開発ビルドにはダウンロード可能な公開済みランタイムがありません。Dream アプリのリポジトリから `pnpm host:install-dev devbox` を実行し、**ホストコマンド**を空欄にして再接続してください。リモートビルドには Node.js 22 以降、pnpm または Corepack、make、Python 3、C++ ツールチェーン（g++ 10 以降）が必要です。インストーラーは、ランタイムを置き換える前に既存の開発ホストデーモンを停止します。
