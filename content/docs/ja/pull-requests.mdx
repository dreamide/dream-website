右側のツールバーにある **Pull requests** ボタンは、現在のブランチのGitHub PRを開きます。リポジトリにGitHub CLIをインストールし、認証を行ってください。新しいPRを公開するには、[Git workflows](/docs/ja/git-workflows#プルリクエストを作成) を参照してください。

## 現在のブランチのPRを開く

1. プロジェクトを選択し、現在のブランチを確認する。
2. 右のツールバーの **Pull requests** をクリックします。
3. PRのタイトル、状態、ソースブランチおよびベースブランチ、およびチェックを確認する。
4. **概要** で説明と議論を行うか、**コード** で変更されたファイルを指定する。

ブランチにPRがなければ、パネルは **プル リクエストを作成する** を提供します。GitHubで変更を施した後は、**プルリクエストの操作 → 更新** を使用するか、**GitHub で開く** でブラウザ上でPRを確認できます。マージされたPRは、そのPRのヘッドより新しいコミットがブランチに含まれる場合に自動的に表示されなくなります。

## コードをレビューし、コメントを投稿する

**概要**で議論を読み、**書き込み** および **プレビュー** を使って Markdown コメントを構成してください。**コメントを投稿** を選択して GitHub に公開してください。

**コード**でファイルを展開し、そのdiff内の行を選択して**行にコメントを投稿**できます。既存のレビュースレッドを読むことができ、**返信**を使ってそのスレッドを継続できます。テキストパッチが利用できない場合、GitHub上のPRを開いてそのファイルを確認できます。

これらのコメントはGitHubに投稿されます。ローカルの変更についてコーディングエージェントに尋ねるには、[Changesにおけるdiffフィードバック](/docs/ja/feedback#diffの行にコメントを付ける)を使用してください。

## タイトルと説明を編集する

アカウントに権限がある場合、**タイトルを編集**または**説明を編集**を使用します。タイトルを編集した後は、それを保存します。説明については、**書き込み**および**プレビュー**を用いてから**保存**します。また、編集コントロールが存在する場合、自分のコメントも編集できます。

## プルリクエストをマージする

1. コード、ディスカッション、チェックをレビューしてください。
2. パネルヘッダーの **マージ** をクリックします。
3. **PR をマージ**のソースブランチとベースブランチを確認してください。
4. 利用可能な方法を選択してください：**マージコミットを作成**、**スカッシュしてマージ**、または**リベースしてマージ**。
5. マージを提出します。

のみ、オープンでドラフトではないPRのみマージ可能です。GitHubでまずドラフトを準備済みにマークしてください。アカウントにはマージ許可が必要であり、リポジトリが利用可能なマージ方法を決定します。GitHubはリポジトリの要件が満たされていない場合、マージを拒否する可能性があります。

Dreamは、マージ詳細をロードした際に表示されていたHEADコミットがPRに変更されていないことを確認します。GitHubで変更された場合は、再試行する前にリフレッシュし、新しい変更を確認してください。
