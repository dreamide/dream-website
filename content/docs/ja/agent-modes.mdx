各チャットには、そのメッセージボックスの下に**権限**制御が存在します。新しいチャットは**設定 → 一般 → モデル → 既定の権限**を継承し、これは**フルアクセス**から開始されます。既定の権限を変更しても、既存のチャットには影響を与えません。

## 権限を選択

1. メッセージ入力欄の下にある盾アイコンのコントロールを開きます。ツールチップには**権限**と表示されます。
2. **確認する**、**編集を承認**、または**フルアクセス**を選択してください。
3. タスクの内容を確認して送信します。

| 権限 | 意図された動作 |
| --- | --- |
| 確認する | provider の設定で許可が必要なアクションに対して承認を要求する |
| 編集を承認 | ファイルの編集を自動的に許可する一方で、その他のアクションについては承認処理を維持する |
| フルアクセス | エージェントに承認プロンプトなしでより広いアクセスを付与する |

権限の具体的な動作は、選択したプロバイダーによって決まります。**確認する**を選んでも、すべての読み取りやツール呼び出しで承認を求めるわけではありません。また、**編集を承認**を選んでも、すべてのコマンドが承認されるわけではありません。

<Note>
  Dream には、Build と Plan の個別のコントロールはなくなりました。先に計画を立てるには、変更する前に調査して進め方を提案するようエージェントに依頼してください。この指示だけではファイルシステムへのアクセスは読み取り専用になりません。タスクに適した権限も選んでください。
</Note>

## 質問への回答と承認の処理

アグエントは、要件を明確にすること、選択肢を選択すること、または行動を承認することをあなたに求めることもあります。会話中のリクエストを読み取り、提供されたコントロールを使って応答してください。プロジェクトタブは、アグエントがあなたの回答を待っていることを示すことがあります。そのプロジェクトタブを開き、会話に戻ってリクエストを確認してください。

タスクの変更が必要な場合は、そのチャットでエージェントに修正した指示を伝えてください。必要に応じて停止ボタンで応答を中断できます。停止しても、すでに完了した編集やコマンドは取り消されません。その後に[変更](/docs/ja/git-workflows)を確認するか、その応答の[チェックポイント](/docs/ja/checkpoints)を使って変更されたファイルを復元してください。

並列タスクで別々のファイルが必要な場合、[worktrees](/docs/ja/worktrees) を使用してください。権限設定により、同じフォルダ内の2つのチャットが独立したチェックアウトを取得することはできません。
