Each Dream project has its own workspace. Project tabs let you move between repositories while
keeping each project's open chats and tools together.

Projects can also live on [remote hosts](/docs/remote-hosts). The footer beneath the chat shows the
host, the project, and the branch. Check it before running commands; remote project tools work on
that machine.

## Add and switch projects

1. Click the **+** beside the project tabs, or use **Open Folder** on the getting-started screen.
2. In the **Open folder** dialog, enter the folder's path or click **Browse…**. When you have added a
   [remote host](/docs/remote-hosts), choose where the folder lives under **Open on**.
3. Click **Open**, then select the project's tab to make it the active project.

As you type a path, Dream lists the matching folders. Press **Tab** to complete the highlighted
folder and **Enter** to open it. The default shortcut for this dialog is **Command+O** on macOS or
**Ctrl+O** on Windows/Linux.

The active project determines which chats, files, terminals, browser tabs, and stash items you see.
Check the selected tab before sending a task or running a command. Drag project tabs to reorder them
when you want related projects next to each other.

## Rename or open a project externally

Open the project's **…** menu and choose **Edit** to change its display name or icon. Click the icon
to upload an image up to 5 MB, then **Save**. Reset a custom icon to return to automatic detection
from the project. Renaming a project in Dream does not rename its folder on disk.

Use the menu's **Open in** choices to open the project in your file manager, a terminal, or an
installed editor. The same choices open when you click the project's name in the footer beneath the
chat.

For a project on an SSH host, **Open in** lists the installed editors that support Remote SSH. A
project reached only over HTTPS, or viewed from a paired device's browser, has no **Open in** menu.

## Go back to a previous chat

Use **Back** and **Forward** beside the project tabs to revisit projects and chats you opened.
On Windows and Linux, use **Alt+Left** and **Alt+Right**; on macOS, use **Command+[** and
**Command+]**. Mouse back and forward buttons work too.

This history follows project and chat selections. Switching tool panels does not add entries, and
the embedded browser has its own navigation history. Keyboard shortcuts inside the terminal or
code editor are left to those tools.

## Close and reopen a project

1. Open the project's **…** menu and choose **Close**.
2. When you want to return, open the getting-started screen through the project **+** button.
3. Find the project in **Recently closed**, using its search field if needed.
4. Select the project to reopen it.

Closing a project removes its open tab and stops its terminals; it does not delete its folder. Dream
restores saved project context such as chats and open tools when possible.

**Recently closed** remembers up to 50 projects and shows each one's host and path. Its search
matches a project's name, path, and host.

## Find the workspace controls

The left toolbar contains **Chat history**, **New chat**, and **Enable multi-chat**. Hover over an
icon to see its label. The chat composer holds the selected model, effort and speed when supported,
and permissions.

The right toolbar opens project tools:

| Tool | What you can do |
| --- | --- |
| [Files](/docs/files) | Browse files, search paths, and edit file contents |
| [Browser](/docs/browser) | Preview URLs and inspect web pages |
| [Terminal](/docs/terminals) | Run project commands in separate sessions |
| [Git](/docs/git-workflows) | Review changes, commit, browse history, and manage the branch's pull request |
| [Stash](/docs/stash) | Save prompts and run them later |

**Git** and the Git controls appear only for projects inside a Git repository. The footer beneath the
chat shows the host, the project, and the branch. Use the branch control to switch branches or
[create a worktree](/docs/worktrees). The **Git actions** menu at the right of the footer offers
committing, fetching, pulling, pushing, pull requests, and worktree actions according to the
branch's state.

## Arrange chats and panels

Click a tool to open its panel. Use the panel's close or collapse control when you need more room
for chats, and drag panel dividers to resize the layout. Closing a tool panel is different from
closing its individual terminal sessions or browser tabs.

Double-click the right panel's divider to give the panel an equal share of the window's width. Use
**Expand** in a panel's header to let it fill the workspace and **Collapse** to return it to its
usual size.

Enable [multi-chat](/docs/multiple-chats) to arrange conversations in resizable columns. Each chat has
its own conversation history, while all chats in the project use the same files. Use worktrees for
independent checkouts.

## Capture the Dream window

Press **Ctrl+Shift+S** on Windows/Linux or **Command+Shift+S** on macOS to capture the Dream window.
Dream copies the screenshot to the clipboard, then opens a dialog to save it as a PNG. Canceling
the save dialog keeps the clipboard copy. A notification reports whether the image was copied,
saved, or could not be captured.

For a screenshot of a web page, use the [browser's screenshot action](/docs/browser) instead.

For app-wide appearance, language, and model preferences, open [Settings](/docs/settings). To find
older conversations, use [Chat history](/docs/chats) or [Archived chats](/docs/archived-chats).
