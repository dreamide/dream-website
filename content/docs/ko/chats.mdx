---
title: "채팅 사용하기"
description: "대화를 시작하고, 이전 작업을 찾고, 채팅을 이름을 바꾸며 채팅 기록을 관리할 수 있습니다."
---

채팅은 코딩 에이전트와 나누는 하나의 대화를 담습니다. 채팅은 대개 프로젝트에 속하며 자체 모델, 권한, 대화 기록을 갖습니다. 버그 수정과 기능 검토처럼 각각 따로 돌아와 이어 가고 싶은 작업에는 별도의 채팅을 사용하세요.

폴더를 열지 않고 질문하려면 [프로젝트 없는 채팅](/docs/ko/standalone-chats)을 시작하세요.

## 대화를 시작하세요

1. 작업할 프로젝트 탭을 선택하세요.
2. 왼쪽 툴바의 **새 채팅**을 클릭하세요.
3. 메시지 박스 아래의 모델과 권한을 확인하세요.
4. 작업을 설명하시고 메시지를 제출하세요.

새 채팅은 [기본 모델 설정](/docs/ko/models)을 사용합니다. 메시지를 보낼 전에 **새 채팅**을 다시 클릭하면 빈 초안을 재사용할 수 있습니다. 메시지를 보낸 후에는 대화가 프로젝트의 역사에 나타납니다.

유용한 첫 번째 메시지로는 에이전트에게 결과와 그 결과를 확인하는 방법을 제공해야 합니다. 예를 들어:

> 페이지를 새로고침하면 설정 양식의 값이 사라지는 원인을 찾으세요. 원인을 수정하고 수정 사항을 어떻게 검증했는지 설명하세요.

[파일 참조 및 첨부 파일](/docs/ko/providing-context)을 사용하여 관련된 코드나 이미지를 가리킬 수 있습니다.

## 대화로 돌아가기

1. 왼쪽 툴바의 **채팅 기록**을 클릭하세요.
2. 현재 프로젝트의 대화를 탐색하되, 최근에 업데이트된 대화부터 보여줍니다.
3. **검색 기록**에 채팅 제목의 일부를 입력하여 목록을 좁힐 수 있습니다.
4. 대화를 선택하여 열 수 있습니다.

기록 검색은 이 프로젝트의 제목을 필터링합니다. 여러 프로젝트의 제목과 메시지 텍스트를 검색하려면 상단 바의 **채팅 검색**을 클릭하세요(기본 단축키는 macOS에서 **Command+Shift+F**, Windows/Linux에서 **Ctrl+Shift+F**). 검색 결과에는 로컬 프로젝트, 연결된 원격 호스트, [프로젝트 없는 채팅](/docs/ko/standalone-chats)이 포함됩니다. 보관된 결과를 선택하면 해당 채팅이 복원되고, 닫힌 프로젝트의 채팅을 선택하면 그 프로젝트가 다시 열립니다.

호스트를 검색할 수 없으면 연결을 재시도하고 다시 시도하세요. 결과가 자르기 되었을 경우 쿼리를 좁히세요. 더 오래된 대화를 [보관된 채팅](/docs/ko/archived-chats)에서 관리할 수 있습니다.

[다중 채팅](/docs/ko/multiple-chats)이 활성화되어 있을 경우, 대화를 선택하면 측면 레이아웃에 표시됩니다. 다중 채팅이 비활성화되어 있을 경우, 한 대화를 한 번에 확인합니다.

## 채팅 이름 변경

Dream은 대화가 시작되면 제목을 생성할 수 있습니다. 더 구체적인 이름을 부여하고자 한다면 채팅의 **…** 메뉴를 열고 **편집**을 선택하거나 제목을 두 번 클릭합니다. **채팅 수정**에서 이름을 입력한 후 **저장**을 클릭합니다. **취소**를 선택하면 현재 이름을 유지합니다.

“설정 유지 기능 고치기”와 “설정 테스트 검토”와 같은 이름은 동일한 프로젝트에 대해 여러 차트 이름을 가진 것보다 더 명확하게 구분할 수 있다.

## 진행 중인 작업을 추적하세요

**데스크톱 알림**을 **설정 → 일반 → 채팅 메시지**에서 켜면 Dream이 백그라운드에 있을 때 채팅이 완료되거나 실패하거나 입력이 필요할 때 알림을 받습니다. 알림을 클릭하면 해당 채팅이 열립니다. **알림음**는 별도 설정이며 Dream에 포커스가 있을 때도 재생할 수 있습니다.

알림은 이 창에서 지켜보고 있지 않은 동안 호스트에서 계속 실행되는 턴에도 적용됩니다. 직접 중지한 턴은 알림을 보내지 않습니다.

응답을 스트리밍 중인 채팅에는 로딩 표시기가 나타납니다. 메시지를 보내면 Dream이 해당 메시지가 보이도록 스크롤합니다.

агент이 응답할 때 채팅에는 진행 상황과 도구 활동이 표시됩니다. 도구 세부 정보를 열어 명령어, 파일 읽기, 또는 변경 사항을 검토할 수 있습니다. 에이전트가 작업 목록을 제공할 경우 메시지 박스 옆의 작업 제어기에서 그 진행 상황을 확인할 수 있습니다.

채팅 기록과 프로젝트 탭에는 각 채팅의 상태가 표시됩니다. 응답 중일 때는 스피너, 에이전트가 사용자를 기다릴 때는 주황색 점, 응답이 끝났지만 아직 열어 보지 않았을 때는 녹색 점이 나타납니다. 프로젝트를 선택하고 대화를 열어 최신 메시지를 읽으세요. 응답을 중단하려면 입력창의 중지 컨트롤을 사용하세요. 응답을 중지해도 이미 이루어진 파일 변경은 되돌려지지 않습니다.

턴은 창이 아니라 프로젝트의 호스트에서 실행됩니다. 창과 호스트의 연결이 끊어져도 턴은 계속 실행되며 Dream이 자동으로 다시 연결합니다. Dream을 종료하면 앱이 시작한 호스트와 그 호스트의 턴이 함께 중지됩니다. 앱을 닫은 뒤에도 에이전트가 계속 작업하게 하려면 [호스트를 직접 실행](/docs/ko/dream-host)하세요.

답변이 완료되면, 그 아래에 있는 **이 답변의 파일 변경 사항 보기**를 사용하여 변경된 파일을 확인하고 [어떤 파일을 복원](/docs/ko/checkpoints)할 수 있습니다.

## 메시지를 대기열에 추가하기

다음 지시를 보내기 위해 응답이 끝날 때까지 기다릴 필요는 없습니다. 에이전트가 작업하는 동안 메시지를 입력해 보내세요. Dream이 메시지를 채팅의 대기열에 추가하고 현재 턴이 끝나면 실행합니다. 턴이 실행되는 동안 입력창의 버튼은 메시지 상자가 비어 있으면 턴을 중지하고, 내용을 입력하면 메시지를 보냅니다.

대기 중인 메시지가 있거나 확인이 필요한 실행이 있으면 메시지 상자 위에 **대기열** 목록이 나타납니다. 각 행에는 메시지, 모델, 상태가 표시됩니다.

| 상태 | 의미 |
| --- | --- |
| 대기 중 | 앞선 턴이 끝나기를 기다리고 있습니다 |
| 실행 중 | 에이전트가 지금 작업 중인 턴입니다 |
| 응답 대기 중 | 실행 중인 턴이 사용자의 답변이나 승인을 기다리고 있습니다 |
| 중단됨 | 중지 컨트롤이나 호스트 재시작 등으로 완료되기 전에 중지되었습니다 |
| 실패 | 오류와 함께 종료되었습니다 |

대기 중인 메시지를 대기열에서 빼려면 해당 메시지의 **취소**를 사용하세요. 실패하거나 중단된 실행에는 **다시 시도**와 **제거**가 제공됩니다. 중단된 실행은 작업의 일부를 이미 마쳤을 수 있으므로 다시 시도하기 전에 남겨진 응답을 읽어 보세요.

**대기열 일시 중지**는 대기 중인 메시지를 보류하고 현재 턴은 끝까지 실행되게 합니다. **대기열 재개**는 보류된 메시지를 다시 실행합니다. 중지 컨트롤은 다르게 동작합니다. 실행 중인 턴과 그 턴이 [위임한](/docs/ko/delegation) 작업을 모두 종료하고 대기열을 일시 중지합니다.

실행이 실패하거나 중단되어도 대기열이 일시 중지되며, 대기열 헤더에 **대기열 일시 중지됨**이 표시됩니다. 새 메시지를 보내면 대기열이 재개되고 해당 실행은 목록에서 사라집니다.

대기열은 프로젝트의 호스트에 저장되므로 Dream을 다시 시작해도 유지됩니다. 호스트가 다시 시작되면 실행 중이던 턴은 중단됨으로 표시되고, 대기열은 사용자가 재개할 때까지 일시 중지된 상태로 남습니다. 대기 중인 메시지를 보낼 수 없으면 해당 텍스트가 메시지 상자로 돌아옵니다.

## 닫기, 아카이브, 또는 삭제?

| 액션 | 결과 | 반환 방법 |
| --- | --- | --- |
| 채팅 열을 닫기 | 다중 채팅 레이아웃에서 제거합니다 | 채팅 기록에서 열기 |
| 채팅을 아카이브합니다 | 활성 채팅 기록에서 제거합니다 | 설정 → 보관된 채팅에서 복원하세요 |
| 이전 대화를 삭제합니다 | Dream에서 대화와 그 메시지들을 영구적으로 제거합니다. | Dream을 통해 복원할 수 없습니다. |

컬럼을 닫는 것은 더 많은 공간이 필요할 때 유용합니다. 작업이 완료되었을 때 아카이빙은 유용합니다. 이 두 작업 모두 프로젝트 파일에 대한 에이전트의 변경 사항을 되돌릴 수 없습니다.

이전 대화를 유지하면서 다른 접근 방식을 시도하고자 한다면, [메시지에서 브랜치를 생성](/docs/ko/branching-chats)하세요. 이후에 작업을 준비하고자 한다면, [스태시에 프롬프트를 저장](/docs/ko/stash)하세요. 여러 프로젝트에서 재사용하고자 하는 지침은 [재사용 가능한 프롬프트](/docs/ko/saved-prompts)를 만들어서, 작가의 **+ → 프롬프트 실행** 메뉴에서 실행하세요. **$**를 입력하여 [에이전트 스킬](/docs/ko/skills)을 호출하세요.
