오른쪽 툴바의 **풀 리퀘스트** 버튼은 현재 브랜치의 GitHub 풀 리퀘스트를 열어줍니다. 먼저 리포지토리에 GitHub CLI를 설치하고 인증해야 합니다. 새 풀 리퀘스트를 생성하려면 [Git 작업 흐름](/docs/ko/git-workflows#풀-리퀘스트-만들기)을 따릅니다.

## 현재 브랜치의 PR 열기

1. 프로젝트를 선택하고 현재 브랜치를 확인합니다.
2. 오른쪽 툴바의 **풀 리퀘스트**를 클릭하세요.
3. PR 제목, 상태, 출처 및 기준 브랜치를 검토하고, 검사 결과를 확인합니다.
4. **요약**를 사용하여 설명과 논의를 하거나, **코드**를 사용하여 변경된 파일을 나타냅니다.

브랜치에 PR이 없으면 패널은 **풀 요청 생성**을 제공합니다. GitHub에서 변경된 내용을 반영하려면 **풀 리퀘스트 작업 → 새로고침**을 사용하거나, **GitHub에서 열기**를 통해 브라우저에서 PR을 확인할 수 있습니다. 병합된 PR은 해당 PR의 헤드를 초과하는 더 최신 커밋이 존재하는 즉시 더 이상 나타나지 않습니다.

## 코드를 검토하고 댓글을 작성합니다

**요약**에서 논의를 읽고, **쓰기** 및 **미리보기**를 사용하여 마크다운 댓글을 작성하세요. **댓글 게시**를 선택하여 GitHub에 게시하세요.

**코드**에서 파일을 확장하고 그 diff의 줄을 선택하여 **줄 댓글 게시**를 작성할 수 있습니다. 기존 리뷰 스레드를 읽고 **답글**을 사용하여 그 스레드를 계속할 수 있습니다. 텍스트 패치가 없을 경우 GitHub에서 PR을 열어 해당 파일을 검토할 수 있습니다.

이 의견들은 GitHub에 게시됩니다. 로컬 변경 사항에 대해 코딩 에이전트에게 질문하고자 한다면 [변경 사항에서 줄에 대한 의견을 남기기](/docs/ko/feedback#차이를-가진-줄에-주석을-달기)를 사용하세요.

## 디렉토리 이름과 설명을 편집합니다

계정에 권한이 있는 경우 **제목 편집** 또는 **설명 편집**을 사용하세요. 제목을 편집한 후에 저장하세요. 설명은 **쓰기** 및 **미리보기**를 사용한 후에 **저장**하세요. 또한 편집 컨트롤이 있는 경우 자신의 댓글도 편집할 수 있습니다.

## 풀리퀘스트를 병합합니다

1. 코드, 논의, 검토를 검토합니다.
2. 패널 헤더에서 **병합**를 클릭합니다.
3. **PR 병합**에서 출처 및 기준 브랜치를 확인하세요.
4. 사용 가능한 방법을 선택하세요: **병합 커밋 생성**, **스쿼시 후 병합**, 또는 **리베이스 후 병합**.
5. 머지 제출.

다른 PR만 병합할 수 있으며, GitHub에서 초안 상태를 준비한 후에 표시해야 합니다. 계정에는 병합 권한이 필요하며, 저장소는 사용 가능한 병합 방법을 결정합니다. 저장소의 요구 사항이 충족되지 않을 경우 GitHub는 병합을 거부할 수 있습니다.

Dream은 머지 세부 정보를 로드할 때 표시된 헤드 커밋이 PR가 여전히 그대로인지 확인합니다. GitHub에서 변경된 경우, 새로고침하고 새로운 변경 사항을 검토한 후 다시 시도합니다.
