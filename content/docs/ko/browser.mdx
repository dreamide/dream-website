Dream의 브라우저는 프로젝트와 함께 웹 페이지를 열고 대화를 합니다. 애그نت이 코드를 작업하는 동안 로컬 애플리케이션을 조사할 수 있습니다.

## 애플리케이션을 미리보기

1. [터미널](/docs/ko/terminals)에서 애플리케이션을 일반 프로젝트 명령어를 사용하여 시작합니다.
2. 응용 프로그램이 인쇄한 로컬 URL을 복사하여 그 port도 포함시킵니다.
3. 오른쪽 툴바의 **브라우저**를 클릭하세요.
4. 주소 표시 줄에 URL을 입력하고 **Enter**를 누릅니다.

페이지는 워크스페이스 내부에서 열립니다. 애플리케이션이 다음 실행 시 다른 포트를 사용한다면 해당 주소를 업데이트해야 합니다. Dream의 브라우저가 URL을 열며 애플리케이션을 시작하지 않습니다.

## 브라우저 탭 사용

**새 탭**을 클릭하여 다른 페이지를 열고 탭을 선택하여 해당 탭으로 전환할 수 있습니다. 브라우징 기록에서 두 경로를 동시에 보이게 하기 위해 하나를 다른 하나로 대체하지 않고 유지하는 데 유용합니다.

**뒤로**, **앞으로**, 그리고 **브라우저 새로 고침**을 사용하여 이동합니다. 개별 탭을 그 탭 닫기 컨트롤을 사용하여 닫습니다. 브라우저 패널을 숨기면 나중에 열린 탭으로 돌아갈 수 있습니다.

## 검사하고 보는 것을 공유하세요

브라우저 액션은 다음과 같습니다:

| 액션 | 다음과 같은 일을 사용하여... |
| --- | --- |
| DevTools 열기 | 페이지의 콘솔, 요소, 네트워크 활동을 검사합니다 |
| 스크린샷 찍기 | 버그 보고서나 추가 논의를 위해 페이지를 캡처하세요. |
| 확대 / 축소 / 확대 초기화 | 프리뷰의 표시 크기 조정 |
| 시스템 브라우저에서 열기 | 정상적인 브라우저에서 현재 URL을 확인하세요 |

**브라우저 펼치기**를 사용할 때 더 많은 공간이 필요하고, **브라우저 접기**를 사용하여 작은 화면으로 돌아갑니다. 에이전트에게 전체 페이지의 스크린샷을 제공하고자 할 경우, 채팅의 [첨부 제어](/docs/ko/providing-context)를 사용합니다.

## 채팅에 요소를 전송합니다

1. 브라우저 도구바에서 **요소를 선택하여 채팅으로 보내기**를 클릭하세요.
2. 페이지를 올려서 요소들을 테두리로 표시한 후, 논의하고자 하는 요소를 클릭하세요. **Escape**를 누르면 취소됩니다.
3. **채팅으로 보내기** 폼에 댓글을 입력하고, 별도의 대화를 원한다면 **새 채팅**을 활성화한 후 보내기.

Dream은 댓글을 요소의 선택자, 크기, 텍스트, 스타일, HTML 및 요소의 스크린샷과 함께 전송하여 에이전트가 코드에서 이를 찾을 수 있도록 합니다. 자세한 내용과 제한 사항은 [채팅에 피드백 보내기](/docs/ko/feedback)를 참조하세요.

## 애그نت에게 브라우저를 사용하도록 요청하세요

Claude Code, Codex, OpenCode, 그리고 Grok Build 채팅은 Dream의 브라우저에 도구를 자동으로 제공합니다. 이 도구들은 동일한 프로젝트 브라우저 탭과 함께 작동합니다. Cursor 채팅은 이러한 도구를 받지 않습니다.

에이전트에게 페이지 URL과 구체적인 작업을 주세요, 예를 들어:

> Dream 브라우저에서 http://localhost:3000/settings 를 여세요. 테마를 변경하고 페이지를 새로고침한 다음 선택이 유지되는지 확인하세요. 유지되지 않으면 콘솔과 네트워크 요청을 살펴보세요.

이 도구들은 탭을 열고 탐색할 수 있으며, 페이지 내용을 조사하고 클릭, 입력, 호버, 옵션 선택, 스크롤, 스크린샷을 찍고 컨솔 로그 및 네트워크 응답을 조사할 수 있습니다. 또한 프로젝트 내부의 경로를 사용하여 프로젝트에서 파일을 첨부하여 업로드할 수 있습니다. 파일 업로드는 프로젝트 내부 경로를 사용해야 합니다.

응용 프로그램을 시작한 후에 에이전트가 로컬 URL을 조사하도록 요청할 때. 브라우저 작업은 채팅의 [권한](/docs/ko/agent-modes)에 따라 진행되며, 승인이 요청되면 채팅에서 응답해야 합니다. 이러한 도구는 내장되어 있으며, 수동으로 [MCP 서버 정의](/docs/ko/mcp-servers)를 설정할 필요가 없습니다.

## 사이트 데이터를 다시 로드하고 클리어합니다

애플리케이션 코드를 변경한 후 정상적인 새로 고침을 시도하세요. 페이지가 여전히 오래된 상태처럼 보이면, 브라우저 액션에서 **강제 새로 고침**을 사용하세요.

**캐시 지우기**는 브라우저 캐시 데이터를 제거합니다. **쿠키 지우기**는 쿠키를 삭제하며 내장 브라우저에서 사이트에 로그아웃할 수 있습니다. 캐싱 또는 인증 행동을 조사할 때 이러한 작업을 의도적으로 사용해야 합니다.

## 로컬 페이지가 로드되지 않는 경우

응용 프로그램이 여전히 실행 중인지 확인하고, 그의 터미널 출력에서 전체 URL과 포트를 확인하고, 그곳에 있는 서버 오류를 점검합니다. 시스템 브라우저에서 동일한 주소를 시도하여 응용 프로그램의 문제인지 내장 미리보기의 문제인지 구분합니다.
