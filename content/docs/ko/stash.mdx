스태시는 현재 프로젝트에서 나중에 실행하고자 하는 프롬프트를 보관합니다. 각 저장된 항목은 텍스트, 프로젝트 참조, 모델, 노력, 속도, 및 권한을 포함합니다.

다른 채팅이 바빠 있을 때 다음 작업을 기록할 수 있습니다. 예를 들어 설정 폼의 오류 상태를 검토하는 작업을 "실시 완료 후" 저장할 수 있습니다.

## 후에 작업을 저장하기

1. 작업이 속한 프로젝트를 선택하세요.
2. **스태시**를 클릭하십시오. 오른쪽 툴바 아래에 있는 인BOX 아이콘입니다.
3. 새 프롬프트 컴포저를 패널 아래에 작성합니다.
4. **@**로 프로젝트 참조를 추가하고 모델 및 권한을 선택합니다.
5. 새로운 프롬프트를 제출하여 저장된 목록에 추가합니다.

이 아래의 composer에서 제출하면 작업이 저장되며, 에이전트 응답을 시작하지 않습니다. 저장된 항목은 스태시 패널에서 그 항목 위에 나타납니다. 프로젝트를 전환하면 해당 프로젝트의 별도 스태시를 확인할 수 있습니다.

## 저장된 프롬프트를 편집하세요

저장된 항목에서 텍스트를 직접 편집하고 그 아래에 있는 제어기를 조정합니다. 실행 전 모델과 권한을 다시 확인하세요, 특히 저장한 이후에 기본 모델을 변경한 경우입니다. 저장된 항목은 자체 선택을 유지합니다.

프로젝트 참조는 경로를 가리킵니다. 참조된 파일에 대한 스�냅샷을 유지하지 않습니다. 에이전트는 작업을 실행할 때 프로젝트가 존재하는 그 상태와 함께 작업합니다.

<Note>
  Stash에 유지하고자 하는 맥락을 프로젝트 참조를 사용합니다. 첨부 파일 선택기에서 선택한 파일 첨부 파일은 저장된 항목에 유지되지 않습니다; 일반 채팅에서 해당 파일을 첨부합니다.
</Note>

## 저장된 작업 실행

1. 실행하고자 하는 저장된 항목을 찾습니다.
2. 문서의 텍스트, 참조 사항, 모델, 및 권한을 검토합니다.
3. 그 항목의 제출 컨트롤을 클릭하세요.

Dream은 저장된 설정으로 새 채팅을 생성하고 프롬프트를 제출합니다. 멀티 채팅이 활성화되어 있다면 대화는 현재 채팅과 옆에 열립니다. 그렇지 않으면 현재 보이는 채팅이 됩니다.

항상 새 채팅으로 넘겨질 때 항목은 스태시에서 제거됩니다. 응답이 실패하면 오류를 새 대화에서 확인해야 하며, 항목이 스태시에 남아 있는 것을 기대하지 마십시오.

## 저장된 작업 제거

저장된 항목에서 **스태시된 채팅 삭제**을 사용하여 대화를 시작하지 않고 항목을 제거할 수 있습니다. 이는 프로젝트 내 파일을 제거하는 것이 아니라 저장된 프롬프트를 제거합니다.

스태시는 프로젝트별로 미래의 작업을 저장합니다. 여러 프로젝트에서 계속 사용하고자 하는 지침은 [재사용 가능한 프롬프트](/docs/ko/saved-prompts)를 사용하세요. 완료된 대화를 활성 역사에서 제거하고 싶다면 [보관된 채팅](/docs/ko/archived-chats)을 사용하세요. 코드 변경을 분리하고 싶다면 [Git 워크트리](/docs/ko/worktrees)를 사용하세요.
