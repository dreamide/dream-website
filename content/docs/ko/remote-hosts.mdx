Dream은 로컬 프로젝트와 함께 원격 컴퓨터의 프로젝트를 열 수 있습니다. 파일, Git 명령, 에이전트 프로세스, 터미널은 프로젝트 호스트에서 실행됩니다. 프로젝트 호스트 레이블을 보면 어디에서 작업하고 있는지 알 수 있습니다.

SSH로 호스트에 연결하거나, 해당 컴퓨터에서 [원격 액세스](/docs/ko/remote-access)가 켜져 있으면 HTTPS로 Dream 호스트와 페어링하세요. 하나의 호스트에 여러 경로를 둘 수 있으며, Dream은 먼저 연결되는 경로를 사용합니다.

Dream은 SSH를 통해 Linux x64, Linux ARM64, macOS Apple silicon(ARM64)용 관리형 호스트 런타임을 설치합니다. 이는 원격 호스트 플랫폼이며, Dream 데스크톱 앱은 Windows, macOS, Linux에서 실행할 수 있습니다. Linux 호스트 런타임은 glibc 2.31 이상을 사용하는 시스템을 지원합니다.

## SSH 호스트 추가

1. 시스템 터미널에서 `ssh devbox`가 작동하는지 확인하세요. `devbox`는 SSH 설정 별칭 또는 `user@host`로 바꿉니다. Dream은 시스템의 SSH 클라이언트, 설정, 키를 사용합니다.
2. **설정 → 연결**을 열고 **호스트 추가 → SSH 호스트**를 선택합니다.
3. **SSH 대상**을 입력하거나 `~/.ssh/config`에서 제안된 별칭을 선택하고, 필요하면 **이름**을 입력합니다.
4. 런타임을 자동으로 설치하려면 **호스트 명령**을 비워 둔 채 **저장**을 클릭합니다. Dream이 새 호스트에 연결합니다.
5. Dream에서 호스트 키, 비밀번호, 암호문 또는 2단계 인증 요청에 응답하세요. 요청을 거부하거나 취소하면 해당 연결 시도가 중지됩니다.

**SSH 호스트 추가…**는 **폴더 열기** 대화 상자에서도 선택할 수 있습니다.

관리형 런타임은 버전별로 `~/.dream/host/versions/`에 설치됩니다. 호스트에서 런타임을 다운로드할 수 없으면 Dream이 로컬로 다운로드한 뒤 SSH로 업로드할 수 있습니다. 에이전트 CLI도 원격 컴퓨터에 설치하고 로그인하세요. CLI는 해당 컴퓨터의 환경에서 실행됩니다.

런타임을 수동으로 설치한 경우 **호스트 명령**을 원격 컴퓨터에서 `dream-host`를 실행하는 명령으로 설정하세요.

## HTTPS로 호스트 페어링

페어링은 SSH 없이, 해당 호스트의 [원격 액세스](/docs/ko/remote-access) 설정이 사용하는 주소를 통해 이 데스크톱을 Dream 호스트에 연결합니다.

1. 호스트 컴퓨터에서 **설정 → 연결**을 열고 **기기 페어링**을 선택합니다. 이 버튼은 **원격 액세스** 아래에 있습니다.
2. 이 데스크톱에서 **설정 → 연결**을 열고 **호스트 추가 → 페어링 링크**를 선택합니다.
3. **링크** 탭에서 **페어링 링크**를 붙여 넣습니다. 또는 **코드** 탭에서 호스트에 표시된 **호스트 주소**와 **페어링 코드**를 입력합니다.
4. 필요하면 이름을 입력하고 **페어링**을 선택합니다.
5. 코드를 사용했다면 호스트의 원격 액세스 설정에 있는 **페어링 대기 중**에서 이 데스크톱을 승인하세요.

페어링 링크는 한 번만 사용할 수 있으며 10분 후에 만료됩니다. 호스트의 HTTPS 인증서는 이 컴퓨터에서 신뢰할 수 있어야 합니다.

## 원격 프로젝트 열기

1. 시작 화면에서 **폴더 열기**를 선택합니다. 이 화면으로 돌아가려면 프로젝트 **+** 버튼을 사용하세요.
2. **열 위치**에서 호스트를 선택합니다. Dream이 요청하면 연결하세요.
3. **폴더 경로**를 입력하면 Dream이 입력하는 동안 폴더를 제안합니다. 경로 아래 목록을 탐색하고 **상위 폴더**를 사용할 수도 있습니다.
4. **열기**를 클릭하세요. 원격 폴더가 자체 채팅과 도구를 갖는 프로젝트 탭으로 열립니다.

닫은 원격 프로젝트는 호스트 및 경로와 함께 **최근 닫힘**에 나타납니다. 다시 열면 해당 호스트에 연결됩니다. 원격 경로는 원격 컴퓨터에 속하므로 Dream 외부에서 파일을 열 때는 그 컴퓨터에 연결된 편집기를 사용하세요.

## 경로 관리

경로는 호스트에 연결하는 한 가지 방법으로, SSH 연결 또는 페어링된 HTTPS 주소입니다. 같은 호스트에 여러 경로를 추가하면 하나를 사용할 수 없을 때도 계속 작업할 수 있습니다. 예를 들어 사무실 네트워크에서는 SSH를, 그 밖의 장소에서는 HTTPS를 사용할 수 있습니다.

1. **설정 → 연결**을 열고 호스트에서 **편집**을 클릭합니다.
2. 경로를 검토합니다. 경로는 연결될 때까지 순서대로 시도되며, **사용 중인 경로**가 현재 사용 중인 경로를 표시합니다.
3. 순서를 바꾸려면 **위로 이동**과 **아래로 이동**을 사용합니다.
4. 같은 호스트에 연결하는 다른 방법을 추가하려면 **SSH 경로 추가** 또는 **HTTPS 경로 추가**를, 경로를 삭제하려면 **경로 삭제**를 선택합니다. 경로는 하나 이상 남아 있어야 합니다.

우선 경로를 사용할 수 없으면 Dream은 다음 경로로 전환하고 전달된 포트를 그대로 유지합니다. HTTPS 경로를 변경하려면 새 페어링 링크가 필요합니다.

## 호스트 재연결 또는 제거

**설정 → 연결**의 각 호스트에는 **연결됨**, **다시 연결 중…**, **연결 실패** 같은 상태가 표시됩니다. Dream은 중단된 연결을 다시 시도합니다. 호스트를 사용할 수 없는 동안에도 프로젝트 탭은 계속 표시되지만, 다시 연결될 때까지 메시지를 보낼 수 없습니다. 재연결이 멈추면 표시된 오류를 읽고 **연결**을 사용하세요.

호스트의 이름, 대상, 명령을 변경하려면 **편집**을 사용하세요. 대상이나 명령을 변경하면 활성 연결이 다시 연결됩니다. **연결 해제**해도 프로젝트 탭은 그대로 남습니다.

**제거**는 확인을 요청한 다음, 이 Dream 작업 공간에서 호스트와 해당 프로젝트를 제거하고 터미널을 중지합니다. 호스트의 파일과 채팅은 삭제되지 않습니다.

## 연결 문제

먼저 시스템 터미널에서 같은 SSH 대상을 확인하세요. 다시 연결하기 전에 인증 또는 호스트 키 문제를 해결하세요. 호스트 런타임이 시작되지 않으면 **설정 → 연결**의 오류를 읽고, 구성된 **호스트 명령** 또는 사용 중인 플랫폼용 런타임이 있는지 확인하세요.

HTTPS 경로의 경우 호스트가 실행 중이고 원격 액세스가 **준비됨** 상태인지 확인하세요. 경로에 **확인 필요**가 표시되면(호스트의 **편집** 대화 상자에서 확인) 기기의 액세스가 취소되었을 수 있습니다. 호스트의 원격 액세스 설정에서 받은 새 링크로 다시 페어링하세요. [원격 액세스 문제](/docs/ko/remote-access#원격-액세스-문제)를 참조하세요.

개발 빌드에는 다운로드할 수 있는 게시된 런타임이 없습니다. Dream 앱 저장소에서 `pnpm host:install-dev devbox`를 실행한 뒤 **호스트 명령**을 비운 상태로 다시 연결하세요. 원격 빌드에는 Node.js 22 이상, pnpm 또는 Corepack, make, Python 3, C++ 도구 모음(g++ 10 이상)이 필요합니다. 설치 프로그램은 런타임을 교체하기 전에 기존 개발 호스트 데몬을 중지합니다.
