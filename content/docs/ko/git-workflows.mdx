오른쪽 툴바에서 **Git**을 열어 **변경 사항**, **기록**, 및 **풀 리퀘스트** 탭을 사용할 수 있습니다. 채팅 아래에 있는 **Git 작업** 메뉴는 현재 브랜치에 대한 다음 단계를 제공합니다.

## 시작하기 전에

커밋에 있어, 저장소는 Git 작성자 식별자가 설정되어 있어야 하며, 푸시에 있어 원격 저장소와 그에 접근할 수 있는 인증 정보가 필요합니다. 풀리퀘스트 생성은 GitHub CLI를 사용하며, 해당 목적 저장소에 설치되고 인증되어 있어야 합니다.

커밋 메시지와 PR 텍스트를 직접 입력할 수 있습니다. 이를 생성하려면 제공자 모델을 활성화하고 **설정 → 일반 → 모델 → 텍스트 생성 모델**을 선택합니다.

## 변경 사항 검토

1. **Git → 변경 사항**을 열어 수정된, 추가된 및 삭제된 파일을 검토합니다.
2. 파일을 펼쳐서 그 파일의 diff를 검토합니다.
3. 헤더에서 **통합 diff** 또는 **분할 diff**를 선택하고, 필요할 경우 **변경 사항**에서 단어 감싸기 기능을 활성화합니다.
4. 외부에서 작업한 내용이 아직 반영되지 않았다면 **변경 사항 작업 → 새로 고침**을 사용하세요.

매우 큰 차이를 가진 경우, Dream은 **차이가 너무 커서 렌더링할 수 없음** 라고 표시할 수 있습니다. 더 큰 뷰를 로드하거나, 파일을 편집기 또는 터미널에서 검토하고자 할 때만 **어쨌든 렌더링**을 사용하세요.

파일의 **파일 변경사항 되돌리기** 기능을 사용하여 원하지 않는 작업 변경 사항을 버립니다. **모든 변경 사항 되돌리기**는 더 넓은 범위를 적용하며, 확인 전에 범위를 검토해야 합니다. 코드를 되돌리는 것은 그 코드를 생성한 대화를 아카이브하는 것과는 별개입니다. 특정 응답이 변경한 내용만 되돌리고 싶다면, 그 응답의 [마크포인트](/docs/ko/checkpoints)를 사용합니다.

특정 줄에 대해 에이전트에게 질문하고자 할 경우, 차이를 보여주는 곳의 줄 번호를 드래그하거나 줄의 **+** 컨트롤을 클릭한 후 댓글을 입력합니다. Dream은 파일 경로와 선택한 줄을 함께 전송합니다. [채팅에 피드백 보내기](/docs/ko/feedback)를 참조하세요.

## 작업을 커밋하세요

1. **Git → 변경 사항**을 열거나, 하단의 **커밋** 메뉴에서 **Git 작업**을 선택합니다.
2. 다음 커밋 콤파이터 아래에 있는 파일 차이를 검토하세요.
3. **스테이징되지 않은 변경 사항 포함**를 확인하세요. 기본적으로 활성화되며, 커밋에 미스테이징된 변경 내용을 포함합니다.
4. **메시지 자동 생성**를 기본적으로 켭니다. 자신만의 메시지를 작성하려면 이를 끄고 텍스트를 입력하세요. 끄는 것은 생성된 메시지를 초기화하는 것입니다.
5. **커밋**을 선택하거나, 커밋을 원격 저장소에 퍼블리시할 준비가 되면 **커밋 및 푸시**를 선택하세요.

선택한 부분만 커밋하려면 터미널 또는 외부 편집기에서 Git을 사용하여 해당 파일을 스테이징하고 **스테이징되지 않은 변경 사항 포함**을 끄십시오. 변경 사항 패널은 개별 스테이징 제어를 제공하지 않습니다.

Dream은 활성 프로젝트 폴더 외부에 스테이지된 변경 사항이 있는 경우 커밋을 거부합니다. 이 작업을 계속하기 전에 별도로 커밋을 적용하세요.

<Warning>
  Include unstaged를 활성화하면, 이 체크아웃을 공유하는 여러 차트에서 작업을 포함하는 커밋이 가능합니다.
</Warning>

## 브랜치를 푸시합니다

    height={259}
    loading="lazy"
  />
</Frame>

**브랜치 게시**는 업스트림이 없는 브랜치에 사용하고, **푸시**는 보낼 커밋이 있을 때 사용합니다. 이 하단 작업은 즉시 푸시를 실행합니다. 먼저 브랜치, 원격 저장소, **기록**의 커밋을 확인하세요. 업스트림이 있으면 하단에 앞선 커밋 수와 뒤처진 커밋 수가 표시됩니다.

푸시가 실패하면 오류를 확인하고 원격 저장소에 접근할 수 있는지 확인하세요. 성공적인 로컬 커밋은 이후 푸시가 실패하더라도 여전히 커밋된 상태를 유지하므로, 복합 작업을 반복하기 전에 브랜치 상태를 확인하세요.

## 풀 리퀘스트 만들기

1. 기능 브랜치를 개발할 때 PR의 기반 브랜치와 이름이 다를 수 있습니다.
2. 푸터에서 **PR 생성**을 선택하거나 **Git 작업 → 풀 요청 생성**.
3. 소스 브랜치와 기반 브랜치 및 제안된 변경 사항을 검토하세요.
4. 제목과 설명을 입력하거나 **PR 세부정보 자동 생성**을 사용하여 생성된 텍스트를 검토합니다.
5. **다음 단계**에서 브랜치의 상태에 맞는 작업을 선택합니다.
6. PR가 검토에 준비되어 있지 않다면 **초안**를 켭니다. затем 제출합니다.

    width={672}

    loading="lazy"

| 다음 단계 | 무엇이 일어나는가 |
| --- | --- |
| PR를 만드세요 | 이미 푸시된 작업에 대해 PR를 생성합니다 |
| 푸시 및 PR 생성 | PR를 생성하기 전에 커밋을 푸시합니다. |
| 커밋, 푸시 및 PR 생성 | 작업 변경사항을 커밋하고, 푸시하며, PR를 생성한다 |

대화는 **초안**가 시작되어 있음을 의미합니다. Draft를 활성화하여 드래프트 PR을 생성할 수 있습니다. PR 생성은 브랜치를 필요로 하며, 소스와 기반 브랜치가 동일한 경우를 제외합니다.

결합된 작업이 실패했을 경우, 이전 단계는 이미 완료되었을 수 있습니다. 다시 시도하기 전에 커밋, 원격 브랜치, 또는 PR를 확인하세요.

## 프로젝트를 검토하고 풀리퀘스트를 병합합니다

Git → 풀 리퀘스트를 열어 현재 브랜치의 풀 리퀘스트를 확인합니다. 설명, 검토, 논의를 **요약**으로 확인하거나, 차이를 검토하고 내부 댓글을 작성할 수 있는 **코드**를 사용합니다. 허용되는 경우 제목과 설명을 편집할 수 있으며, **합치기**를 사용하여 합치기 방법을 선택할 수 있습니다. 전체 풀 리퀘스트 흐름은 [풀 리퀘스트 검토](/docs/ko/pull-requests)를 참조하세요.

## 브랜치를 전환하거나 생성하기

채팅 아래에 브랜치 스위치를 열고, 로컬 브랜치를 검색하여 하나를 선택하여 브랜치를 체크아웃합니다. 브랜치 이름을 지정하고 생성하려면 **Create and checkout new branch…**을 사용합니다. Dream 외부에서 생성된 브랜치가 누락된 경우 리스트를 새로 고침합니다.

브랜치를 바꾸면 해당 프로젝트의 모든 채팅이 사용하는 파일이 변경됩니다. 작업을 완료하기 전에 미완성 작업을 검토하세요. 독립적인 체크아웃을 가진 병렬 작업에는 [Git 워크트리](/docs/ko/worktrees)를 사용하세요. 워크트리가 완료되면 그 푸터를 사용하여 기반 브랜치에 머지하거나, 풀리퀘스트를 생성하거나 체크아웃을 제거할 수 있습니다. [워크트리를 완료하세요](/docs/ko/worktrees#워크트리를-완료합니다)를 참조하세요.

## 커밋 기록 탐색

열린 **Git → 기록**, 또는 **Git 작업 → 기록 보기**를 사용하여 색상 그래프에서 커밋과 머지 작업을 추적합니다. **커밋 검색**를 사용하여 메시지, 작성자, 해시 접두어, 또는 ref에 따라 로드된 커밋을 필터링합니다. **Load more**는 더 오래된 커밋을 포함합니다; 검색을 지우면 그래프를 다시 표시합니다.

커밋 위에 마우스를 올리거나 키보드로 초점을 맞추면 **커밋 해시 복사**를 사용할 수 있습니다.
