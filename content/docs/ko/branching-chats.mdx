---
title: "대화 분기"
description: "이전 메시지에서 같은 워크스페이스 또는 분리된 Git 워크트리에서 계속합니다."
---

대화를 브랜치로 분기할 때는 현재 대화를 기반으로 다른 접근 방식을 탐색하고자 할 때 사용합니다. Dream은 선택한 메시지부터 대화 내용을 복사하여 새 대화에 복제하고 원래 대화를 유지합니다. 그 이후의 메시지는 새 대화에 포함되지 않습니다.

## 동일한 작업 공간에서 계속하기

1. 소스 대화를 열고 그 응답이 끝날 때까지 기다려주세요.
2. 브랜치를 만들기 위한 메시지를 찾습니다.
3. **이 메시지에서 계속…** 동작을 사용합니다.
4. **이 작업 공간**에서 **새 채팅에서 계속**을 선택합니다.
5. 새로운 대화에서 대안을 시도하고자 하는 내용을 후속 메시지로 보내세요.

새로운 채팅은 원본 채팅의 모델 및 권한 설정을 기반으로 시작합니다. 다중 채팅에서는 원본 채팅 옆에 열립니다. 단일 채팅 레이아웃에서는 현재 보이는 대화로 변합니다.

예를 들어, 에이전트가 버그를 설명한 후 작은 수정을 비교하기 위해 새 채팅을 요청할 수 있습니다. 두 대화는 현재 프로젝트 파일을 사용할 수 있습니다.

<Note>
  브랜치는 대화 기록을 복제합니다. 선택된 메시지가 전송된 당시의 파일 시스템 상태를 복원하지 않습니다. 이 워크스페이스 내의 두 대화는 여전히 동일한 파일을 공유합니다.
</Note>

## 새로운 워크트리에서 계속하기

독립적인 체크아웃을 위해 **이 메시지에서 계속… → 새 작업 트리**를 사용하세요. 이 옵션은 Git 저장소를 필요로 합니다. Dream은 워크트리 프로젝트를 생성하고, 복사된 기록을 포함한 새 채팅을 만듭니다.

이 단축키는 현재 브랜치를 기반으로 하며 채팅 제목에서 브랜치 이름을 생성합니다. 사용자가 고안한 기반 브랜치를 선택하도록 묻는 것은 없습니다. 기반 브랜치와 브랜치 이름을 직접 선택하고자 한다면 [브랜치 스위치에서 워크트리를 생성](/docs/ko/worktrees#워크트리-생성)합니다.

<Warning>
  새로운 워크트리는 커밋된 Git 역사에서 시작되며, 아직 커밋되지 않은 변경 사항을 포함하지 않으며, 선택한 메시지에서 정확한 파일 상태를 재생하지 않습니다. 새로운 체크아웃으로 필요한 변경 사항을 저장하고 커밋한 후에 워크트리로 브랜치를 생성하세요.
</Warning>

## 적절한 브랜치 유형을 선택하세요

| 당신이 원하는 것은… | 사용하기 |
| --- | --- |
| 현재 코드에 대해 동일한 코드에 대해 다른 질문을 하세요. | 이 작업 공간 |
| 논리적 추론을 비교하면서 이전의 논의를 유지한다. | 이 작업 공간 |
| 다른 에이전트가 독립적인 체크아웃을 편집할 수 있도록 하자 | 새 작업 트리 |
| 작업을 시작하되 메시지를 복사하지 않기 | 새 채팅 |

응답 처리 중일 때 브랜치는 사용할 수 없습니다. worktree 옵션이 사용할 수 없는 경우 프로젝트가 Git 저장소 내에 있는지 확인하세요. 결과 프로젝트를 열고 제거하는 방법은 [워크트리](/docs/ko/worktrees)를 참조하세요.
