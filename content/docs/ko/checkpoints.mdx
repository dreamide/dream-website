**변경 체크포인트**가 활성화되면, 각 에이전트 응답 전과 응답이 완료될 때마다 Dream이 프로젝트 파일을 스�냅샷으로 저장합니다. 이러한 체크포인트를 사용하여 응답이 정확히 어떤 파일을 변경했는지 확인하고, 다른 접근 방식을 취하고자 할 때 선택한 파일을 복원할 수 있습니다.

## 검증점이 어떻게 작동하는지

- 체크포인트는 Dream의 애플리케이션 데이터 내부의 개인 저장소에 프로젝트의 워크 트리(추적되지 않은 파일을 포함)를 기록한다. 자신의 리포지토리에 커밋, 스태그, 브랜치를 생성하지 않으며, Git 리포지토리가 아닌 폴더에서도 작동한다.
- 프로젝트의 `.gitignore`에서 제외한 경로와 `node_modules`, `dist`, `build`, `coverage` 같은 일반적인 빌드 폴더는 캡처하지 않습니다.
- Dream은 사용자가 메시지를 보낼 때마다 **변경 전** 스냅샷을 한 번 캡처하고, 응답이 완료되거나 사용자가 중지할 때 **변경 후** 스냅샷을 캡처합니다.
- 체크포인트는 Dream이 `git` 실행 파일을 사용할 수 있어야 합니다. 캡처가 실패하거나 너무 오래 걸릴 경우, 응답은 체크포인트 없이 진행되며 그 체크포인트의 리뷰 제어는 표시되지 않습니다.

체크포인트는 기본적으로 켜져 있습니다. 켜기를 끄려면 **설정 → 일반**을 열고 **채팅 메시지**를 찾아 **변경 체크포인트**을 비활성화합니다.

## 반응의 변경 사항을 검토합니다

1. 응답이 끝날 때까지 기다립니다.
2. 보조 메시지 위에 마우스를 올리고 **이 답변의 파일 변경 사항 보기**를 클릭하십시오. 메시지 하단의 시계 아이콘을 클릭하십시오.
3. **이 답변의 변경 사항**에서 파일 목록을 검토하세요. 각 행은 경로, 상태(**추가됨**, **삭제됨**, **수정됨**, 또는 **이름이 변경됨**) 및 줄 수를 나타냅니다.
4. 행을 펼쳐서 차이를 확인합니다.

대화는 해당 응답에 대한 전후 스�냅샷만 비교합니다. 다른 응답이나 당신의 직접적인 편집에 대한 변화는 포함되지 않습니다. 응답이 중단된 경우, 대화는 해당 후 상태가 열었을 때 캡처된 것으로 표시합니다.

답변 후 다시 변경된 파일은 후속 답변, 터미널 명령어, 또는 편집기에서 나타나는 경우 **이후 편집됨** 라는 표시를 표시합니다. 이진 파일은 차이를 표시하지 않습니다.

## 파일 복원

1. 복원하고자 하는 파일을 선택하세요. 이후 편집이 없는 파일은 기본적으로 선택됩니다. 모든 파일을 포함하려면 **모두 선택**을 사용하세요.
2. **복원**을 클릭합니다. 버튼은 선택된 파일 수를 표시합니다.
3. **복원됨**된 행을 검토한 후 **닫기**를 클릭합니다.

복원은 선택한 파일에 대한 응답의 변경 사항을 되돌리면서도 그 파일에 이후에 이루어진 관련 없는 수정은 유지합니다. 응답이 생성한 파일은 삭제되고, 응답이 삭제한 파일은 다시 생성되며, 이름이 바뀐 파일은 이전 경로로 이동됩니다.

후에 이루어진 수정이 답변의 변경과 중복되면, Dream은 해당 파일을 수정하지 않고 경고합니다. **덮어쓰기**를 선택하여 파일을 답변 전의 완전한 내용으로 대체하고, 그 후에 이루어진 수정을 버립니다.

<Warning>
  복원은 대화 창에서 되돌릴 수 없습니다. 복원 전에 영향을 받은 파일에서 필요로 하는 후속 작업을 복사하세요. 파일을 복원하는 것은 대화에서 메시지를 삭제하지 않습니다. 복원한 내용을 에이전트에게 알려주고, 그 후에 계속 진행하려면 그 내용을 알려주세요.
</Warning>

복원은 Git 작업이 아닌 파일 작업입니다. 복원 후 [변경 사항](/docs/ko/git-workflows)을 열어 작업 트리를 확인하세요. 같은 파일을 복원하기 전에 [편집기에서 작성 중인 내용을 저장](/docs/ko/files)하세요.

## 체크포인트 저장소

채팅이 존재하는 동안 체크포인트는 계속 사용 가능합니다. **설정 → 보관된 채팅**에서 채팅을 영구적으로 삭제하면 그 채팅의 체크포인트도 삭제되며, [워크트리 프로젝트](/docs/ko/worktrees)를 완료하거나 제거하면 해당 프로젝트의 체크포인트도 삭제됩니다. 채팅을 보관하면 체크포인트는 유지됩니다.

다른 접근 방식을 시도하면서도 지금까지의 대화를 유지하려면 이전 메시지에서 브랜치를 생성하는 것과 함께 복구를 결합해야 합니다. [이전 메시지에서 브랜치를 생성하는 것](/docs/ko/branching-chats) 브랜치만 생성하면 메시지가 복사되지만 파일은 변경되지 않습니다.
