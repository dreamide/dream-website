멀티 채팅은 동일한 프로젝트 내에서 여러 대화를 동시에 표시합니다. 각 대화는 자체 메시지와 모델 선택을 유지하므로, 다양한 접근 방식을 비교하거나 구현 작업 중에 리뷰를 계속 보관할 수 있습니다.

## 다른 채팅을 열림

1. 프로젝트를 열고 보여주고자 하는 대화를 열어라.
2. 왼쪽 툴바에서 **멀티 채팅 활성화**를 클릭하세요. 툴바 아이콘 위에 마우스를 올리면 이름을 볼 수 있습니다.
3. **새 채팅**을 클릭하여 열린 채팅 옆에 대화를 추가합니다.
4. 새로운 채팅의 composer에서 모델을 선택하고 메시지를 보내세요.

기존 대화를 되살리려면 **채팅 기록**을 열고 선택합니다. 레이아웃에 이미 존재하는 채팅을 선택하면 해당 대화를 초점으로 설정하며 중복 대화를 생성하지 않습니다.

Multi-chat은 프로젝트 설정입니다. 하나의 프로젝트에서 여러 대화를 동시에 보고, 다른 프로젝트에서는 하나의 대화를 사용할 수 있습니다.

## 작업 공간을 정리하세요

- **크기 조정:** 채팅 컬럼 사이의 분할선을 드래그하여 각 컬럼의 너비를 조절합니다.
- **순서 재정렬:** 대화의 제목 영역을 드래그하여 다른 대화 옆으로 이동시킬 수 있습니다.
- **열을 닫기:** 헤더에 있는 **×**를 클릭합니다. 대화는 채팅 기록에 남아 있습니다.
- **하나의 대화로 돌아가기:** 보고자 하는 채팅을 선택한 후 왼쪽 툴바에서 **멀티 채팅 비활성화**를 클릭합니다.

다른 채팅이 열려 있는 경우에만 가까운 제어 기능이 사용 가능합니다. 다중 채팅을 끄더라도 다른 대화는 아카이브되지 않으며, 필요할 때는 역사에서 다시 열 수 있습니다.

## 예시: 구현한 후, 검토하기

1. 드림 IDE를 사용하여 "설정 저장소 구현"이라는 이름의 대화를 시작하고, 설정 폼을 고치게 하세요.
2. 멀티 채팅을 활성화하고 "설정 복구 지속성"이라는 이름의 두 번째 채팅을 생성하세요.
3. 다른 활성 모델을 리뷰 채팅에서 선택하면 두 번째 모델의 평가를 받을 수 있습니다.
4. 구현이 준비되면 리뷰 채팅을 통해 현재 변경 사항을 검토하고 파일을 수정하지 않고 문제를 보고하라.
5. 구현 대화를 통해 발견한 내용을 해결하면서 검토를 계속해서 보이게 하세요.
6. 필요할 때 리뷰 열을 닫고, 역사에서 다시 열어 검토 내용을 다시 확인할 수 있습니다.

두 번째 채팅은 첫 번째 채팅의 메시지를 자동으로 받지 않습니다. 작업 맥락을 제공하고 [관련 파일을 참조](/docs/ko/providing-context)하거나, 이전 메시지를 복사하고자 할 때는 [채팅 분기](/docs/ko/branching-chats)를 사용하세요.

## 공유되는 것을 이해하세요

같은 프로젝트 내의 모든 채팅은 동일한 프로젝트 폴더를 공유합니다. 파일 수정과 Git 브랜치 변경은 다른 채팅에게 보이게 됩니다. 그들의 대화 기록은 별개이지만, 그들은 서로를 보고 있습니다.

<Warning>
  두 개의 에이전트가 동일한 파일을 편집할 경우 서로의 작업에 간섭될 수 있습니다. 작업이 독립적인 체크아웃을 필요로 할 때는 별도의 [Git 워크트리](/docs/ko/worktrees)를 사용하세요. 멀티 채팅만 활성화하는 것은 파일 변경을 분리시키지 않습니다.
</Warning>

완료된 대화는 [아카이빙](/docs/ko/archived-chats)을 사용하여 기록을 관리할 수 있습니다.
