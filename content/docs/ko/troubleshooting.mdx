---
title: "문제 해결"
description: "결과 없이 모델과 채팅, 터미널 및 미리보기 문제, 일반적인 Git 오류를 해결합니다."
---

문제가 나타난 대화 또는 도구에서 처음으로 오류를 확인하세요. 설정을 변경하기 전에 어떤 프로젝트와 제공자가 선택되었는지 확인하십시오. 특히 여러 대화가 열려 있을 때입니다.

## 프로바이더 CLI가 감지되지 않았습니다

1. 시스템 터미널을 열고 제공자 CLI가 시작되는지 확인하세요.
2. 로그인 또는 첫 실행 설정을 완료합니다.
3. Dream에서 **설정 → 제공자**를 열고 해당 제공자를 새로고침합니다.
4. 드림이 열려 있는 상태에서 설치했고, 여전히 탐지가 실패한다면 드림을 다시 시작하여 변경된 환경을 인식할 수 있도록 해야 합니다.

Dream은 앱에서 실행 파일이 단순히 상호 작용하는 쉘 내의 단축 링크나 앨리아스를 통해만 사용되어야 하며, 실행 파일이 앱에 사용 가능해야 합니다. [제공업체 연결](/docs/ko/providers) 참조.

## 모델이 없거나 대화를 시작할 수 없습니다

**설정 → 제공자**를 확인하고 최소 하나의 탐지된 모델을 활성화하세요. 탐지된 CLI에 활성 모델이 없는 경우 채팅을 시작할 수 없습니다. 제공자 인증 또는 모델 설정을 변경한 후 새로 고침하세요. OpenCode의 경우 새로 고침 전에 인증 또는 구성 작업을 완료하세요.

그런 다음 **설정 → 일반 → 모델**을 확인합니다. 이전에 선택한 기본 모델이 사용할 수 없는 경우, 다시 활성화된 모델을 선택합니다. 기존 채팅은 각각 자체 선택기를 가지고 있으며, 전역 기본 모델을 변경해도 그 선택을 대체하지 않습니다.

## 추론 강도 또는 속도 제어 기능이 누락되었습니다

이 컨트롤들은 선택한 모델의 기능에 따라 달라집니다. 필요 기능을 제공하는 모델을 선택하세요. 채팅의 모델을 변경하면 그 채팅의 노력과 속도 선택이 초기화됩니다. 따라서 변경 후에는 둘 다 다시 확인하세요. [모델과 기본 설정](/docs/ko/models) 참조.

## 채팅을 찾을 수 없습니다

1. 대화가 발생한 프로젝트를 선택하세요.
2. 열린 **채팅 기록**을 확인하고 검색 필드를 지우기.
3. 채팅의 제목을 기준으로 검색한다.
4. **설정 → 보관된 채팅**을 확인하고, 그 채팅이 있다면 복원하세요.
5. 프로젝트가 닫혀 있다면, 시작하기 화면의 **최근 닫힘**을 통해 다시 열 수 있습니다.

다중 채팅 열을 닫아도 대화가 아카이브되지 않습니다. 메시지가 없는 빈 채팅은 역사에 기록되지 않습니다. 영구적으로 삭제된 채팅은 Dream을 통해 복구할 수 없습니다.

## 복원된 채팅이 다시 아카이브됨

채팅을 복구하면 그 채팅의 마지막 활동 날짜가 유지됩니다. **지금 보관**을 다시 실행하면 그 날짜가 자르기 기준보다 오래된 경우, 다시 보관 대상이 됩니다. 작업을 실행하기 전에 자르기 기준과 보관하고자 하는 채팅을 확인하세요.

## 브랜치는 사용할 수 없습니다

현재 응답이 끝나기 전에 브랜치를 생성하지 마세요. **새 작업 트리**도 Git 저장소가 필요합니다. 기반 레퍼런스가 누락되었거나 유효하지 않으면 워크트리 생성이 방해될 수 있습니다; 사용하고자 하는 커밋된 브랜치나 레퍼런스가 저장소에 존재하는지 확인하세요.

새로운 워크트리에 예상되는 수정이 누락된 경우 원래 프로젝트에서 커밋되지 않은 상태였는지 확인하세요. 워크트리는 그런 변경 사항을 복사하지 않습니다. [Git 워크트리](/docs/ko/worktrees)를 참조하세요.

## 반응에는 View 파일 변경 제어가 없습니다

제어는 응답이 완료된 후에 어시스턴트 메시지에 나타나며, 해당 응답에 대해 체크포인트가 기록되었을 때만 나타납니다. **변경 체크포인트**에서 **설정 → 일반 → 채팅 메시지**이 활성화되어 있는지 확인하고, Dream에 `git` 실행 파일이 사용 가능할지 확인하세요. 매우 큰 프로젝트는 캡처 시간 제한을 초과할 수 있으며, 이 경우 응답은 체크포인트 없이 실행됩니다. [변경 사항 검토 및 복원](/docs/ko/checkpoints)을 참조하세요.

## 다이프나 요소 피드백을 보낼 수 없습니다

목표 채팅이 응답 중일 때 보낼 수 있는 제어는 비활성화되며 **채팅 처리 중**으로 표시됩니다. 응답이 끝날 때까지 기다리거나 팝오버에서 **새 채팅**을 활성화하세요. 팝오버가 선택 사항이 차이와 더 이상 일치하지 않는다고 보고할 경우, 변경 사항을 새로고침하고 줄을 다시 선택하세요. [채팅에 피드백 보내기](/docs/ko/feedback) 참조.

## 터미널에서 계속하기는 누락됨

이 기능은 유효한 재개시 가능 제공자 세션을 가진 클라우드 채팅에서만 사용 가능하며, 응답이 처리되는 동안 비활성화됩니다. 새 채팅, 다른 제공자, 또는 모델이나 속도를 변경한 후 세션을 재설정한 경우 해당 기능을 사용할 수 없습니다. [터미널](/docs/ko/terminals#터미널에서-클라우드-채팅을-계속하기)을 참조하세요.

## 터미널이 열리지 않는다

프로젝트 디렉토리가 여전히 존재하는지 확인하세요. **설정 → 일반 → 터미널**에서 사용 가능한 쉘을 선택한 후 새 세션을 열어주세요. 클라우드 연속 기능을 사용할 경우 원래 세션 디렉토리도 존재해야 합니다. 시스템 터미널에서 동일한 쉘을 사용하여 환경 문제를 식별해 보세요.

## 브라우저 미리보기는 빈 상태이거나 오래된 상태입니다

응용 프로그램이 실행되고 있는지 확인하고, 툴의 터미널에 표시된 정확한 URL과 포트를 사용하세요. 터미널 오류를 점검한 후 **브라우저 새로 고침** 또는 **강제 새로 고침**을 시도하세요. 시스템 브라우저에 표시된 URL을 비교하세요. 페이지 오류는 DevTools를 사용하여 확인하고, 인증 또는 캐시 문제에만 쿠키나 캐시를 삭제하는 것을 예약하세요. [브라우저 미리 보기](/docs/ko/browser)를 참조하세요.

## 파일을 저장할 수 없습니다

파일이 쓰기 가능함을 확인하고 편집기의 오류를 읽습니다. 편집 중에 디스크에서 파일이 변경되었으면, **디스크에서 다시 불러오기** 전에 초안을 보존한 후에 원하는 변경 사항을 다시 적용합니다. [파일과 검색](/docs/ko/files#편집기-외부에서-파일을-변경하는-경우-처리하기)을 참조하세요.

## Git 작업이 실패합니다

풀 리퀘스트 댓글, 편집, 병합에 문제가 있는 경우 [풀 리퀘스트 검토](/docs/ko/pull-requests)를 참조하세요. GitHub CLI가 인증되었고 계정이 필요한 저장소 권한을 가지고 있는지 확인하세요. 초안 풀 리퀘스트는 병합하기 전에 준비 상태로 표시되어야 합니다.

| 증상 | 확인해야 할 사항 |
| --- | --- |
| 폴더에 Git 도구 없음 | Git 저장소 내 폴더를 열기 |
| 커밋에 스테이지된 변경 사항이 없습니다 | 검토 포함, 또는 Git을 통해 원하는 파일을 스테이지합니다. |
| 활성 프로젝트 외부에서 스테이지된 변경 사항 | Dream의 커밋 액션을 사용하기 전에 별도로 커밋하세요. |
| 푸시는 목적지가 없습니다 | Git 원격 저장소를 구성하고 접근 가능성을 확인합니다 |
| PR 생성 시 CLI 오류가 발생합니다 | GitHub CLI가 설치되었는지, 인증되었는지, 그리고 저장소에 접근할 수 있는지 확인합니다. |
| PR 소스와 기준은 동일합니다 | PR를 생성하기 전에 기능 브랜치로 전환하세요 |
| PR 생성 보고서에서 분리된 HEAD | PR를 만드기 전에 브랜치를 확인하세요 |
| 작업 트리 제거가 실패합니다 | 그 체크아웃에서 수정되지 않은 변경 사항을 검토하고 유지하세요 |
| 메르지 & 리모브는 사용할 수 없습니다 | 워크트리는 기준에 대해 커밋이 없거나, 주 체크아웃에 아직 커밋되지 않은 변경 사항이나 머지 중이 있습니다. |
| 워크트리 보고서는 갈등을 발생시킨다 | 메이저는 중단되었고 아무런 변화가 없었습니다; 워크트리에 기준 브랜치를 병합하고, 갈등을 해결한 후 커밋한 다음 다시 시도하세요 |
| 완전한 워크트리에서 프로필 요청 생성은 사용할 수 없습니다 | Git 원격 저장소를 구성하고 GitHub CLI를 설치합니다. |

결합된 작업이 실패한 후에는 재시도 전에 브랜치 상태를 확인해야 합니다: 커밋이나 푸시는 후속 단계가 실패하기 전에 성공할 수 있습니다. [Git 작업 흐름](/docs/ko/git-workflows) 참조.
